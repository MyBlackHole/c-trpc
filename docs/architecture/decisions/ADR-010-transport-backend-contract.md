# ADR-010：传输后端契约与比较证据

- 状态：提案；等价比较未完成，不作为后端全面验收结论。
- 日期：2026-10-29。
- 关联：#246、#240–#245、#247。

用户选择传输与业务消息均自定义。当前产品方向保持自定义 TRP；这不要求冻结
历史帧、SDK 私有布局或尚未满足的资源语义，也不以已有代码量证明其性能优势。

拟采用[后端语义契约及对照设计](../../superpowers/specs/2026-10-29-transport-backend-contract-design.md)：
后端提供双向流、准入、信用、错误/排空和退休；消息、类型和 Call/Attempt 语义
在上层固定。一次 Attempt 可对应一个 HTTP/2 Stream；逻辑 Call 的尝试次数和
生命周期由 RPC 管理。源码分层不要求新线程或队列，最终可以只维护一个后端。

尚未批准或实施生产 HTTP/2 适配器，尚无同功能、同资源及同硬件的 TRP/HTTP/2
比较结果。后续必须先按共同语义/故障 oracle 检查正确性，再比较维护成本、资源
及性能；保留不可表达和失败结果。不以纯 HTTP 或 parser 结果宣称完整 RPC 更快。

本提案只补齐决策对象、接口行为和证据门槛。它不关闭 #246，也不替代 TLS-E、
预算、错误隔离、生命周期、服务目标、类型合同与发布总体验收。
