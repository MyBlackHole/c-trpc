## 旧语义与失败复现

原 Server 把推导的总内存硬预算按 shard 等分。各分片账目已经包括 Reactor、
对端表、Channel、重组池、任务和 RPC 存储，合计不会超出总额；但一个 shard
使用超过自己的等分份额时，其他 shard 的空余不能被它使用。原实现也没有
一个同时观察所有 shard 当前用量的原子总账。

先加入两级预算测试：根限额 16，两个子限额各 16，A 预留 12、B 预留 4
后 B 再申请 1 须被总额拒绝；A 释放后 B 可继续。旧代码缺少父预算能力，
测试首次编译即失败。再加入双 RuntimeShard 测试，旧代码创建成功后根
当前值为零，不等于两子当前值之和。Server 构造接缝测试在旧配置上观察到
没有共用根预算，断言失败。这三处分别证明原语、Runtime 和普通 Server
需要接入，而不是仅改变配置字段名称。

## 实现与边界

- 可选父预算只能指向根。子预留先占父总额，再占本地账目；本地拒绝
  精确撤销父额度。释放先归还子，再归还父。操作期间父当前值大于或
  等于所有子当前值之和，操作完成后在 Server 没有直接根预留时相等。
- 普通 V2 Server 在自身对象中持有根预算，原推导总额成为根硬上限。
  每个 shard 保留本地统计，本地限额设为同一总额，避免旧等分限额先行拒绝。
  直接 Runtime、Client 和 Transport-only Server 不设置父预算。
- Runtime 销毁在仍有预算持有者时返回 `TR_AGAIN` 并保留预算外壳。
  真实缓冲池持有测试验证：池缓冲未归还时根仍记账；归还并重试后根归零。
- 同一份分配同时出现在子账与根账是层级观察，不是两份存储，也不应把
  两个 `current_bytes` 相加作为实际占用。未计入预算的应用私有存储、
  线程栈和进程 RSS 不由本次硬限额覆盖。总额跨同一 Server 的 shard，
  尚不跨 Server 或租户。关闭时已转移到独立 producer 持有域的存储
  也不再计入这个 Server；跨域持有账本仍属于 #241 后续工作。

## 验证与成本

GCC release 全量 `xmake test -v -j1` 80/80 通过。定向 RED/GREEN
覆盖总额耗尽、子限额失败回滚、并发申请只准入一个、其他子恢复、双分片
固定存储与后续申请、第二个分片构造拒绝后的全额回滚、持有缓冲跨销毁、
普通 V2 Server 的同根配置。
GCC ASan/UBSan 对 Runtime、Server Record、Client Record、公开 V2 SDK
和 Message 变换五个目标 5/5 通过，启用 leak 检测与错误立即退出。
没有新增内存分配、线程、锁或消息复制；带父预算的申请和释放各增加
一次原子计数操作。尚未测量 40k 容量、吞吐和尾延迟，不能从功能结果
推导性能目标达成。

本次只解决 #241 的同一 Server 跨 shard 总额与空余复用。租户身份与
限额、跨 Server 总额、压缩/解压分域、慢消费者和完整组合矩阵仍未完成。
