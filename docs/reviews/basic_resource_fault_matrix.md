# 基础资源故障注入矩阵（阶段一）

本阶段针对 #154 中的基础资源构造路径，先固定可验证的不变量和注入点，不将静态分析告警直接归类为误报。

| 模块 | 注入点 | 必须证明的性质 |
|---|---|---|
| Buffer 固定池 | 描述符分配、存储分配、互斥锁初始化 | 已分配资源被释放；内存预算完整归还；失败后可重新构造 |
| Buffer 动态池 | 描述符分配、互斥锁初始化 | 失败路径不遗留描述符；预算归还；重新构造成功 |
| Command Queue | 数组分配、互斥锁初始化、条件变量初始化 | 失败路径释放数组；已初始化的锁被销毁；重新构造成功 |
| Completion Queue | 数组分配、互斥锁初始化、条件变量初始化 | 与命令队列相同的失败回滚契约 |
| Timer Queue | 第一处分配、第二处分配 | 第二次分配失败时第一块内存释放；无双重释放；重新构造成功 |

## 测试约束

- 故障只允许通过测试目标的链接期 `--wrap` 注入，不得进入生产静态库。
- 通过线程局部注入状态隔离目标构造调用，确保分配失败位置确定，不影响测试框架自身。
- 必须对正常路径、每个失败点以及失败后重试分别测试；仅观察返回错误码不算通过。
- 使用真实 GCC/Clang 构建和 ASan/UBSan 验证资源回收；不得用睡眠或不确定竞争模拟分配失败。
- 断言检查对象在失败后未发布资源；对于已成功初始化的同步对象，明确验证其销毁。
- 保留当前 `TR_AUTO` 与 `take()` 所有权语义，不通过删除清理机制消除分析器告警。
