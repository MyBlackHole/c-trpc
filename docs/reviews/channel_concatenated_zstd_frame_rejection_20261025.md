# 串接有效 Zstandard 帧拒绝回归

日期：2026-10-25。版本：`2.0.0-dev.116 -> 2.0.0-dev.117`。关联 #241、#235、PR #324。

## 目标与场景

验证单条压缩消息只接受一个 Zstandard 帧。既有回归覆盖有效帧后的任意尾随字节；本用例改为在首个有效帧后拼接第二个同样有效的完整帧，确保拒绝逻辑针对帧串接本身，而不是仅检测非法尾随数据。

## 输入与断言

- 分别编码两段正文，并用 `ZSTD_decompress()` 独立验证两个帧均完整有效、输出长度和字节均正确。
- 将两帧编码体直接拼接，envelope 声明编码体总长度和两帧解码长度之和。
- 通过真实 TCP Shared Channel 接收后，Channel 以 `TR_ERR_STATE` 复位当前流；服务端应用交付数保持不变，活动流与缓冲池恢复到基线。
- 保留原有单帧后跟垃圾字节的拒绝回归，两个输入边界分别覆盖。

## 验证结果

- GCC Release `test_transport/default` 在最终版本下连续 3/3 通过。
- `git clang-format --diff HEAD -- tests/test_transport.c` 未发现格式改动；`git diff --check` 通过。
- 测试命令将 `TMPDIR` 与 `XMAKE_TMPDIR` 指向工作区 `build/test-tmp`；未在 `/tmp` 创建测试文件。

本次仅增加测试、记录和开发版本，不改生产运行时、公开 API/ABI 或 wire。该场景验证两帧串接被流级拒绝，不覆盖更多帧数量、字典帧或并发预算矩阵。#241/#235 与 V2 整体验收继续开放。
