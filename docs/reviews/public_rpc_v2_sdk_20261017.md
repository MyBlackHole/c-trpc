# 公共 V2 业务 SDK 与安装消费验收

## 阶段结论与基线

本阶段接续 [OPEN 准入与分层排空](rpc_record_admission_drain_20261017.md)，
基线为草稿 PR #274 的 `9fa35d86d1898eecdaab560f274ec79783774227`，
tree 为 `7c31aca90b6942de508a25b1fd91d2c34cda777d`。
此前 V2 需要库内记录层入口；本阶段提供可以从安装目录独立消费的公共业务接口，
复用已经验收的消息基数、流重置、期限和分层排空。

完整接入与使用限制见 [公共 V2 SDK 使用合同](../rpc-v2-sdk.md)。

## 公共能力与执行合同

| 入口或对象 | 本阶段提供的合同 |
| --- | --- |
| 方法描述与构造 | 构造时复制冻结方法表；请求和响应分别选择 ONE 或 MANY |
| Client 调用 | start、复制发送、半关闭、取消、消息、初始及尾部元数据、可写与唯一终局 |
| Client 弱能力 | 可复制的值；内部保留完整 64 位调用代次，不延长 Client 寿命 |
| Server 工作 | OPEN、MESSAGE、HALF_CLOSE 事件；同调用 FIFO，不同调用可并行 |
| Server 回复 | 工作回调内复制追加与选择终局；网络背压后继续发送已生成批次 |
| Server 调用身份 | 进程内跨连接、跨 Server 不重复的不透明值；不具有发送权限 |
| 元数据读取 | 按数量、索引或键访问；隐藏 TLV 布局，键和值保留精确长度 |
| 生命周期 | 复用 connect、wait_ready、listen、start、begin_drain、wait_drained、destroy |

ONE 恰好一条消息，MANY 允许零条；一条零字节 MESSAGE 仍计为一条。
方法 codec 编号必须非零，正文按原始字节传递，不隐式编解码。
当前不支持 NONE 基数。方法的正文大小在构造、发送及回复边界均受合同限制。

Client `send()` 仅借用输入至返回。`TR_OK` 表示已经复制并接受一条消息，
业务随后可立即复用源内存；失败不保存这条正文。`TR_AGAIN` 保留可写等待责任，
但可写通知不预约容量，重试仍可受背压。实现先校验调用、基数和长度，再在有界
动态池申请和复制，避免无效大输入先消耗存储。已经被 TX 接受的复制缓冲区可以
比调用槽存活更久，销毁顺序保持宿主、Channel/TX、复制池、运行时预算的依赖。

调用回调表直接复制进原固定槽，不为公共包装另建每调用堆对象。start 受理后先
发布输出及终局责任，再推进协议；回调可能早于外部 start 返回。终局函数可释放
业务参数，因此输出句柄的存储不能放在可能被早终局释放的同一个对象内。
已受理调用承担恰好一次终局责任，terminal 返回后不再使用其参数或交付其他业务回调。

Client 正常回调在所属 I/O 域，必须短小、不阻塞。允许同一 Client 的发送、
半关闭、取消和发布排空意图，拒绝递归 start、阻塞等待、销毁及同步跨所有者调用。
弱能力使用寿命以首次 destroy 尝试开始为界；即使 destroy 失败，也只能继续
销毁对象，不能复活旧能力。对象销毁与并发 API 使用必须由调用方外部串行化。

Server 的工作输入是有界副本，仅借用至当前 work 返回。取消令牌和回复能力
也只在当前工作线程及回调中有效，不得保留或跨线程使用。TLS 先验证当前能力及
执行域，再访问内部对象；这不构成对所有历史指针复用的识别承诺。同一调用的
前一事件回复被传输接受后才执行下一事件，网络背压不会重复执行工作函数。

`reply_append()` 成功即已复制正文。任意追加失败锁存整批错误，业务即使忽略
错误并返回 OK，也不能得到截断的成功批次。finish 后追加同样失败；非 OK
终局丢弃本批正文。HALF_CLOSE 未显式选择终局时默认完成为 OK，仍须通过 ONE/MANY
基数检查。不同调用可以并发访问同一方法参数，业务负责共享状态同步。

## 准入、取消、终局与静默

完整合法 OPEN 匹配方法并通过准入期限检查后，立即固定服务端业务终局责任，
早于工作对象分配及任务提交。后续资源不足导致 OPEN work 未开始，也必须通知
一次终局；未知方法、无效或未完成 OPEN 不进入业务方法。

服务端取消是合作式。RESET、期限或排空都不能强制抢占工作线程，也不能在
已经提交的工作真正返回并完成交付之前释放输入或通知业务终局。同调用身份由
Dispatch 实例编号及路由器全局代次组成，避免跨槽、连接或 Server 的身份碰撞；
编号耗尽时拒绝准入，不回绕复用。

终局交付域描述实际执行位置：LIVE 位于 I/O 所有者；SHUTDOWN 仅用于父执行域
停止后由外部销毁线程交付的残留终局。destroy 仍可能先在未退出的 I/O 域关闭
连接并交付 LIVE，不能要求所有销毁结果都是 CANCELLED/SHUTDOWN。先到的有效
终局不会被残留清理覆盖。Server 工作和两种终局回调均不能同步调用 Client V2
业务入口或阻塞生命周期操作，避免跨执行域等待。

Client terminal 不等于调用网络槽或 TX 已退役；网络 RESET 已接受也不等于
Server 工作已退出。完整静默仍使用前阶段的 RPC、任务、回调、Channel、发送
责任分层收敛。有限等待使用一个单调绝对期限；非合作业务或对端仍可使等待
返回未完成，销毁不暗中另加优雅等待预算。

连接或 GOAWAY 相关错误产生的 `UNAVAILABLE` 也不能证明服务端未接受或执行
`CALL_OPEN`。本 Client 不自动重试或重放；应用不能仅凭该状态重放有副作用的
调用。V2 尚无跨连接 Attempt/去重合同，结果不确定时由调用方策略处理。

## 资源与配置边界

V2 构造将 `limits.max_message_bytes` 和 `initial_window_bytes` 分别解释为
业务正文上限与正文信用窗口。方法的最大请求和响应必须同时不超过两者；先验证
公共语义上限，再由库补入记录及控制空间，防止封装开销扩大业务准入范围。
内部信用阈值保证整条记录可以继续发送；帧载荷大小仍是独立的分帧约束。
加法、乘法和平台大小转换都检查溢出，不能满足合同即明确失败。

每连接并发调用受 `min(max_calls, max_streams)` 限制。Client 复制池、Server
输入事件、任务与回复均受有限资源约束。当前 Server 每调用最多保留 16 个未
收敛输入事件；每个工作事件最多追加 16 条回复，正文总量至多为该 Server 最大
方法响应上限的 16 倍，并与其他调用共享实例容量。过载可以返回
RESOURCE_EXHAUSTED，不承诺所有调用同时占满各自理论额度。

预算推导集中于 [`rpc_v2.c`](../../src/rpc/rpc_v2.c)，不把运行时布局、线程数、
任务槽、私有调优结构公开为 ABI。内部计费预算是一项有限存储约束，不等于
进程 RSS 或线程栈上限，也不按对端数、调用数和全部待办最大正文简单相乘。

### 保留的首轮结果与修订原因

首轮冻结 `cd6487517a06704b0b8054183a2726cb63a17a98` 的 GCC debug、
GCC release、ASan/UBSan 均为 83/84，Clang release 为 84/84。
三个失败都位于新增 Server 测试：外部线程观察 Client 本地取消终局后，立即
要求 Server worker 已收到网络取消。客户端本地状态不证明 RESET 已传到服务端。

测试修订改为 worker 在固定 15 秒总期限内检查真实公共取消令牌，每次最多
进行 1 毫秒条件变量等待；读到取消后才发布同步事实。外部确认取消已被观察、
worker 尚未退出、Server terminal 尚未发生，才释放阻塞工作；worker 返回前
仍再次检查令牌，保留一次终局和生命周期断言。该修订没有改动生产代码。

首轮 TSan 日志在 `test_runtime_threads/default` 开始后提前结束，无完整
测试汇总，命令退出 255；因此该轮验收不完整，不写成 83/84，也不把它归因于
上述已查明的测试竞态。日志确有 70 个开始记录，14 个目标未开始；没有观察到
sanitizer 诊断或 OOM 记录，提前退出原因未确定。最终新冻结的 TSan 已重新
完成全部 84/84，以这一完整运行作为门禁结论。所有首轮日志原样保留。

开发中另一次 SDK 测试曾将 destroy 一概要求为 CANCELLED/SHUTDOWN；在生产
冻结前按实际所有者关闭顺序修正为严格验证对应的 UNAVAILABLE/LIVE 路径。
这项修订明确停机交付域含义，没有放宽为任意状态或修改生产终局选择。

证据根为 `build/validation-public-v2-sdk/`。最终矩阵位于

## 后续边界

本阶段实现公共业务接入及安装闭环，后续仍需按独立合同推进回调外异步生产者、
响应元数据写入和 V2 语义统计；自动重连、连接组、网络压缩及 TLS 尚未提供。
现有不支持的配置明确返回 `TR_ERR_UNSUPPORTED`，不会静默切换协议。
旧 RPC smoke 的结果仍只证明其既有测试对象，不作为 V2 吞吐或生产负载承诺。

本记录只陈述已完成的本地验收。远端工作流将在最终草稿 PR 创建后运行，
届时按确切 head、合并检出 tree、全部 14 项作业的完整日志和制品逐一核对，
并在 PR 正文补记结论；本地通过不替代远端结果。
