# RPC OPEN 准入期限、GOAWAY 边界与分层排空

## 范围与基线

本阶段接续 [单流 RESET](rpc_record_reset_20261017.md)，开发基线为草稿
PR #273 的提交 `163948ef1111ce0f56664deadcd6d637df1a79d6`，tree 为
`b06ce1444673084af99d1f9ae3895babfc46cc17`。本记录修订此前关于慢 OPEN、
无受理边界 GOAWAY 和仅网络流排空的限制；历史记录保留原有验证范围。

本阶段处理三个问题：未完成 RPC OPEN 缺少固定准入期限；GOAWAY 不能精确
结束双方交叉发送的新 OPEN；网络流归零后，发送项、业务任务或终局回调仍
可能占用资源。稳定 SDK 的默认 RPC 仍为 V1；V2 使用既有库内显式入口。
Channel 规则同时作用于两者，因此同步修正 V1 的未确认 OPEN 取消路径。

## OPEN 准入期限

`tr_rpc_record_endpoint_config.open_timeout_ns` 是从传输流 `OPENED`
到完整有效 RPC OPEN 的本机总预算。0 使用固定 10 秒默认值，非零为有限
纳秒预算；这与完整 OPEN 中零剩余预算表示调用无期限属于不同合同。

宿主在最初接纳传输事件时读取单调时钟，以饱和加法固定绝对截止时间。
重入栈内也先在原预分配槽保留精确流身份和原期限，再通过已有待处理事件
机制延后交给 Dispatch，不在交付时重新计时；同槽终止事件优先处理。

Dispatch 在接收、进度推进及完整 OPEN 验证后检查当前时刻。零星字节、
可写通知、缓冲区恢复都不续期；在这些边界观察到 `now >= due` 即拒绝，
原定时器和公平扫描不承诺实时抢占。只有完整 OPEN 和
元数据校验成功且仍未到期，才清除准入期限并建立原有调用期限。
未验证的输入不能决定业务执行期限，也不能启动业务。

准入超时选择 `DEADLINE_EXCEEDED`，取时失败选择 `INTERNAL`，均直接
进入已有 RESET 路径，不等待普通 FINAL 或 `final_wait_ns`。RESET
接管遇到背压时保留原槽及重试责任。RPC 绑定与增量输入按原终止路径释放；
Channel 对不合作对端保留的 RESETTING 网络槽仍须等待响应、断连或显式
销毁，10 秒准入预算不等于全部网络资源的强制回收期限。

原低层 Dispatch 准入入口仍可不附加 OPEN 期限；新增限时入口接收上层
所有者固定的绝对值。默认网络宿主始终安装有限准入预算。

## GOAWAY 最后受理边界

Channel 握手版本升为 2，只接受版本 2，不保留旧 GOAWAY 解释分支。
帧封装版本仍为 1，RPC V1/V2 版本也不因此改变。

| GOAWAY 字段 | 合同 |
| --- | --- |
| 类型 | `TR_FRAME_GOAWAY` |
| `flags`、`stream_id`、载荷长度 | 全部为 0 |
| `message_id` | 不超过 `UINT32_MAX` 的最后受理对端流 ID |
| 边界 0 | 尚未受理该物理连接上的任何对端流 |
| 重复帧 | 必须重复同一边界，改变边界为连接协议错误 |

每条物理连接分别维护已观察对端 ID 前沿和最后受理 ID。仅在分配原流槽
且初始 WINDOW_UPDATE 获得发送责任后，才推进受理边界；看到或拒绝 OPEN
不能推进它。首次排空固定该边界。

初始 WINDOW_UPDATE 是对应 GOAWAY 的 FIFO 前驱：GOAWAY 固定接受时的
命令前沿，发送器也不越过此前发送工作。因此收到 GOAWAY 时，边界必须
恰好等于该物理连接此前确认过的最高本地流 ID，方向也必须正确。它不能
否定历史准入、声称未来流已准入、引用另一拆分连接的 ID 或未发布空洞。
被边界覆盖的更早本地流也不能仍缺初始确认。

收到 GOAWAY 的物理连接冻结双向新流并回复自己的边界，不冻结拆分模式
的另一条物理连接。只有显式 Channel `begin_drain()` 才建立全 Channel
准入屏障并禁用重连。已经受理的流可以继续工作。

本方排空后、对方 GOAWAY 到达前可能还有交叉 OPEN。它们仍须满足精确
连接、方向、帧形状、标志和严格递增 ID 校验，但不分配流槽，也不逐流回复 CLOSE。
对方 GOAWAY 是最后一个可能 OPEN 的 FIFO 屏障；之后再有 OPEN 即为协议错误。
边界外的本地 OPENING 直接失效并通知一次 `ERROR(TR_ERR_CLOSED)`，没有
后续 CLOSE/RESET 义务。未知 CLOSE 严格报错，不设排空期间忽略分支或
无界拒绝表。

### 未确认 OPEN 的收尾

未取得初始确认的本地流不能发送 CLOSE，关闭调用返回 `TR_AGAIN`。
原持有者须等待确认后重试，或接受 GOAWAY 拒绝及连接失败。V1 的早取消
和终局控制背压接入原有终局关闭定时器；取消的一元调用也先走取消路径，
不能被一般一元发送重试误判为已关闭。

定时器调度失败时同步中止精确物理连接。回调可能退役或复用 RPC 槽，
所有继续访问的取消路径都重新核验 Call 代次。新流建立后若 RPC 索引
绑定失败，已无 Call 承担重试责任，直接中止对应连接。

运行态对端 OPEN 无法分配槽，或初始 WINDOW_UPDATE 未取得发送责任，
同样终止精确连接。此时没有已受理流能承担可重试的逐流拒绝，不能静默
留下对端 OPENING。已经归属活流的消息和 RPC 错误仍按原 RESET 隔离规则处理。

## 发送与网络排空

库内 `tr_reactor_notify_tx_drained_on_owner()` 不申请命令或发送项，
只在原连接记录当前命令接受前沿及待通知状态。重复待办登记不刷新前沿。
只有此前全部命令已经处理、精确连接 TX 链为空、GOAWAY 和 RESET 两个
独立预留项全部归还，才在所有者上发布一次 `TX_DRAINED`。已接受但未从
命令队列取出的 SEND、短写、EAGAIN 和未入 TX 链的预留项都仍属于待办。

事件循环复用现有推进点检查。通知回调内重新登记空连接时保留一次立即
检查请求，避免没有后续 I/O 时永久等待；受阻发送不因待通知而持续轮询。
关闭或中止连接撤销旧代次观察，只发送原 CLOSED/ERROR，复用槽不继承通知。

Channel 的 DRAINED 要求显式本地排空、全部流归零，并对每条存活物理
连接同时证明本方 GOAWAY 已接管、对方 GOAWAY 已收到、Reactor 发送观察
已完成。失效连接由原关闭责任收敛。既有 Channel 维护定时器负责普通
外部 CLOSE 释放最后流后的进展，避免持 Channel 锁同步调用 owner 而
与 V1 RPC 发生锁反转。

发送排空证明本机资源已归还、成功发送的字节已交给内核，不证明对端应用
收到或处理。半关闭与 RESET 停止屏障也不证明业务任务退出。

## V2 宿主与门面排空

Endpoint 和 Client 宿主在最外层 owner 进度边界发布 RPC 静默状态。
外部等待只读同一互斥锁保护的结果，不读取未同步的 worker/owner 字段，
不循环向 owner 发同步探测。

正常 Endpoint 只有绑定实际退役才静默；停止对象可保留待销毁固定槽，
但必须交付真实任务完成、返回用户终局回调并交接网络责任。进度栈、待
处理事件及未报告终局均阻止静默发布；关闭就绪同样不能越过未报告终局。

Client 已受理但 RPC OPEN 未成功发送的调用、未确认传输 OPEN、未返回
终局回调及未退役绑定均计入 RPC 责任。开始排空在同一 owner 事务内先
冻结新 RPC 调用，再冻结 Channel，原有调用继续正常发送、完成或终止。

Server 冻结对端表后在各分片安装 Endpoint 观察。各 owner 汇总本分片
已有宿主，通过单调条件变量向等待线程发布结果；排空期间不恢复并发
对端回收。Client 同样发布单宿主结果。

一次有限 Client/Server 等待只构造一个 `CLOCK_MONOTONIC` 绝对截止时间，
先等 RPC 静默，再把同一个期限传给 Channel。`timeout_ms == 0` 仅立即
检查。超时不撤销排空，也不给后续层重新分配完整预算。仍运行的业务、
未返回的回调或不合作对端使有限等待返回未完成。

## 有界资源与范围限制

新增状态由原连接、宿主槽及分片固定持有，不随对端输入建立新容器。
原来按对象大小记账的预算自动包含新增字段；门面条件变量随原门面对象
构造和销毁，预算回归仍采用既有记账范围，不将其解释为进程 RSS 上限。
准入检查复用 Endpoint 进度定时器，取消关闭复用 V1 截止时间定时器，
网络排空复用 Channel 维护定时器。Reactor 观察不新建定时器，也没有
每流线程、每流计时器、额外业务正文队列或逐流拒绝表。

本阶段不添加公共 V2 SDK、自动业务重试、非合作任务强制退出、不合作
对端的强制优雅排空、TLS、吞吐性能承诺或完整异步 producer API。
