# 小池预算下的多帧消息重组回归

日期：2026-10-25。版本：`2.0.0-dev.107 -> 2.0.0-dev.108`。关联 #241、#240、#235、PR #324。

## 目标与场景

在真实 TCP Shared Channel 中验证较大 RAW 消息在小 DATA TX/RX 与重组池容量下仍可跨帧前进并完整重组。Channel 协商的单帧负载上限为 256 字节，应用消息为 1,500 字节。

## 资源配置与断言

- DATA TX 池只有 1 项；CONTROL TX 池为两个端点各留 1 项。
- RX 池只有 2 个 256 字节缓冲区，供测试中的两个端点使用；应用发送缓冲池只有 1 项。
- Server 重组池只有 1 个 2,048 字节槽。1,500 字节正文按 256 字节帧上限拆成 6 帧，并以相同 message ID 重组为一条消息。
- 服务端应用接管重组后的消息时，重组池可用数为 0；逐字节校验正文后释放，池可用数恢复为 1。
- 既有 `test_parser_one_byte_fragments` 继续验证解析器逐字节接收完整帧；本回归聚焦真实 Channel 多帧重组和小池容量。

## 验证结果

- GCC Release `test_transport/default` 连续 4/4 通过。
- 变更行 clang-format 检查与 `git diff --check` 通过。
- 测试命令将 `TMPDIR` 与 `XMAKE_TMPDIR` 指向工作区 `build/test-tmp`；未在 `/tmp` 创建测试文件。

本次只收紧集成测试资源配置、补充断言与开发版本记录，不改生产运行时、公开 API/ABI 或 wire。它证明单一 Shared Channel 消息在当前池配置下能完成帧级拆分与重组；强制 TCP 字节级分段、双向同时分片、池满期间多个流的公平性、压缩输出与解码预算仍待单独验收，#241/#235 和 V2 整体验收保持开放。
