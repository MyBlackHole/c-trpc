# V2 一元调用共用内核审查记录（2026-10-18）

## 范围与基线

接续 #240、#248、#279。固定基线提交
`573b0cca4a4277c5c2d283e3c66e6aaa694940ba`，源码树
`cd1091f09b60d36deffdd883d6e79fbf7638d41f`。
本轮落实既定顺序中的“一元调用共用 V2 内核”，不扩大为默认门面迁移完成。

## 计划与共同语义

新增公开 `tr_client_v2_unary_call()`：ONE→ONE、复制受理、异步回调；复用
`tr_client_v2_start` 所有者提交和 `tr_record_client_call_start` 准入，方法表、
调用代次、记录状态机、取消、期限、统计与退役路径只有原来的一份。

与逐步流式发送的区别仅在发送责任：一元入口在受理前复制一条请求，库持有
后续 MESSAGE/HALF_CLOSE 的推进责任。流式 send 的 AGAIN 仍不保存输入。
协议仍是 OPEN → MESSAGE → HALF_CLOSE；响应仍由 FINAL_STATUS 决定结果。
不增加 V1 自动兼容、第二调用表、执行器、定时器或正文队列。

## 实施与所有权

已有固定调用槽增加一个正文指针、一个待发送阶段和一元标志。
阶段只记录尚需提交的发送动作，不能绕过原 binding 的基数/最终状态检查。
正文从已有 Client 复制池取得，共用实例配额和硬预算；空正文不占复制槽，
但待发送 MESSAGE 仍存在。每次进度最多推进正文与半关闭两个动作。

| 边界 | 行为与释放责任 |
|---|---|
| 参数、方法、长度、元数据或资源准入失败 | 不改 out，不回调，不新增终局责任 |
| 复制后 stream/binding 创建失败 | 归还正文；已接受的内部网络责任仍按原路径退役 |
| start 返回 TR_OK | 正文及 OPEN 元数据已复制，原存储可复用；终局可能已提前交付 |
| 下游返回 AGAIN | 不推进阶段，保留唯一副本，由既有进度泵重试 |
| MESSAGE 被接受 | 原发送函数清空正文指针，TX 接管存储；继续提交 HALF_CLOSE |
| 未发送时取消、期限或错误终局 | 安全发送边界归还副本，再通知唯一 terminal |
| owner 停止后收尾 | 原停止域终局与回收继续负责副本；失败可重试，不重复终局 |

一元能力禁止应用手工 send/half_close，防止自动推进与手工操作竞争；cancel
不变。writable 不调用。message/metadata/terminal 沿用原借用及回调域合同。

## 验证

本地还原完整基线源码树并逐字节修改，使用 GCC 14 的 O0/O2、Clang 17 的 O2、
Clang ASan/UBSan、GCC TSan 五种模式。每种编译全部 45 个生产单元，运行
7 个定向测试：Client 记录、一元公共 SDK、记录状态、流绑定、V2 独立 TCP、
混合执行组和工作域，共 35/35 通过。

这些本地检查直接调用编译器；容器没有 Xmake，不能将其称为原生全量 CI 或
安装验收。V2 独立 TCP 本地链接复用现有 Xmake 列明的 23 个生产对象并检查
禁止旧 RPC 符号。其余涉及 Zstandard 的本地目标链接系统静态 1.5.7；不把
该依赖视为 Xmake 固定包供应链或第三方对象完整插桩的证明。

扩充原 `test_client_record`：三个发送阶段各自背压、非空与零字节请求、
请求元数据复制、响应早于半关闭、响应后取消、请求待发送时取消/期限/断连、
发送 NOMEM、内联接收错误、停止域销毁失败重试、受理后早终局释放 arg、
池满/槽满、stream/binding 分配失败及失败不改输出/统计。纯 SDK 用例验证
一元正文及元数据交付、零字节单条请求、远端未知方法与本地基数拒绝。

生产单元仍为 45、原生测试目标仍为 85；只增加本测试目标的两个链接故障钩子。
不更改 CI 作业身份、超时、格式配置或静态诊断基线，不降低任何检查门槛。
固定 clang-format 18.1.8 仅整理本补丁涉及行；原生五模式全量、固定双静态与
安装消费结果须读取新 PR 精确提交的远端运行，不能继承 #279 的绿色状态。

反向检查使用两个编译成功的错误变体：取消一元手工发送禁入会在 STATE
断言失败；删除待发送副本释放会在池计数断言失败。相同定向场景的正确源码
对照均通过。错误变体只在独立验证目录，不进入本补丁；它们验证回归能识别
对应错误，不扩充生产实现或伪装成正常测试通过数。

## 后续与未完成项

旧注册接口或旧结果回调，不删除 V1 Endpoint、执行组、Codec 或线协议。
下一实现步骤是在此共用一元能力之上迁移普通门面，随后删除失去调用者的旧
语义；不能以本轮通过关闭 #240/#248。压缩、TLS、重连、连接组与正式发布均
不在本轮完成范围。独立代码审查及跨堆叠 PR 的最终集成仍需单独确认。
