# MSG-D：Runtime 接入与父所有者退出后的消息回收

## 基线与本轮交付

基于 #255 的 `13883aeed58d3d9f76b5ac4969e64b5bf34e7fda`，关联 #235、#241、
#243、#248 和总审查 #239。MessageService 现在由真实 Runtime 分片按显式配置
创建、启动、停止与回收，并提供 `tr_runtime_shard_message_submit()` 库内入口。
不再要求调用方或测试自行创建并在 Runtime 之外管理服务。

尚未修改 RPC 线协议、公开 Client/Server SDK 或默认压缩策略。关闭消息服务的
分片不额外创建线程；启用时必须有非零硬预算和合法任务容量/调度配置。
Runtime 接入不是已经实现网络压缩、算法协商或 TLS。

## 停止证明与恢复租约

旧 Reactor 的 `started` 仅在 `tr_reactor_stop()` 成功 join 后清除。致命
`epoll_wait()` 错误关闭准入，不等于外部线程已经取得所有者状态。
POSIX 的 [pthread_join](https://pubs.opengroup.org/onlinepubs/9799919799/functions/pthread_join.html)
定义成功 join 后目标线程已终止；本轮借此边界而不猜测原线程是否还在运行。

新增库内 `tr_reactor_recovery_guard`：

- 必须零初始化、不可复制；只在父 Reactor 已成功 stop/join 时取得。
- 取得后在多次非阻塞回收调用之间保持，`start/destroy` 返回状态错误。
- 同一租约可重试，其他租约不能抢占。它不是引用计数，外层仍负责串行化
  生命周期和对象存储，不能容忍任意并发 free。
- 不在回调中持 Reactor 的 `ctl_lock`，也不伪造当前线程的 Reactor owner 身份。
- 子线程、完成回调和事件源均已静默后才释放租约。

新增精确 owner 查询，MessageService 创建/操作检查具体 Reactor，而非只检查
当前线程是否是任意 Reactor 的 owner。错误线程的拒绝不依赖已结束线程的标识。

## 完成在哪个执行域交付必须显式表达

MessageService 的完成参数改为 `{outcome, delivery}`。此库内接口尚未发布，
直接调整调用方，不保留会隐藏线程变化的兼容分支。

| delivery | 执行位置 | 允许的结果 |
|---|---|---|
| `ON_OWNER` | 所属 Reactor 正常所有者 | 按实际变换结果交付；可显式保留输出 |
| `OWNER_STOPPED` | 成功 join 后的串行化回收线程 | 强制取消、无业务载荷；仅本地清理/通知终止 |

两条路径合计恰好一次。已经算出成功但尚未交付的结果，遇到父所有者退出后也必须
释放，不能从回收线程伪装成正常成功。回收分支不得调用旧协议状态或重新网络发送；
参数允许本地释放，普通完成与回收完成都不得长期阻塞。

通用 task_executor 仅增加终止清理所有者移交能力，完全不认识 Reactor。
调用方必须先证明旧 owner 永久静默；执行器已停止准入且没有正在分派的回调时
才能移交。工作线程只使用原槽位/取消令牌，旧任务继续收敛，不因此重开准入。
工作线程上下文明确拒绝接管或从 Runtime 停机路径等待自身。

## Runtime 实际停止链

```text
停止消息准入／请求取消（父 owner 不可用时允许该步骤未执行）
    -> Reactor stop/join：失败立即保留原状态，不接管
    -> 取得恢复租约
    -> 标记消息服务只可回收；取消剩余任务、移交完成清理责任
    -> 有界交付、重试 join 工作线程
    -> 完成全部退役
    -> 注销辅助 fd 和定时器；清理失败保留 fd/对象/租约
    -> 清除通知并销毁执行器
    -> close fd、释放租约和服务
    -> Runtime 才能重启／最终销毁
```

工作尚未退出返回 `TR_AGAIN`，不是循环等待不合作的用户工作。重试可以继续处理
剩余完成；部分 join、辅助源 DEL、定时器注销和最终执行器销毁失败不会丢失对象。
若创建服务成功而启动中途失败，Runtime 的正式启动回滚也走这条同一收尾路径。

直接使用 MessageService 时，调用方仍需先完成父 stop/join，再调用
`reap_stopped()`。不能先 free 父 Reactor 再要求服务修复悬空指针。租约取得前的
生命周期顺序由组合者负责；Runtime 已保证不会在服务尚存活时销毁该父对象。
本轮不自动处理进程终止、线程强制取消、任意永久阻塞或外部破坏的对象。

## 保留输出与预算外壳

消息输出允许跨 Runtime 停止存活。Runtime 在释放自身外壳前检查分片预算仍有
持有字节时返回 `TR_AGAIN`，保留包含预算对象的分片存储；应用归还最后引用后
才能重试最终销毁。检查发生在各内部资源完成释放之后，不把正常 Reactor 固定
预算错误地当成泄漏。部分销毁后的 Runtime 不允许重新 start。

此保证针对实际计费请求字节和其存储寿命，不是整个进程 RSS、pthread 栈或
内核对象的硬上限。旧 RPC 执行器与完整网络信用机制不在本轮迁移范围。

## 新增及保留的测试

新增真实 `test_runtime_message_recovery`：

1. 通过 Runtime 创建并提交实际 Zstandard 工作，正常 owner 完成、独立解码正确。
2. 应用保留成功输出后 stop；destroy 返回 AGAIN；最后引用释放后 destroy 成功。
3. 默认关闭返回 UNSUPPORTED 且保留输入；消息工作线程启动失败进入 Runtime 回滚。
4. 固定运行中的压缩任务并排入第二任务，再令真实 Reactor 的 epoll_wait 返回 EIO。
5. 注入原 owner 的 join 失败：不能取得租约、不能交付回收回调；重试成功才接管。
6. 持有任务时回收返回 AGAIN；父 start/destroy 和 Runtime 重启均被阻止。
7. 分别注入工作线程 join、辅助源 DEL、定时器注销和执行器最终销毁失败，验证
   fd/对象/租约保持，以及重试完成一次、实际 close 一次。
8. 固定 owner，在算法已经保存成功结果并发出通知之后，先触发致命退出而不允许
   定时器代为交付；回收结果必须是 OWNER_STOPPED/CANCELLED，不能交付成功输出。
9. 恢复回调重入 stop、调用父 start/destroy 均拒绝且不自死锁；恢复结束后可创建
   下一服务实例并再次停止。
10. 从另一个真实 Reactor 所有者创建目标服务被拒绝，不仅检查非 owner 主线程。

既有 `test_message_service` 仅同步完成参数类型并新增正常域断言，保留以前的
算法取消、通知饱和、故障及解绑测试。其它旧测试不改逻辑。Xmake 只增加新测试
目标和其链接期注入，不新增第二套正式构建定义或放宽源码覆盖规则。

本轮不再用本地 Reactor 替身。由于本地 DNS 无法解析 GitHub，通过单独的
`diag/message-recovery-source-20261015` 分支，只归档已固定的受版本控制源码，
下载 Actions 归档后核验 282 个文件的 Git blob，再对真实仓库文件修改/编译。
该诊断工作流没有合入本功能分支或主分支；不归档凭证、环境变量或 runner 私有文件。
项目规定的 clang-format 18.1.8 同样通过诊断归档离线安装，用于新增和修改行检查。

本地没有 Xmake，因此编译列表从其 trcore 定义提取，使用实际全部生产源和
GCC 14.2/Clang 17 编译；这是真实实现的手工交叉验证，不称为正式 Xmake 构建。
本地 Zstandard 1.5.7 是预构建静态库，不宣称第三方库自身被检查器插桩。

当前实际结果：新回收测试在 GCC/Clang 的 O0/O2 构建运行成功；调试与优化矩阵
同时覆盖既有消息服务、执行器/Message 组合、Runtime、线程失败、Reactor 致命
退出及满队列停止等目标。新回收测试重复 30 轮通过。Clang ASan/UBSan（含泄漏
检查）和 GCC TSan 对新测试及这些实际模块集成用例通过。

对 task_executor、message_service、runtime 三个变化实现，GCC fanalyzer 与
Clang analyzer 无诊断；Reactor 保留既有 `items` 的潜在泄漏诊断。新增结构字段
使其从 305 行平移到 307 行，Clang 基线仅更新这一坐标，诊断内容、检查项与
`unverified` 状态均不改，不删除或屏蔽告警。固定 Clang 14 的结果仍以远端为准。

最初新测试遗漏存储提供方头文件，并设置了小于默认最大帧长的 RX 缓冲尺寸；
已修正测试自身的编译/配置，不放宽生产验证或屏蔽失败。之后重新执行相关矩阵。
