# Stream 单消息窗口准入回归

日期：2026-10-25。版本：`2.0.0-dev.103 -> 2.0.0-dev.104`。关联 #241、#240、#235、PR #324。

## 目标与场景

为 #241 的 `L` 与 `W` 边界矩阵补充真实 Channel 回归。Client/Server 在 TCP Shared Channel 上协商
`initial_window_bytes = 1024`；测试先提交 `L = 1025` 的 RAW 单消息，再走原有 `L = W = 1024`
发送、信用耗尽、应用持有和消费后恢复路径。该用例不改变窗口、消息或分片协议。

## 断言

- `L > W` 在发送准入时返回 `TR_ERR_BAD_LENGTH`，而不是等待不可能由消费触发的信用并返回 `TR_AGAIN`。
- 拒绝前后发送信用均为 0，发送上限保持 1024，接收端没有收到 DATA。
- 拒绝不转移缓冲区所有权；调用方可以释放该缓冲区，最终池容量归还完整。
- `L = W` 仍成功；对端持有首条消息时第二条返回 `TR_AGAIN`；释放消息后窗口更新并使发送恢复。

## 验证结果

- GCC Release `test_transport/default` 通过。
- 临时移除生产代码中的 `payload_len > tx_window_bytes` 检查后，测试按预期在
  `TR_ERR_BAD_LENGTH` 断言失败；恢复生产代码后目标测试通过。
- 变更行 clang-format 检查和 `git diff --check` 通过。

本次只增加集成回归、记录和开发版本号，不改生产运行时、公开 API/ABI 或 wire。该场景验证一个
`L > W` 边界，不代表窗口不对称、并发压缩、解压预算或慢消费者完整验收；#241/#235 与 V2 验收仍开放。
