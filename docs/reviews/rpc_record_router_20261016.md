# RPC-B2：服务端方法快照与入站调用路由

## 基线与交付范围

基于 #263 的 `5d56b527be427aaf951e24912407c5c1ecb2bf55`。
新增 `rpc_record_router.h/.c` 和真实 TCP 集成测试，沿用 RPC-A 记录内核及
RPC-B1 传输绑定，没有再实现一套协议状态机。关联 #240、#241、#247、#248。

[gRPC 核心概念](https://grpc.io/docs/what-is-grpc/core-concepts/) 将服务定义、
方法实现与调用生命周期分开。本轮借鉴的是从本地已注册描述选择处理入口，
而不是信任对端提供基数、编码器或大小策略；没有引入 Protobuf、HTTP/2，
也不把方法查表等同于鉴权。

本轮完成注册、发现和同步准入/调度回调，不声称阻塞业务工作已经迁移到新
执行器。旧 V1 Endpoint/Client/Server 默认路径未替换，保持过渡模块的有限范围。

## 方法与路由所有权

创建时复制整个方法数组，含描述、回调和参数指针；按 service/method 排序，
拒绝相同二元标识。不同服务允许复用方法号，原数组创建后可以释放或修改。
参数指针仍是借用，必须存活到路由器销毁；复制指针不等于取得参数强引用。

运行期二分查找方法。创建期采用原地插入排序，不依赖排序库隐藏分配；该排序
最坏 O(n²)，配置来自可信本地调用方，本轮不作大注册表性能承诺。每个 Channel
的路由槽位预分配，容量不得超过其流容量，槽位查找当前为有界线性扫描。

显式 admit 仅成功时发布能力和占用槽位；容量不足返回 AGAIN，尚不承担终止通知。
成功准入后所有路径都有一次本地 terminal 责任。路由器、槽位和方法表在分配前
一起预约预算；绑定和部分记录继续使用原有独立计费规则。

路由能力带路由器、槽位和单调代次，退役复用后旧代次拒绝，耗尽不回绕。
它是弱能力，不能在路由器已释放后使用，也不能允许旧指针指向新分配的对象。

## 从未知流到本地方法

```text
有效 Stream → admit → 最多48字节固定 OPEN 头
    → 头部形状和长度校验 → 本地方法查找
    → 用本地描述建立既有 RPC-B1 绑定
    → 完整 OPEN 元数据校验 → 方法准入/调度回调
```

未知方法在完整头阶段选择本地 UNIMPLEMENTED，不为该方法缓存元数据或业务体。
已识别方法仍须由下层完成全部 OPEN 元数据校验，只有合法完整 OPEN 才触发方法
回调，不能因为找到了编号就先发起业务。随后的 codec、lane、基数、长度、终局
和发送背压继续由同一个绑定验证。

接收头已被吸收后，绑定分配/预算失败是 RESOURCE_EXHAUSTED 终局，而不是暗示
可以重放输入的 AGAIN。所有失败仍由调用方释放原 RX 缓冲及网络信用。

接收记录和调用终局回调只在所有者上执行；视图借用到回调返回，不能将其原指针
排队给工作线程。回调可经弱能力发送或取消，但不能递归 receive/event、准入、
退役或销毁路由器。发送仍只有真实 Stream 接受后才接管载荷及提交状态。

终局通知不自动释放槽位；显式 retire 要求外层已移除该流路由且异步使用者静默，
并拒绝活跃调用和回调内退役。这样终局后的晚到字节不能意外重建一个调用。
路由器不接管 Channel handler，也不自动发送 FINAL_STATUS/RESET/close；未知
方法的本地错误必须由集成层选择线上的拒绝动作，不能宣称客户端已收到错误。

## 有序与停止域回收

正常销毁先取消全部未终局路由，回调返回后才释放绑定和表。停止域回收逐绑定
复用既有 Reactor recovery_guard；外部必须全程排除父循环重启/销毁和并发 API。
不嵌套获取不同租约，任何一步失败保留路由器及未完成责任。

一个重要组合状态是：固定头已到，绑定已创建，但 OPEN 的元数据尚未收齐。
下层尚未接受 OPEN，路由层却已经接受了 Stream。路由层必须为此状态补足一次
OWNER_STOPPED/CANCELLED 通知，不能因下层还未 opened 而丢掉准入责任。
同样，只有三字节头的未绑定路由也必须收敛。已经通知的终局在重试时不重复。

## 真实测试与本地证据

`test_rpc_record_router` 使用本机真实 TCP、两个 Reactor、Channel、RPC-B1 绑定。
服务端不再预先为每个测试 Stream 指定方法，而是注册一次表，从 OPEN 自动发现。
客户端仍使用原绑定发送，这是新增路径的组合测试，不是默认 V1 已迁移的证据。

覆盖四种基数、不同服务复用方法号、乱序注册数组、注册后修改原数组；逐字节
OPEN/TLV、同输入串接 OPEN/MESSAGE/HALF_CLOSE 和1024字节实际业务体；头部未完整
时真实半关闭的 DATA_LOSS；未知方法、坏元数据、分配失败与其他合法流继续处理。

负向测试覆盖重复/非法描述、三个构造分配点、预算不足、超大配置、错误所有者、
容量耗尽、重复路由、旧能力在槽位复用后失效、回调重入销毁/退役、真实父线程
停止前拒绝清理、回收中途租约失败后重试以及全部缓存/前缀最后预算归零。
故障包装只存在于测试目标的 malloc/calloc/recovery_acquire；合法路径执行真实实现。

本地不能解析 GitHub、没有 Xmake。只读源码快照工作流调用被安全检查拦截，未重试
该操作。使用已有 #260 归档并核对286个 Git blob；GitHub compare 确认本地链接的
原 Reactor/Channel/I/O/队列/Buffer 源在 #263 前未改动。四个新增依赖源/头逐文件
读取并核对 #263 blob，修改前 Xmake 重建后精确匹配
`4f9ef109e66564eb615b7830e70686ebc9f3e08d`。没有声称本地重建了整个 #263 树。

本地实际结果：GCC14.2/Clang17、O0/O2、C11/pedantic/NDEBUG四组测试通过，
GCC O2额外20轮通过；Clang ASan/UBSan含泄漏检查、GCC TSan非PIE通过；新实现两套
静态分析无诊断，新头两套编译器自包含通过。固定clang-format18.1.8用于新增代码。
初轮编译的容量溢出检查警告和销毁回调内退役的错误码不一致已修正后重新运行。
三个本地错误变体（忽略service、忽略代次、遗漏未OPEN的停止终局）均被测试拒绝，

## 后续与明确缺口

尚无业务执行器的生产派发/结果持有、方法级鉴权、慢 OPEN 总期限、自动拒绝记录
及RESET、默认Endpoint迁移、网络压缩、方向性协商、网络信用重设计、连接组DATA
或TLS。等待头的数量有界，但不代表已实现慢对端期限；外层仍须超时取消。
不新增线程/事件源或无界队列；预算不覆盖整个RSS、线程栈或Channel既有缓存。
下一步应把这份方法快照和路由器接入具体 Endpoint 的业务任务及终局发送，删除
已替换的手工路由，不长期维持平行的端点实现。
