# 非对称窗口应用持有与信用恢复回归

日期：2026-10-25。版本：`2.0.0-dev.106 -> 2.0.0-dev.107`。关联 #241、#240、#235、PR #324。

## 目标与场景

在真实 TCP Shared Channel 的非对称窗口双向发送中，验证网络信用不会因接收完成而提前返还；应用保留首条消息时，发送端仍受对端窗口限制。双方接收窗口分别为 Client 1,024 字节、Server 2,048 字节。

## 断言

- Client→Server 先提交 1,536 字节正文，Server→Client 随后在等待任一接收回调前提交 1,024 字节正文；两方向均完整交付且由应用持有。
- Client 方向已有 1,536/2,048 字节在途时，再发送 513 字节返回 `TR_AGAIN`；Server 方向已有 1,024/1,024 字节时，再发送 1 字节返回 `TR_AGAIN`。
- 两次拒绝后发送字节数、发送限额及接收计数保持不变，证明在应用持有消息期间没有提前返还信用。
- 分别释放两条已持有消息后，对端信用更新到达；复用 `TR_AGAIN` 时仍由调用方持有的原缓冲区重试成功，新增消息在两个方向交付。
