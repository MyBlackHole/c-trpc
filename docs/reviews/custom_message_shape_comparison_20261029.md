## 同等输入与模型范围

分别构造紧凑字段与固定块候选，比较同一组逻辑值及 presence。输入 Layout 已知、
有限且无环；未实现外部 schema 编译器或生成器。各样例有匹配布局，只有稀疏类型
预留 32 个可选 u64 槽，不把这些槽计入普通数组/bytes 类型来制造空间劣势。

紧凑候选沿用稳定字段编号、最短 tag/length varint、固定宽度值和可跳过字段。
固定块候选借鉴 SBE 的块边界/版本及顺序变量段，另外选择八字节 presence；这是
本项目实验布局，不是运行 SBE 上游库。两者均有四字节根长度，下表正文不含它。
数组均为 packed 小端 u32，包含零和 UINT32_MAX；没有用不同值编码省略比较成本。

共 28 个样例：缺席/零/最大 u64；缺席及 0/1/127/128/4096/65536 字节 bytes；
缺席及 0/1/31/128/1024 元素数组；1/2/4/8 层嵌套；32 槽中 0/1/4/16/24/25/32
个字段存在。v2 新增 optional counter/token，在各样例和各层轮换缺席、显式零、
空值及非空四种组合。嵌套是单子节点链，不据此声称任意对象图/复合数组已经覆盖。

## 实际字节结果

以下为 v1，避免 v2 presence 轮换影响不同形状的横向比较；完整 v1/v2 结果均归档。

| 逻辑样例 | 紧凑正文 | 固定块正文 |
|---|---:|---:|
| 一个 u64 sequence=7 | 10 | 20 |
| u64 + 4096 字节 bytes | 4109 | 4120 |
| u64 + 1024 个 u32 | 4109 | 4120 |
| 八层嵌套（含 bytes 和数组） | 246 | 362 |
| 32 个可选 u64，全部缺席 | 10 | 276 |
| 32 个可选 u64，存在 1 个 | 21 | 276 |
| 32 个可选 u64，存在 24 个 | 274 | 276 |
| 32 个可选 u64，存在 25 个 | 285 | 276 |
| 32 个可选 u64，全部存在 | 362 | 276 |

此模型中，每个已存在的稀疏字段增加 11 字节，固定块预留槽为 8 字节；高密度时
固定块更小的反例与低密度时紧凑格式更小的结果同时保留。改变 presence 宽度、
null 表示或布局规则会改变交叉点，不把 25 个字段泛化为任何 SBE 实现的阈值。
新结果只有字节/语义证据，不能与上轮 C 纳秒数拼成新负载性能结论。

## 未知字段修改和预算反例

旧读者增大根/子节点的 bytes、新增一个已知可选数值并删除另一个，再重编码。
新读者能取回根和子节点各自的 counter/token，且已知修改准确。紧凑格式保留 ID 5
与 ID 63 的原始字段，它们分别在已知可选字段前及末尾；固定块保留原 writer revision、
未知固定区、未知 presence 及未知尾部。旧读者不预先知道未来固定区的具体大小。
两种候选都拒绝通过未知携带伪造当前已知字段；缺席的已知字段也不允许 ID 冲突。

根和子节点各有六个 u32，总元素额度 10 时必须拒绝，12 时通过。字段、元素、工作、
根字节、深度、未知字节均验证准确边界及不足一个时拒绝；预算沿整棵消息共享。
这证明模型计数没有重置，不证明 Python 的峰值内存或 CPU 时间受相同数值限制。

六个独立负对照覆盖两种格式各自丢根未知字段、丢嵌套未知字段、进入子节点重置
预算。它们分别触发 ROOT_UNKNOWN_LOSS、NESTED_UNKNOWN_LOSS、EXPECTED_REJECTION；
运行器同时核对实际 format/mutation 事件及非零退出，排除入口错误的假阳性。
最终正常进程再次通过，结果与负对照前逐字节相同；没有修改生产或存档源文件。

另有一组固定块反例：旧端按边界携带加长的未知固定区，字节往返成功；了解 v2
布局的新端将其拒绝。未知内容可被跳过/保留，与未来语义已经合法是不同承诺。
不能把旧端的验证通过当作升级后数据或跨安全域转发的信任依据。

## 语义往返不等于同一字节

224 个新旧写入/读取组合及 256 个固定 seed 未知字段往返通过；其中 28 个固定块
组合为 v1 写入、v2 读取再用 v2 编码，明确升级布局，当前每层增加 12 字节但语义
不变。其余组合要求重编码保持原字节，并均核对新读者看到的语义。
需要字节恒等的透明传递仍使用 copy_wire；一般重编码不能充当签名/内容寻址的
规范化依据。这个结论来自实际反例，不用放松未知字段保留来通过检查。

六个手写黄金帧分别独立核对两种候选的 u64、数组及嵌套布局；非最短/溢出整数、
重复/逆序 ID、错 kind、坏长度、数组长度不整除、坏块及不支持版本均实际拒绝。
固定帧外层截断与伪造外层长度后的内部截断分别检查；五个完整字段边界前缀是
合法 optional 子集，明确计为合法消息，不错误宣称任何缩短都应拒绝。

## 对当前设计的建议

以下是本项目根据开源机制、平坦 C 探针和本轮结构证据作出的设计建议：

1. 通用 RPC 首选继续收敛紧凑、稳定编号的字段格式，数组使用 packed 固定宽度值。
   它适合新增/稀疏字段及逐字段未知携带；选择依据是演进与空间取舍，不宣称其
   验证 CPU 更低。上轮平坦 C 对照中固定块验证 CPU 更低的结果仍有效。
2. 初版保持单一通用格式。固定块保留为高密度数值负载的后续候选，需由实际负载
   的 CPU、随机访问及代码体积证据决定，避免立即承担两套生产生成器/演进规则。
3. 未知携带逐层绑定已验证源和原布局身份；已知字段修改后重编码仍受共享额度
   约束。原字节复制、语义往返、规范化字节分别定义，不用一个 roundtrip 混称。
4. 固定发布支持基线和这些形状/反例，后续 C/Rust 黄金字节、借用与失败边界必须
   单独实测；Python 通过不提前计为这些实现或 #245 已完成。

正式 tag/kind 编号、集合/字符串规则、描述规范化、方法合同及错误映射仍需形成
可审阅的具体 wire 方案。生产实现尚未开始；本记录提供收敛依据，不代替用户设计审阅。
