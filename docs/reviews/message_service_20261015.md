# MSG-C：消息变换、所有者通知与事件解绑

## 范围与依赖

基于 #254 / EXEC-A，提交基线 `55334e21e630ad8b2812f2f8bc5eca1b4ebcfbd3`。
关联 #235、#241、#243、#248、#249、#239。本轮把已有 Message、Zstandard、
任务执行器与 Reactor 事件源接入一个库内组合模块，不再只增加互不调用的原语。

`src/runtime/message_service.h/.c` 是会话组合层：允许消费各模块导出契约，
但不读取任务槽位、变换控制块或 Reactor 的私有布局。Message 核心仍不依赖
执行器/网络；任务执行器仍不识别压缩算法、消息或 fd。SDK、旧网络协议、
RPC 执行器及现有生产门面默认行为未迁移；这不是网络压缩已发布。

## 算法取消与执行器终局

新增 `tr_message_transform_run_checked()`，外部单调取消查询仅在 run 栈内借用，
不保留到操作对象。后端每个现有检查点调用该查询，观察到取消后锁存为变换取消。
服务适配将执行器取消令牌传入该接口，取消可以在压缩/解压过程中停止后续推进，
而不只是算法结束后丢弃结果。它仍是协作式取消，不实时抢占单次算法或分配调用。

算法终局与执行器终局不同：查询后才到达的取消，仍由执行器提交结果时裁决；
完成适配再次检查 cancelled，并清理已生成但不可交付的成功载荷。

## 两个接受点与原消息所有权

服务提交在原消息的显式克隆上调用 prepare。两份句柄共享同一存储引用，不复制
载荷或重复计算存储容量。执行器成功接受后才清空调用方原句柄并承担一次完成责任。
若 prepare 或执行器拒绝，释放临时克隆和新预约，原消息、能力输出及回调责任不变。

回滚已准备的操作时先 cancel 再 run/finish，取消路径不运行压缩算法；不能因为
prepare 成功就宣称任务已排队。临时克隆会增加一次引用操作，这个成本只属于显式
变换服务，none 继续使用原来的无队列移交路径。

## 通知不是结果队列

任务执行器新增受限通知函数：仅在启动前设置，或 join 且结果交付完毕后清除。
工作完成先入原槽位队列，再在锁内同步调用短小通知。通知不交付用户代码、不
重新进入执行器、不分配，只唤醒事件源；结果和存储责任始终留在原执行器槽位。

服务拥有一个 `EFD_NONBLOCK | EFD_CLOEXEC` 的 eventfd，Reactor 只借用。
读取在 dispatch 之前执行，避免先交付后清通知时吞掉新的唤醒。一个事件可以
代表多个完成；每轮 dispatch 受数量上限约束，剩余完成重新置位通知，不等待
另一个工作完成才恢复前进。通知与完成个数不需要一一相等。

依据 [Linux eventfd(2)](https://man7.org/linux/man-pages/man2/eventfd.2.html)：
普通 eventfd 的 read 清除聚合计数；非阻塞 write 的 EAGAIN 表示计数器已满而
仍然可读，因此不应丢弃结果或忙等。read/write 的 EINTR 最多重试四次，耗尽或
其他 I/O 错误锁存 errno。错误后拒绝新消息，在所有者上取消未终局任务。

每个服务另占用一个现有 Reactor 定时器，周期由显式配置限制在 1 ms..1 s，
作为通知失效后的前进保障；即使写持续失败，也能领取已接受结果。定时器复用
同一个有界 pump，不新增轮询线程。这不是零开销方案，周期成本、批量大小及
运行中信号压力仍需性能测量；不以正常路径事件驱动掩盖故障时永久丢失唤醒。

## 创建、启动、关闭与失败保留

create 在所属 Reactor 的 owner 上只预分配服务/任务槽位、创建 fd 与执行器，
不启动线程和注册源；失败不发布半对象。start 在一个 owner turn 中依次发布
辅助源、后备定时器并启动执行器；任一步失败停止准入并保留对象，调用方必须关闭。

关闭次序为：

```text
停止准入 -> 有界完成交付/等待工作退出 -> join
    -> 所有完成回调已经返回
    -> 注销辅助 fd 事件源 -> 注销定时器
    -> 清除通知 -> 销毁执行器 -> 关闭 fd -> 释放服务与预算
```

未静默返回 TR_AGAIN。回调/提交内部的重入 close 返回状态错误，不能释放当前
仍在使用的组合对象。辅助源或定时器注销失败时保留对应发布、fd 和回调参数；
重试只继续尚未跨过的屏障。执行器最终销毁失败时，已解绑的源不重新发布，只重试
最终销毁；Linux close 的错误不能靠重试同一个 fd 数字解决，以免关闭被复用的 fd。

**父 Reactor 必须晚于该服务关闭。**on_owner 接口要求运行在所指定 Reactor 的
所有者上下文，跨线程用既有 tr_reactor_call。当前阶段不提供父循环先行致命退出后
的所有者接管；也没有把新服务挂入旧 Runtime/Client/Server 的自动销毁链。
正式门面接入前必须补齐这一异常生命周期，不能把有序关闭测试扩展成任意停机安全。

## 测试范围

新 `test_message_service` 是真实 Reactor 集成目标，链接真实 trcore；不是独立
模块测试替代物。它仍复用生产源，不增加分析专用源或放宽编译数据库覆盖规则。
链接包装只存在于该测试，限定在当前服务的 fd/定时器/任务创建，不影响其他通知。

覆盖：
- 正常编码、解码、输出保留、错误所有者调用及完成回调重入关闭；
- 固定在首个真实算法调用返回后阻塞工作者，在另一线程取消；解锁后确认
  算法不再进入第二次调用，输入/输出与工作区责任收敛；
- prepare 后执行器拒绝，原消息地址/长度/引用、预算及输出能力保持；
- 四个控制块分配失败、eventfd 失败、源/定时器注册及 arm 失败、两个线程
  启动失败位置，部分启动对象仍可关闭；
- 辅助源注销失败、定时器注销失败、最终执行器销毁失败时保留 fd 与对象；
- 持续 write(EIO) 和连续 EINTR 用后备定时器交付结果，拒绝新消息，不自旋；
- 在同一 owner turn 将真实计数器置满，积累四条完成；禁止测试后备定时器
  帮忙交付，验证 dispatch_limit=1 的事件续跑和真实 write(EAGAIN)；
- 槽位/服务实例复用时旧任务能力失效；所有源注销之后才 close，所有输出
  释放后预算归零。辅助源的陈旧 epoll 代次规则仍由现有 Reactor 契约负责。

## 实际局部证据及边界

工作容器无 Xmake，无法解析 GitHub。已从连接器返回内容重建并校验基线 Git blob，
包括 Message、引用/预算、任务执行器、变换/Zstandard 及 Xmake 文件，防止转录漂移。
本地使用一个明确的事件循环替身及仅本地头文件声明，不作为生产源码上传；
它使用真实 epoll/eventfd 和 pthread，但不是 c-trpc Reactor。

新生产适配、修改的执行器/变换、真实 Zstandard 与集成测试在该替身上用
GCC 14.2/Clang 17、O0/O2、NDEBUG 构建运行，另做 GCC O2 20 轮重复、
Clang ASan/UBSan 与 GCC TSan；这些只构成本地组合证据，不是全库验收。
Zstandard 是本地预构建静态库，未宣称第三方库自身已被检查器插桩。

初轮 Clang analyzer 对柔性数组分配总长提出零长分配路径诊断；在已有容量上界
外补充总长下界验证，再运行分析，没有新增抑制规则。GCC/Clang 对三个新增或
修改的生产实现最终无诊断；服务接口的本地分析依赖声明替身，真实头闭包和固定
版本分析器仍须远端验证。三个导出头另作 GCC/Clang 自包含编译。

本地格式工具为 clangd 17。远端必须以本次精确 head 的 Xmake、固定格式器、
两套静态分析、实际新增测试执行日志及 ASan/TSan 结果为准，不能继承 #254 的绿色。
提交时不预写远端成功；后续实际结果更新到 PR 及原任务。
