# Stream 消息长度与非对称窗口三档回归

日期：2026-10-25。版本：`2.0.0-dev.105 -> 2.0.0-dev.106`。关联 #241、#240、#235、PR #324。

## 目标与场景

在真实 TCP Shared Channel 中验证消息长度 `L` 与对端接收窗口 `W` 的小于、等于和大于关系。Client 接收窗口为
1,024 字节，Server 接收窗口为 2,048 字节；双向场景合计覆盖 `L<W`、`L=W` 和 `L>W`。

## 断言

- Client 向 Server 发送 1,536 字节（`L=1536<W=2048`），发送上限为 Server 公布的 2,048 字节，正文完整交付。
- Server 向 Client 发送 1,024 字节（`L=W=1024`），正文完整交付。
- Server 向 Client 发送 1,025 字节（`L=1025>W=1024`）立即返回 `TR_ERR_BAD_LENGTH`，已发送信用不变且 Client 未收到 DATA。
- 双向发送上限均取对端窗口；接收端持有消息期间正文逐字节有效，释放后账目与缓冲区可正常回收。

## 验证结果

- GCC Release `test_transport/default` 通过，`git diff --check` 通过。
- 暂时将发送准入条件改为使用本地 `initial_window_bytes` 后，测试在 Server 对 1,025 字节超窗消息的拒绝断言处失败：本地窗口 2,048 会错误放行超过对端 1,024 窗口的消息。该变异已撤销，生产源码无差异，恢复后的目标测试再次通过。
- 测试命令将 `TMPDIR` 与 `XMAKE_TMPDIR` 指向工作区 `build/test-tmp`；未在 `/tmp` 创建测试文件。
