## 基线归档与符号事实

执行顺序：`mkdir -p build/tmp build/r14`；`TMPDIR="$PWD/build/tmp" xmake f -c -y -m release --toolchain=gcc && TMPDIR="$PWD/build/tmp" xmake build trcore && python3 scripts/rpc_v1_inventory.py --root . --archive build/linux/x86_64/release/libtrcore.a --output build/r14/rpc-v1-before.json`。配置和构建退出码均为 0；inventory 扫描 209 个 C 系文件、发现 103 个候选名称、41 处非 V1 核心生产引用、38 个归档全局定义和 3 个归档对象未解析引用。后两个数字是脚本的 V1 候选名口径，不是 `nm` 的全部符号数。

`ar t build/linux/x86_64/release/libtrcore.a` 有 76 个成员，其中 `rpc.c.o`、`rpc_wire.c.o`、`rpc_codec.c.o` 均在。`nm -A -g` 显示 `rpc.c.o` 定义 `tr_rpc_call_*`、`tr_rpc_endpoint_*`、`tr_rpc_executor_group_*`、`tr_rpc_message_release`、`tr_rpc_register_*`、`tr_rpc_unary_call*` 等旧 V1 全局入口；它**没有**定义 RAW/Wire 函数，而是有 `U tr_rpc_raw_encode`、`U tr_rpc_wire_decode_ex`、`U tr_rpc_wire_encode`。`rpc_wire.c.o` 分别定义 `T tr_rpc_wire_decode`、`T tr_rpc_wire_decode_ex`、`T tr_rpc_wire_encode`；`rpc_codec.c.o` 定义 `T tr_rpc_raw_encode` 与 `T tr_rpc_raw_decode`。R14 后必须删除前两个对象、保留第三个及其 RAW ABI，且精确检查旧符号；`tr_rpc_endpoint_result` 等 V2 类型名不得被前缀规则误杀。
