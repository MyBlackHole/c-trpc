## 基线归档与符号事实

执行顺序：`mkdir -p build/tmp build/r14`；`TMPDIR="$PWD/build/tmp" xmake f -c -y -m release --toolchain=gcc && TMPDIR="$PWD/build/tmp" xmake build trcore && python3 scripts/rpc_v1_inventory.py --root . --archive build/linux/x86_64/release/libtrcore.a --output build/r14/rpc-v1-before.json`。配置和构建退出码均为 0；inventory 扫描 209 个 C 系文件、发现 103 个候选名称、41 处非 V1 核心生产引用、38 个归档全局定义和 3 个归档对象未解析引用。后两个数字是脚本的 V1 候选名口径，不是 `nm` 的全部符号数。

`ar t build/linux/x86_64/release/libtrcore.a` 有 76 个成员，其中 `rpc.c.o`、`rpc_wire.c.o`、`rpc_codec.c.o` 均在。`nm -A -g` 显示 `rpc.c.o` 定义 `tr_rpc_call_*`、`tr_rpc_endpoint_*`、`tr_rpc_executor_group_*`、`tr_rpc_message_release`、`tr_rpc_register_*`、`tr_rpc_unary_call*` 等旧 V1 全局入口；它**没有**定义 RAW/Wire 函数，而是有 `U tr_rpc_raw_encode`、`U tr_rpc_wire_decode_ex`、`U tr_rpc_wire_encode`。`rpc_wire.c.o` 分别定义 `T tr_rpc_wire_decode`、`T tr_rpc_wire_decode_ex`、`T tr_rpc_wire_encode`；`rpc_codec.c.o` 定义 `T tr_rpc_raw_encode` 与 `T tr_rpc_raw_decode`。R14 后必须删除前两个对象、保留第三个及其 RAW ABI，且精确检查旧符号；`tr_rpc_endpoint_result` 等 V2 类型名不得被前缀规则误杀。

### `test_transport.c` 混合目标的逐场景边界

`main` 中 `test_refcount_semantics` 至 `test_channel_reconnect_one_lane_unreachable`、`test_channel_version_negotiation_failure`、`test_channel_keepalive_and_diagnostics`、`test_client_server_facade_nodelay_policy` 属于共享基础/Channel/Transport，保留原目标与断言。特别保留 parser 的单字节分片、CRC、池背压、非法标志/长度，Reactor owner 发布、TCP、Channel lane/flow/fragment/drain/reconnect 的全部场景；这些不是旧 RPC Core 的删除清单。

需从该目标移出的旧 V1 场景逐个为：`test_rpc_wire_and_raw_codec`（旧 Wire 编解码退役，RAW 往返迁到 Task 2 `test_rpc_raw_codec`）；`test_rpc_method_registration_is_owner_serialized`、`test_rpc_method_index_collisions`（旧注册/索引，V2 冻结方法表见 `test_rpc_v2_server::test_configuration`、`test_public_server`）；`test_rpc_destroy_fails_closed_while_reactor_stopping`（旧 Endpoint，V2 资源屏障见 `test_rpc_record_endpoint_tcp::test_stopped_recovery` 与 `test_server_record::test_stopped_work`）；`test_rpc_deadline_heap_order`、`test_rpc_call_slot_reuse`（旧堆/slot，V2 deadline 与重用见 `test_client_record::test_public_saturated_deadline`、`test_public_unary_slots`）；`test_rpc_unary_raw_roundtrip`、`test_rpc_large_message_fragmentation`、`test_rpc_bidi_streaming_raw_fast_path`、`test_rpc_client_and_server_stream_shapes`（V2 形状/复制见 `test_rpc_v2_sdk::test_shapes_and_copy`、`test_large_message_ownership`）；`test_rpc_connection_replacement_semantics`（V2 peer retirement 见 `test_rpc_v2_sdk::test_stats_peer_retirement`，旧 Endpoint 的连接替换机制退役）；`test_rpc_metadata_cancel_deadline`（V2 `test_client_record::test_shapes_and_metadata`、`test_deadlines_and_lifecycle` 与 `test_rpc_record_cancel::test_crossed_final_and_cancel`）；`test_rpc_interceptor_v1`（无 V2 interceptor 合同，退役）；`test_rpc_multithread_executor_per_call_serialization`（旧 per-call executor 串行机制退役，V2 工作完成顺序须按 G4 的公开边界核实）。从 `test_transport` 清理旧 include/fixture 时，不删除上述共享测试。

## 先补的 V2 确定性断言

以下是**登记的后续工作，不是现有通过证据**。选择已有 V2 目标中最接近的 fixture 扩展，避免复制整套网络脚手架。全部使用条件变量/故障包装或容量栅栏，不靠睡眠碰运气。

| 编号与目标 | 确定性故障点 | 通过判据 |
| --- | --- | --- |
| G1：扩展 `test_client_record` 的公开 deadline 准入场景 | 已接纳一个有期限调用后，以该目标已有 `clock_gettime`/timer-arm 包装在第二个更早期限调用准入点单次失败；释放原调用的响应/期限门闩。 | 第二个入口返回 `TR_ERR_SYS`、输出句柄不变、无 OPEN/幽灵终局；第一个调用按其原期限恰一次终局，随后同槽可重用。若 V2 不存在对应 arm 准入点，只断言实际公开读钟/连接进度故障，不模拟旧堆根。 |
| G2：扩展 `test_client_record` 的销毁/终局竞态场景 | 在 V2 客户端 terminal 回调内以条件变量卡住，另一线程触发断连与 `tr_client_destroy`，然后放开回调。 | 销毁不得越过活动回调；返回可重试状态后最终收敛；终局回调恰一次、已锁存状态不被断连改写，客户端预算归零。 |
| G3：扩展 `test_server_record` 的 V2 容量拒绝场景 | 单 worker 的 `work` 回调在条件变量门闩停住，按固定 task/dispatch 容量填入已接纳一元与流式调用，再提交一条超额调用；放开门闩后用原连接再调用。 | 超额调用在业务回调前获得唯一合法拒绝终局（若合同规定 `RESOURCE_EXHAUSTED` 则精确断言）；此前受理工作均兑现各自终局；同连接随后成功、Server 排空且预算归零。不要求旧 16/14+2 队列阈值。 |
| G4：扩展 `test_rpc_record_endpoint_tcp` 的同流/跨流流控场景 | 以该目标已有真实窗口/发送包装把一条 V2 流的后续 MESSAGE 压住，同时另一流继续，再释放窗口。 | 受阻流不超收、不提前终局，额度恢复后按序交付且只终局一次；另一流可独立完成；消息缓冲和 Endpoint 销毁预算归零。不观察旧 pending executor task 或 V1 `tr_rpc_message_release`。 |
| G5：新增 `test_rpc_v2_server_destroy_drain`（计划 Task 3） | 原 `test_v2_server_destroy_waits_for_accepted_work` 的真实 TCP、条件变量阻塞已接纳 work。 | 阻塞期间首次 `tr_server_destroy` 为 `TR_AGAIN`、Server owner 未提前释放；放行后重试 `TR_OK`，server terminal 恰一次。 |
