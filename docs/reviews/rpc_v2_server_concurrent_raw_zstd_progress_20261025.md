# 公开 Server 并发 RAW/Zstandard 进展回归

日期：2026-10-25。版本：`2.0.0-dev.84 -> 2.0.0-dev.88`。关联 #241、#235。

## 验收目标

在真实公开 Server 与双 DATA 连接上同时保持压缩消息来源和 RAW 消息来源活跃。服务端应用持有部分解压输出期间，验证另一物理 DATA 成员上的 RAW 源能持续补充有界在途窗口并交付；压缩源也必须完成固定批次。该回归用于证明并发来源下的有限进展，不定义长期公平性阈值。

## 场景与证据

- 真实公开 `tr_server`/`tr_client` 建立两条 DATA 物理连接和两个 transfer。Server 接收 Zstandard，单条解码正文上限为 1 MiB，压缩任务容量为 32。
- 第一成员分八批提交共 256 条真实 1 MiB Zstandard 消息，每条正文填充不同字节并由服务端逐字节校验；每批 32 条全部完成回调后才提交下一批。前五条解码输出被应用接管并持续持有，其余 251 条在回调中释放，避免持有输出使预算自然拒绝并关闭压缩成员。
- 第二成员由独立测试线程全程发送 1 字节 RAW 消息，最多维持 32 条已接受、未交付消息；每次收到服务端完成回调后立即补发下一条。总消息保护上限提高到 65,536 条，若测试触及上限会断言失败。
- 服务端分别记录每一批首条与末条 Zstandard 回调时已交付的 RAW 数量，并要求每批至少完成 32 条 RAW 消息。测试链接包装确认所有 Zstandard 与 RAW 消息的提交标志，并验证两类首条消息被路由到不同 DATA 物理连接；后续 RAW 消息保持在同一 DATA 连接代次。
- 八批完成后，测试停止 RAW 生产线程并排空已接受消息，再逐字节复核五条仍被持有的 1 MiB 输出，随后释放并正常 drain/销毁 Server 与 Client。

## 观测结果

- dev.85 首轮 GitHub GCC Debug CI 在该场景失败。复现显示服务端 DATA 事件以 `TR_ERR_STATE` 关闭；根因是旧测试配置仅有 8 个压缩任务槽，却允许客户端在服务端解压完成前提交 32 条消息，任务槽耗尽后按设计拒绝新任务。dev.86 将任务容量提高到 32；生产逻辑不变。
- GCC Debug 定向目标四次通过，压缩批次期间 RAW 交付为 154–273 条；完整 Debug 套件 91/91 通过，耗时 151.574 秒。
- GCC Release 定向目标六次复跑及完整 Release 套件中的一次定向运行，共七次通过，RAW 交付为 1,489–2,842 条；完整 Release 套件 91/91 通过，耗时 142.284 秒。
- GCC ASan/UBSan（`detect_leaks=1`）定向测试通过，观测到并发区间内 5,315 条 RAW 消息；GCC TSan 定向测试通过，观测到 2,255 条。
- `git diff --check` 与系统 clang-format 23.1.3 的改动行复核通过；项目固定 clang-format 18.1.8 未执行。

dev.87 的新四批场景另有以下本地证据：

- GCC Release 定向目标 7/7 通过，各批进展总和为 6,397–11,011 条 RAW；一次观察到四批分别交付 1,377、1,811、1,707、1,894 条。完整 Release 套件 91/91，通过用时 131.980 秒。
- GCC Debug 定向目标 4/4 通过，四批 RAW 进展总和为 2,150–3,231 条。
- Clang Release 定向目标通过，四批 RAW 进展总和为 8,592 条。
- GCC ASan/UBSan（`detect_leaks=1`）定向目标通过，四批 RAW 进展总和为 19,238 条；GCC TSan 定向目标通过，为 11,705 条。
- 系统 clang-format 23.1.3、`git diff --check` 通过；固定版 clang-format 18.1.8 不在环境中。

dev.88 将同一有界场景加倍，并为每批记录发送开始至全部 32 条 Server 回调的单调时钟耗时；耗时仅用于诊断，不做运行时阈值断言：

- GCC Release 定向目标六次通过（一次 `xmake test` 加五次直接复跑），总压缩阶段 390–433 ms，每批 RAW 进展 1,718–3,171 条；观测到的每批压缩耗时为 42–65 ms。另一次包含在完整套件中的运行总阶段 418 ms。
- GCC Debug 定向目标通过：八批各至少 32 条 RAW，压缩总阶段 489 ms，每批 RAW 为 240–912 条。
- Clang Release 定向目标通过：压缩总阶段 409 ms，RAW 进展总和 18,904 条。
- GCC ASan/UBSan（`detect_leaks=1`）定向目标通过：压缩总阶段 1,681 ms，RAW 进展总和 41,031 条。
- GCC TSan 定向目标通过：压缩总阶段 4,571 ms，RAW 进展总和 21,458 条。
- GCC Release 完整套件 91/91，通过用时 130.110 秒；改动行 clang-format 与 `git diff --check` 通过。

## 结论边界

测试覆盖八批共 256 条 Zstandard，以及全程持续补充的有界 RAW 在途窗口，并在每批内分别检查 RAW 前进。它能发现两来源并发时某一方在整个批次窗口内完全不进展；新增的批耗时也只是一组本机有限负载观测，不是受控跨机器性能基线，不测量每条消息的最大等待时间，也没有为公平比例建立通过阈值。完整 #241/#235 仍需明确长期持续负载、消息大小/配比、延迟阈值、稳定基线和更广预算/取消组合。本次只改集成测试、文档与版本，不改生产运行时、公开 API/ABI 或 wire。
