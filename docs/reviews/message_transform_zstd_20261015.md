# MSG-B：有界 Zstandard 消息变换与可取消操作

## 范围与基线

基线为 MSG-A / #252 的 `3d678f96a30f106f7d96a8b059414c7cd75e888e`。
本切片接在尚未合并的消息存储接口之后，关联 #235、#241、#248、#239。
新增生产实现与独立测试，不替代整体消息层、压缩接入或模块化整改验收。

本轮没有修改旧 Buffer、RPC、Channel、Reactor、SDK 安装白名单、工作流、
既有测试、基础引用计数/预算原语或静态分析基线。现有网络路径仍不执行压缩。

## 接受不是完成，也不是执行器准入

```text
prepare 失败：输入和输出指针不变，回滚新预约，无待完成责任
prepare 成功：消费输入 → READY
READY → run 的唯一执行者 → RUNNING → DONE → finish → 操作销毁
              ↑ cancel 只设置取消意图，不接管释放责任
```

`prepare` 只接受一份分阶段变换操作，既不入队，也不创建线程、不调用完成回调。
调用方发布指针时必须同步，接受后必须驱动一次 `run`，再 `finish`。
外部队列拒绝时也须执行 `cancel → run → finish`，不能丢弃已接受操作。
这不是通用执行器、完成队列、停止屏障或每 Call 顺序调度已经落地。

`run` 不得在 Reactor 回调执行；它返回 `TR_OK` 只表示终局结果已保存。
实际结果单独区分成功、取消、容量限制、真实分配失败、坏数据和内部错误。
`finish` 必须在执行者和所有取消者退出后调用；原子状态不是对象生存期屏障。
尚未完成返回 `TR_AGAIN`；已有存活输出则拒绝覆盖，并保留操作供正确重试。
成功结果通过 Message 移交，失败或取消不会返回部分输出。

取消位和终局提交共用一个原子状态。`RUNNING → DONE` 的比较交换是提交点：
取消位先写入则销毁可能已生成的输出，发布取消终局；提交先完成则取消返回
`TR_ERR_STATE`。这避免“单独检查取消后仍发布成功”的竞态。
取消请求自身不返还预算、不释放输入、不销毁上下文。重复的已接受取消幂等。
检查点位于最多 64 KiB 的输入/输出推进之间，不承诺抢占单次算法或分配调用。

## 内存责任与峰值

输入沿用原存储已有预算，不再次计费；输出/操作使用传入的非零硬预算域。
需要统一域限制时，组合方必须让输入和变换使用同一预算域；接口不会把不同
预算域的上限自动合并，也不会接管或重置调用方预算。

接受前预约：

```text
操作控制块 + 输出存储控制块 + 输出载荷容量 + 完整工作区上限
```

控制块先预约再分配，输出载荷和后端上下文在 `run` 分配。真实分配仍可能失败。
编码输出容量为 `min(compressBound(输入长度), 编码上限)`，不足则变换报告 LIMIT，
不能把压缩后可能较小当成一定能成功。解码输出容量为已检查的声明原始长度。
零长度输出实际分配并记账一个字节，避免依赖 `malloc(0)` 定义拥有关系。

Zstandard 使用自定义分配器：每次请求加上对齐后的记账头，校验剩余工作区，
再调用真实分配；维护所有在用分配的链表，不把第三方内部分配排除在上限外。
没有启用后端工作线程。先释放上下文及其全部分配，再归还完整工作区预约。
异常残留也先实际释放再报内部错误，不带着残留分配返还额度。

`run` 释放输入与工作区；未领取输出仍有拥有者且继续占用容量。
`finish` 归还操作元数据；输出有独立存储控制块，可在操作销毁后继续克隆/切片。
最后输出引用才释放载荷和控制块，随后 MSG-A 归还载荷额度。
记账覆盖本切片的请求字节及自己的控制块/分配头，不覆盖 malloc 元数据、
栈、线程栈、分配器驻留页、旧池保留容量或整个进程 RSS。

## 解码验证

消息解码只接受一个普通 Zstandard 帧：拒绝跳过帧、非零字典 ID、串接帧及尾随字节。
每条消息使用全新上下文，不跨消息共享字典或压缩历史。

编码长度、声明原始长度、帧窗口及工作区分别有硬上限。帧头已知原始长度时，
必须与消息声明一致；帧头未知长度仍允许，但真实输出必须恰好等于已预约长度。
不使用对端帧头直接决定任意大小分配。显式检查帧窗口，同时配置流式解码窗口上限。
坏头、截断内容/帧尾、错误校验和、长度不符均无成功输出。编码主动附加校验和；
解码遵循帧自身的校验标记，不声称校验和等于认证或要求外部帧一律携带校验和。

输出恰好占满时仍可能需要读取帧尾。实现用一个字节的栈探针区分“仅消费帧尾”
与“又产生数据”，不会越界写，也不会把截断或超长输出当成完整消息。

确定性交错用门闩而非睡眠：执行前取消、压缩/解压推进中取消、后端成功但输入
释放尚未完成时取消；含四个并发取消者。输出继续持有会阻止新的预算准入，
最后引用释放后才允许后续操作；同一操作不能被重复运行或重复领取。

初轮静态分析对载荷指针交接及兜底分配链清理提出诊断。实现改为局部指针管理
失败载荷、成功发布后才绑定释放责任，以及显式弹出链头；随后重新执行上述完整
局部矩阵，没有抑制告警或变更告警基线。
