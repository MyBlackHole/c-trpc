# RPC-A：独立调用记录与统一语义状态内核

## 基线、阶段与采用范围

基于 #261 合并点 `624fa3269d41a897c66fa0f31b87de9091f670af`，其树与
原 head `cc863c4015bfc79a67b998529ef6ad4bc480621d` 相同，仍在父功能分支
而非 main。关联 #240、#235、#241、#247、#248 和 #239。本轮停止继续叠加近义 Runtime 接管接口，转入

新旧解码器互相拒绝版本的负向测试已经加入。

## 一手设计依据与本项目决策

- [gRPC HTTP/2 协议](https://github.com/grpc/grpc/blob/master/doc/PROTOCOL-HTTP2.md)
  区分请求头、长度前缀业务消息、请求方向结束和响应尾部状态；即使成功也有
  最终状态。消息与传输 DATA 帧边界并不一一对应。
- [gRPC 压缩](https://grpc.io/docs/guides/compression/) 支持方向性选择与逐消息
  不压缩，每条消息的压缩历史不跨消息延续。

读取日期为2026-10-16。这里只借鉴边界和终局原则，不宣称实现 gRPC 互通；
记录采用 c-trpc 现有小端原语，不复制 HTTP/2、HPACK 或 gRPC 的5字节格式。

本阶段选择固定48字节、逐字段编码的候选头。相比可变头，其校验和字段作用域
更直接，但增加的线协议开销尚未做性能比较，协议正式启用前仍可更改。没有把
“当前帧较短”当成省略最终状态、方法打开或资源检查的理由。

## 记录格式

| 字节偏移 | 长度 | 含义与允许范围 |
| --- | --- | --- |
| 0 | 4 | TRPC 魔数 |
| 4 | 2 | 小端版本2 |
| 6 | 2 | OPEN / INITIAL_METADATA / MESSAGE / HALF_CLOSE / FINAL_STATUS |
| 8、12 | 各4 | service_id、method_id，仅 OPEN；数字0合法 |
| 16、20 | 各4 | codec_id、compression，仅 MESSAGE |
| 24、28 | 各4 | 编码体长度、声明解码长度，仅 MESSAGE |
| 32 | 4 | 元数据长度，仅 OPEN、INITIAL_METADATA、FINAL_STATUS |
| 36 | 4 | 最终状态，仅 FINAL_STATUS，0..16 |
| 40 | 8 | 相对剩余期限纳秒，仅 OPEN；0表示无期限 |

头后为元数据和编码体。两者不在同一记录中共存：MESSAGE 必须无元数据，
控制记录必须无业务体、codec 或压缩标识。未使用字段非零明确拒绝，避免未来
误把控制数据交给变换器。none 的编码/解码长度必须相等；压缩消息必须有非空
编码帧，即使其原始消息长度为0。未知算法和不在本方向获准集合中的算法拒绝。

相对期限由绑定层在实际发送时根据剩余时间产生；本机绝对单调时钟不得上网。
已经过期必须本地结束，不能因下取整成0而被解释成无限期限。此模块只承载该值，
未实现排队耗时扣除、定时器或跨机器时间转换。

## 长度、借用与失败语义

固定头完整时立即验证编码长度、解码长度、元数据长度及总长溢出；正文未到齐
也必须先拒绝超限头。metadata受调用者更小上限与512字节当前硬上限约束。
允许算法集合来自本地方向性准入策略，不能直接把远端自报能力当授权。

`decode_header` 不要求正文到齐，可以用于分配前准入。`decode` 每次返回首条
完整记录的借用视图及精确 consumed，后续串接记录保持未消费；不完整返回 AGAIN。
EOF遇到 AGAIN 是截断，不能伪装正常半关闭。所有失败保持输出不变。

编码器只写固定头，不分配、复制或接管载荷。调用方可使用分散/聚集发送，但必须
持有全部缓冲到发送结束；解析视图也不自动延长输入寿命。元数据在本层是有界字节，
TLV内容、保留键、身份认证、方法与codec匹配仍须由上层验证。本模块不运行解压，
也不把“声明解码长度合法”当成“真实解压输出已验证”。

## 四种调用形态使用同一状态模型

请求方向为 OPEN -> MESSAGE* -> HALF_CLOSE；响应为 INITIAL_METADATA? ->
MESSAGE* -> FINAL_STATUS，响应有 MESSAGE 时必须先有 INITIAL_METADATA。
基数来自本地方法描述，不由远端 OPEN 自行指定。

- ONE 恰好一条，零长度 MESSAGE 仍算一条；MANY 可为零条。
- 请求半关闭不终止响应方向；收到响应 MESSAGE 不宣布成功。
- 成功 FINAL_STATUS 必须满足双方 ONE 约束。错误状态允许在任何已打开阶段
  提前结束，不要求先收到请求体或半关闭。
- MANY/MANY允许无请求/响应体直接成功。对于服务端提前成功，不要求请求已
  半关闭，但必须已满足已知的 ONE 请求基数；其余上传的丢弃/复位由绑定层定义。
  这是本项目显式决策，不声称 gRPC 各语言对此有完全相同的 API 行为。
- 本地取消、期限或断连通过 abort 选定非OK终局；最先成功的终局获胜。后续
  状态、消息及取消不得复活调用或改写结果。

状态无堆分配、无锁、无回调，只由单一所有者使用。发送预检可在副本上进行，
只有下游接受后才提交副本；中间必须没有重入修改。当前没有将该责任接入旧
Call/Stream，因此不宣称已经解决现有重试、发送准入或回调生命周期。

## 测试与本地实际证据

新增 `test_rpc_record` 只链接5个实际生产对象：rpc_record、旧rpc_wire、
message、transform、zstd，以及静态Zstandard；不链接整个trcore补齐依赖。
Xmake只新增一个生产翻译单元与一个测试目标，既有检查/告警基线保持不变。

测试包含独立固定字节向量、非对齐输入、每个字节位置截断、记录串接、头阶段
超限拒绝、非法字段/算法/版本、失败不改输出及新旧版本互拒。四种基数均验证
空消息、零消息流、半关闭、先数据后状态、提前错误和终局竞争；长度7以内的
6192个事件尝试加上每个可达前缀的16种本地终止检查。另有固定种子的20000个
头部变异样本。有限枚举和变异测试不是无限状态空间证明或完整模糊测试活动。

组合用例执行真实Zstandard编码与解码，只将MESSAGE业务体视图交给变换器，
OPEN里的凭证样例保留在控制记录内；最后引用释放后同一预算归零。该测试不涉及
网络、Runtime线程或真实鉴权，不把字节分离当成压缩侧信道的完整防护。

本地复用已提供的 #260 固定源码归档，核对286个Git blob和树；本次独立目标
使用的旧源/头在 #261 未改。Xmake按 #261 的唯一追加目标恢复，恢复后的blob为
`db739977ecc8cc7ed8e1bce838ad549c56a70830`，再作本次增量。未声称本地重建
了 #261 所有文档/测试，也未运行本地完整Xmake构建；容器没有Xmake。

实际局部结果：GCC14.2/Clang17，O0/O2且NDEBUG的4组构建运行通过；GCC O2
额外20轮通过；Clang ASan/UBSan含泄漏检查通过；新生产源两套分析器无诊断；
新头两套编译器自包含编译通过。新核心执行区间的malloc/calloc/realloc包装
禁止分配。Zstandard为本地预构建静态库，未宣称其自身已插桩。

四个仅本地错误变体（终局复活、MESSAGE夹带元数据、短读提前改输出、成功遗漏
ONE约束）均被测试拒绝，最终代码已恢复。固定clang-format18.1.8处理新增源码。
远端精确提交的完整CI/格式/RPC冒烟和实际测试日志须单独核对，不沿用 #261。
