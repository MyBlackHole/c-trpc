## 实现选择

普通工厂、冻结方法表、传输专用工厂、一元及流式公开签名继续使用 #281。
内部 `rpc_record_client.c/.h` 采用 #280 最终提交
`d8dc7f5acd2a0c3279ad80d65798e823ed890536` 的共同发送路径：
一元 MESSAGE/HALF_CLOSE 仅记录在原调用槽的发送意图中，并进入流式调用已有的
请求检查、时间检查和发送函数；每次进度推进最多两步。删除 #281 单独的
内部一元包装与复制发送逻辑，公开一元入口仍保留，不恢复旧 `_v2` 工厂别名。

同一个发送入口在每段发送前重新检查本机期限、钟源和绑定终局，正文复制在
传输流创建前完成。终局不能在发送尚未返回时回收请求或进入可释放用户参数的
业务回调。整个实现仍只有一张调用表、一个绑定终局和原有进度定时器。

新旧实现的隔离对照覆盖 MESSAGE 接管后、HALF_CLOSE 准入前的钟源失败：
旧 #281 的一元专用路径没有该阶段检查，会继续发送后续记录并可能交付响应；
新路径选择 INTERNAL，不接受 HALF_CLOSE 或交付迟到响应。该故障注入只在测试
发送包装内启用，不修改生产钟源，也不据此宣称所有时钟和网络竞争均已验证。
