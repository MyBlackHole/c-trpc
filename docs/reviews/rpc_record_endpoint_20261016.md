# RPC-C1：自动路由、预留拒绝响应与端点生命周期

## 基线与有限交付

基于 #265 的 `52c55de06c3abb29800aca41f4b10801949eea19`，
原树为 `b16de22176ace99604768e1bc3c02df063fbb35a`。
新增库内 `rpc_record_endpoint.h/.c`、真实 TCP 集成测试及 Xmake 登记。
复用原方法路由、工作派发、记录状态机、共享执行器和恢复租约，不新建线程池。
尚未替换旧 `tr_rpc_endpoint` 或公开 Client/Server 默认路径，不宣称网络压缩可用。

## 责任边界

端点显式独占一个空闲 Channel 的上层 handler；创建者必须拥有替换权，
在 create/start 之间不发布其他 handler 或打开流。此处遵循现有 Channel
设置契约，不假称增加了 handler 所有权注册表。生命周期观察者不被替换。
Channel、Reactor、共享执行器及业务参数都是借用，必须晚于端点清理。

端点接纳 OPENED、转发记录及流事件、释放原 RX，并自行推进业务任务与回复。
工作函数不直接操作流；所用请求/回复和每调用顺序仍由已有派发器管理。
不再需要集成方逐流创建路由或编写手工 pump 定时器。

为了不夺取共享执行器已有的 notify 钩子，本阶段使用端点持有的有界周期定时器
交付执行器完成并轮转推进调用，同时响应 WRITABLE。回调数和调用访问数各有上限，
不能声称单个业务完成回调的 CPU 时间受强制限制。周期为显式 1 ms..1 s 配置；
这不是零延迟完成订阅，空闲唤醒、多个端点公平性及性能要独立测量。
后续应由 Reactor/Runtime 共享完成驱动器提供订阅，不在本任务冒险覆盖他人通知。

## 自动拒绝与最终状态

本地未知方法、解析/准入错误和取消在工作完成责任收敛后，自动尝试发送非 OK
FINAL_STATUS。不会让已终局的 RPC 状态机复活；这条路径只负责一次错误记录，
不允许绕过状态机生成成功、业务体或初始元数据。正常业务 FINAL 已由派发器
接受时不重复发送。

每个 Channel 传输槽预先分配一个固定头及控制块，整个预留池先计费再分配。
因此业务预算耗尽不要求再次分配拒绝记录。池有独立引用，正在发送的头不引用
端点本体；端点销毁后仍被 TX 使用的存储继续存活并计费，最后释放才归还预算。
槽位对应的 busy 位在实际 TX 释放后才清除，旧记录未释放时不得改写复用。

FINAL 返回 AGAIN 时保留同一终局重试；到显式 final_timeout_ns 后只放弃精确
错误记录、尝试 STREAM_CLOSE，并在结果中保留未接受及发送错误，不假报成功。
CLOSE 的容量背压仍须等恢复，不能因期限到期就释放未完成责任。
FINAL 先被接受，然后提交 CLOSE；现有 Reactor 只允许 WINDOW_UPDATE/PING/PONG
越过 DATA，CLOSE 保持顺序。该规则以当前源码为依据，不把它泛化为所有传输后端。
此处是发送半关闭，不是新实现了 RESET 协议。

用户终局通知等到业务退出、错误记录已接受或明确放弃、关闭已接受或精确流
失效后执行一次。final_accepted/close_accepted 是本地接受，不是写出或对端确认。
同连接其他调用不因单条坏消息而关闭整连接。

## 槽位、停止与回收

路由退役后保留精确流代次墓碑，晚到数据只释放，不重新开始业务；新一代
物理槽位可以复用，预留 TX 存储另受 busy/引用保护。
Channel 的物理连接失效时该端点关闭新流准入并取消余下工作；此端点绑定一个
连接轮次，不允许其存活期间替换连接，防止覆盖尚未静默的旧路由。

正常关闭建立 Channel 排空准入屏障，取消业务并继续完成交付/终局发送。
未静默返回 AGAIN。工作/终局回调中不得递归关闭。源解绑失败保留对象，
依次解除 handler 和定时器后才能销毁派发器和端点。共享执行器不被擅自停止。

父 Reactor 已 join 时，reap 先用既有恢复租约确认静默、解除端点源，
再让派发器进入清理域。共享执行器必须由外层统一 stop/join/adopt_cleanup/
dispatch，之后重试 reap。停止域只通知 OWNER_STOPPED/CANCELLED，不发送成功
记录。全程禁止父循环重启/销毁及并发调用，不再增加第二套接管机制。

## 新增验证场景

测试目标使用实际 trcore、TCP、Channel、记录客户端、共享任务执行器。
服务端测试不再安装手写 data/event 回调，也不手动驱动业务 pump。

- 正常 4096 字节请求/回复及最终状态；客户端观察最终记录后收到半关闭。
- 未知方法、错 codec、方法绑定预算耗尽，客户端收到相应非 OK 最终状态。
- FINAL 与 CLOSE 分别连续背压十次，结果只交付一次；持续 FINAL 背压
  到期不假报 final_accepted，而是半关闭使客户端失败。
- 两个端点控制分配失败点、定时器注册/arm、handler 发布失败，及注销
  失败重试，不遗失部分对象和共享执行器。
- 业务故意忽略取消产生迟到输出；原任务未退出时关闭返回 AGAIN，最终
  仅交付取消。父线程停止后复用原清理授权，终局标记正确。
- 测试发送端接管预留头后延迟释放，端点/执行器已经销毁仍可安全归还；
  这是 TX 存储寿命测试，不是对端收包验证。

链接包装只存在于新测试，合法路径使用真实函数。测试断言和执行结果以
本 PR 的实际日志为准，不能沿用 #265 的绿色结果。
