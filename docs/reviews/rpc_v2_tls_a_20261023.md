## 已运行的实验

`tests/test_tls_bio_probe.c` 在内存中生成 Ed25519 测试 CA 和含
`DNS:localhost` SAN 的服务证书；测试目标只链接系统 `libssl`、
`libcrypto`，不把测试密钥写入文件或编进生产库。两端使用非阻塞
`AF_UNIX` socketpair，TLS 最低与最高版本均固定为 1.3。

同一组场景分别以 socket BIO 和 memory BIO 执行：

1. 正确 CA 与 `localhost` 完成握手；错误 CA 与错误主机名被拒绝。
   客户端显式关闭 early data，并独立设置 SNI 与预期验证主机名。
2. 两个方向各发送 128 KiB 确定字节，在缩小的 socket 发送缓冲中完成接收和
   内容核对；socket BIO 确实经历 `SSL_write_ex` 的 WANT 重试。
   memory BIO 搬运每次最多发送 257 字节、接收 193 字节，以形成
   密文分片；其测试驱动显式维护 16 KiB 待发送密文缓冲。
3. 双方 `SSL_shutdown` 后正常结束；未发送 `close_notify` 的写半关闭
   被 `SSL_read_ex` 识别为 TLS 错误。直接关闭 fd 会在仍有未读票据
   时产生 `ECONNRESET`，因此不能把传输错误当作正常关闭。
4. memory BIO 的双向传输中记录写 BIO 与测试驱动队列峰值，
   并确认发送方向遇到 EAGAIN 后仍继续前进。

运行命令：

```sh
TMPDIR="$PWD/build/test-tmp" XMAKE_TMPDIR="$PWD/build/test-tmp" \
  PYTHONDONTWRITEBYTECODE=1 xmake test -v -j1 'test_tls_bio_probe/*'
```

最新结果：1/1 通过（GCC release）。memory BIO 双向传输测得两端
写 BIO 峰值均为 114,864 字节、外部密文队列峰值均为 16,384 字节，
每个方向发生 121 次 EAGAIN。socket BIO 的双向 128 KiB 传输断言
至少一次 `SSL_write_ex` WANT 重试，并在相同调用缓冲上继续成功。

## BIO 选择的当前证据

socket BIO 可以在此非阻塞场景下保持 `SSL_write_ex` 原输入地址和
长度稳定，
通过 WANT 重试完成传输，无需由原型管理密文输出队列。
memory BIO 还需要从 OpenSSL 写 BIO 拷贝到待发送缓冲、从 socket
接收到读 BIO，并负责队列背压及 EOF 传递。OpenSSL 内部 BIO 缓存
仍需另行设上限或计量；测试中的 16 KiB 缓冲不是产品资源上限。

因此 ADR-009 中的 socket BIO 暂作为原型支持的后端选择。该实验尚未测量
OpenSSL 内部分配或 CPU 上界，也未验证真实 Reactor 的 epoll
跨方向 WANT、连接代次及资源回收。TLS-B/C/D/E 尚未完成；#234 保持开放。

## 内部字节端点合同

`src/io/byte_endpoint.c` 已编入 `trcore`，但当前 Reactor 仍走原有
`recv`/`sendmsg` 路径。端点以单所有者驱动接口隔离握手、读、写、
关闭与释放；没有后端时 `TLS_REQUIRED` 初始化返回
`TR_ERR_UNSUPPORTED`。明文端点真实调用非阻塞 socket I/O。

`tests/test_byte_endpoint.c` 覆盖 handshake 的 READ→WRITE→成功、
WANT 事件方向并集、写 WANT 后保持同一地址/长度、读缓冲稳定、
绝对握手期限、空 WANT 失败关闭、握手取消、收到对端 close_notify
后允许排空 TX、有界 close_notify 回送、事件解绑前拒绝释放和 driver
只释放一次。该文件使用可控驱动替身，不能证明生产 TLS 后端或真实
Reactor 集成。
