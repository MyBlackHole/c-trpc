# RPC-B1：V2 记录的真实 Stream 绑定与有界接收

## 基线与有限交付

基于 #262 `a2e1990c2a5360769f2de53b6050c84386a198db`，
树 `00e885656e98aeb586d7156f24e15d2b42e9bd73`。关联 #240、#235、
#241、#247、#248、#239。新增 rpc_record_stream.h/.c、真实 TCP 集成测试、
Xmake 增量和本记录。复用候选 V2 的 rpc_record 状态内核，不重新维护一套基数状态机。

**本轮完成记录到真实 Channel/Stream 的绑定，不是旧 tr_rpc_endpoint/V1 默认
入口已迁移。**绑定使用调用方从本地方法表选择的描述，验证 OPEN 与该描述一致；
尚不负责方法注册表查找、认证、业务执行器派发或公开 SDK 接口。

## 借鉴与接入边界

[gRPC 的 HTTP/2 协议](https://github.com/grpc/grpc/blob/master/doc/PROTOCOL-HTTP2.md)
将调用控制信息、消息序列和最终状态分开；底层 DATA 边界不是应用消息边界。
本绑定吸收这一职责划分，不采用 HTTP/2 字段，也不宣称与 gRPC 互通。

外层按 Stream 槽位和代次路由数据及事件，不替换共享 Channel handler。
绑定仅借用 Channel 和预算，不拥有它们；不创建线程、事件源或第二条消息队列。
完成回调只用于短小的准入/调度动作，不在 Reactor 中运行阻塞业务。

## 发送：下游接受后才提交状态

发送先在状态副本预检，再校验本地方向、方法、codec、业务体长度和控制元数据。
固定头与元数据复制进独立、预算化 TX 前缀；业务体直接使用原 tr_buffer，交给
真实 tr_stream_sendv。只有 TR_OK 才提交状态并清空调用方的拥有型指针。

TR_AGAIN、分配失败或其他发送拒绝会释放新前缀，不消费原业务体，也不推进调用。
零长度 MESSAGE 仍发送固定头、计一条语义消息；提供的零长缓冲在接受后释放。
发送前保存空消息标记，接受后不再读取已经交给下层的非空 payload 字段。

TX 前缀不引用绑定对象，能够比调用绑定活得更久；预算必须持续到真正释放。
这条路径有控制前缀分配/复制成本，不宣称完全无分配。已有 Channel 整消息窗口
准入没有重设计，本轮证明拒绝不错误提交及信用归还后可重试，不证明任意 L>W
消息都能持续前进，也没有新增隐式缓存队列掩盖 TR_AGAIN。

## 接收：有界增量缓存与借用视图

完整连续记录直接借用输入，不新增载荷复制。固定头跨输入时最多保留48字节；
完整头到齐后先检查记录形状、方法、codec、状态和声明长度，再为不完整记录
预约一份精确长度缓存。元数据/正文可以跨多条有序 Stream 消息，单段输入也能
包含多条 V2 记录。已有 Channel 对 TRP 物理分片的重组仍保持原行为。

接收缓存使用非零硬预算；预算或分配失败选择 RESOURCE_EXHAUSTED 并释放缓存，
不返回会使调用方误重放已吸收字节的 AGAIN。协议错误选择当前绑定终局，不自动
关闭同连接的其他流。原 RX 缓冲和网络信用仍由外层 Channel 回调责任释放。
此限额不覆盖之前已经产生的 Channel 重组存储、线程栈或整个 RSS。

自定义元数据使用 u8 key_len/u16 little-endian value_len 的 TLV。总长最多512，
键长1..63，仅允许小写 ASCII、数字、下划线、点和连字符，拒绝重复及冒号保留键。
检查不使用 strlen 读取对端数据。OPEN 方法编号与 codec 匹配不是身份授权。

绑定目前只允许 NONE，压缩记录明确拒绝，不静默降级，不在 owner 中同步解压。
接入异步解码前还需要每调用顺序、解码实际长度验证、取消代次与资源总账。

## 终局、回调和停止回收

沿用候选 V2 的 ONE/MANY、半关闭、最终状态规则。记录验证成功才提交状态和
同步交付借用视图；递归接收和回调内销毁拒绝。终局通知延后到当前 received
退出，至多一次，之后不再交付业务记录；终局回调可释放用户 arg。
发送 FINAL 被接受只代表本地结果选择，不表示已写出或远端执行成功。

残缺头或正文上的 EOF 是 DATA_LOSS；未收到最终状态的关闭不能当作成功。
本地取消释放部分记录缓存；晚到字节不复活调用。不自动发送 RESET/关闭 Stream，
外层错误作用域和流终止动作仍需后续入口迁移落实。

销毁前必须移除外层路由并排除并发使用。正常 owner 上拒绝销毁活跃非终局对象；
停止回收复用已有 Reactor recovery_guard，先证明父线程已 join，再在停止清理域
以 OWNER_STOPPED/CANCELLED 终结未完成调用，不冒充原 owner、不访问失效 Stream。
本轮测试覆盖有序停止后的租约回收，不新增父循环 epoll 致命故障注入场景。

## 新增真实 TCP 集成测试

`test_rpc_record_stream` 使用真实本机 TCP、两台 Reactor、Channel 和 Stream。
测试目标链接 trcore；这是刻意的组合验证，不替代已有记录/消息核心隔离测试。
只在该测试包装 malloc 与 tr_stream_sendv；正常路径调用真实接口。

- 四种 ONE/MANY 组合、零消息 MANY 和零长度 MESSAGE；65537字节双向业务体在
  最大256字节 TRP 载荷下分片重组，独立校验长度与内容，验证原 TX 缓冲身份和
  连续接收视图借用。
- 真实128字节窗口先占112字节，48字节 HALF_CLOSE 不能准入；真实状态不半关闭，
  归还接收信用后重试成功。另有 OPEN/MESSAGE 拒绝、前缀分配失败的所有权测试。
- OPEN/TLV 每次一个字节输入、多个记录串接、错误方法/codec、保留键/重复键、
  完整头阶段超限、未知方向压缩、接收分配和预算失败。
- 同连接坏记录使第二个调用失败，第一个有效调用仍能返回最终成功；不将这一
  场景扩大为完整网络 RESET 或抵抗任意恶意流的证明。
- 残缺记录取消后缓存释放、重复取消与晚到输入、错误 owner/旧流代次、EOF截断。
- 父循环运行时拒绝 stopped reap；移除路由、父线程停止后只在清理域通知一次，
  所有前缀和缓存释放后预算归零。

## 本地实际验证与来源范围

本机没有 Xmake，直接使用实际生产 C 源编译局部链接目标，不称为正式 Xmake 验收。
基底取自先前提供的 #260 固定归档并核对286个 Git blob。测试涉及的 Reactor、
Channel、缓冲、I/O 及队列源码在后续基线上未变化；rpc_record.h/.c 使用本次读取
的 #262 原文，分别校验 blob 39ed507be670d7d372d8f3715b9c667b97115639 和
 e11f969a3233b9a6dc4fb31919cdca90c3ffb761。修改前 Xmake 精确复原并匹配
c4a72563a74dd8a02ca79c0c11b98ba123ef5dc8。

本地并未完整重建 #261/#262 全树；链接映射确认新测试实际未链接有版本差异的
runtime.c 或旧 rpc.c。所用是真实 Reactor/Channel，不是事件循环替身。
全库身份、完整测试和安装消费端必须由本轮精确提交的远端 Xmake 重新验证。
