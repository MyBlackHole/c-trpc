# TLS-E 外部 TLS 客户端互通阶段证据

- 日期：2026-10-27
- 需求：[#234 TLS 1.3 非阻塞传输、证书身份认证与连接生命周期](https://github.com/MyBlackHole/c-trpc/issues/234)
- 代码基线：`feat/v2-tls-d2-234`，父提交 `30c48e6833b57c41d38ee78d300158063cbb806a`
- 候选版本：`2.0.0-dev.23`

## 范围

新增 `test_tls_gnutls_interop`，使用独立的 `gnutls-cli` 进程连接公开 V2 TLS-required
Server。Server 要求 TLS 1.3、客户端证书及受信任 CA。客户端明确只协商 TLS 1.3，并独立验证
服务端 DNS SAN 和 SNI。回归覆盖：

- 受信任服务端证书、正确 DNS 名和受信任客户端证书：握手成功。
- 不发送客户端证书：Server 拒绝连接。
- 提供错误服务端 DNS 名：GnuTLS 客户端在证书验证阶段拒绝连接。

测试通过 `posix_spawnp()` 直接执行固定程序和参数，不经过 shell；子进程使用 `/dev/null`
作为标准输入/输出，父进程对其退出等待设 12 秒上限。测试身份由现有 helper 写入可执行文件
所在 worktree 的 `build/test-tmp/`，不在 `/tmp` 生成文件。CI 的 GCC Release、Clang Release、
ASan/UBSan、TSan 测试作业和会调用完整测试集的 Make 兼容作业安装 Ubuntu 22.04 的
`gnutls-bin`。

## 本地验证

本机工具：GCC Release、OpenSSL 3.6.5、GnuTLS CLI 3.8.13。

| 配置 | 结果 | 用时 |
| --- | ---: | ---: |
| GCC Release | 1/1 通过 | 0.397 秒 |
| GCC ASan/UBSan（`detect_leaks=1`） | 1/1 通过 | 0.482 秒 |
| GCC TSan | 1/1 通过 | 0.470 秒 |
| GCC Release 全量测试（含本目标） | 91/91 通过 | 85.864 秒 |
| Make 兼容入口（GCC Release 全量） | 91/91 通过 | 85.818 秒 |

命令均将 `TMPDIR` 与 `XMAKE_TMPDIR` 指向当前 worktree 的 `build/`：

```sh
TMPDIR="$PWD/build/tmp" XMAKE_TMPDIR="$PWD/build/xmake-tmp" \
  xmake f -c -y -m release --toolchain=gcc
TMPDIR="$PWD/build/tmp" XMAKE_TMPDIR="$PWD/build/xmake-tmp" \
  xmake test -v -j1 'test_tls_gnutls_interop/*'
```

全量测试使用相同的 GCC Release 配置运行 `xmake test -v -j1`，结果为 91/91 通过；Make 兼容入口
`make test CC=gcc` 也运行完整套件并以 91/91 通过。

ASan/UBSan 与 TSan 使用同一测试目标，分别将构建模式改为 `asan`、`tsan` 并设置
`ASAN_OPTIONS=detect_leaks=1:halt_on_error=1`、
`UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1`、
`TSAN_OPTIONS=halt_on_error=1:second_deadlock_stack=1`。

## 限制与剩余工作

该测试只证明 GnuTLS 客户端与 c-trpc Server 的 TLS 握手、mTLS 与服务器身份验证互通；它不发送
TRP/RPC 应用数据，也没有验证 c-trpc Client 对接外部 GnuTLS Server。当前本地 GnuTLS 版本为
3.8.13；Ubuntu 22.04 CI 的 GnuTLS 3.7.x 实测须以新候选的 Actions 结果为准。

本记录不证明 OpenSSL/内核分配的全量资源硬上界，不覆盖并发握手/取消洪峰、长时间负载、目标
平台互通或公网发布门槛。TLS-E 与 #234 仍开放；TLS-D2 原 PR 的既有 CI 结果不能代替新候选的
CI，也不能据此宣称 TLS-E 或 V2 完成。
