## 本次范围

`test_tls_gnutls_interop` 现在覆盖两个方向：

- 独立 `gnutls-cli` 进程连接公开 V2 TLS-required Server。限定 TLS 1.3，Server 强制 mTLS；验证可信身份成功、缺少客户端证书和错误服务端 DNS 名被拒绝。此方向只完成 TLS 握手，不发送 TRP/RPC 帧。
- c-trpc V2 Client 连接由 GnuTLS TLS API 驱动的本地 TLS terminator。Server 限定 TLS 1.3，要求客户端证书并由 GnuTLS 验证证书链；握手后将解密出的 TCP 字节透明转发到本地明文 c-trpc V2 Server。Client 执行 RAW unary，发送 4 字节正文；Server 回显原正文，Client 验证单条回复正文完全一致且终局为 OK。此用例证明真实 RPC 正文通过外部 GnuTLS TLS 实现往返，不再止于 HELLO/ACK。
- 该 GnuTLS 端点只终止 TLS 并透明代理到本地 c-trpc RPC Server，不实现 TRP/RPC 服务端协议。因此它不证明独立 GnuTLS RPC 实现与 c-trpc 的协议互通，也不替代独立业务进程/公网网络矩阵。
- c-trpc Client 的错误服务器名与无客户端证书用例均不能完成 TLS 握手，`tr_client_connect()` 及时返回 `TR_ERR_CLOSED`。GnuTLS Server 对无证书路径报告 `GNUTLS_E_CERTIFICATE_REQUIRED`。
- `test_rpc_v2_tls_reactor` 对 TLS-required Server 保留 16 个仅发送不完整 TLS record 的慢握手 peer，再快速突发打开 48 个超额 TCP 连接。peer 数达到配置上限 16 后，48 个超额连接全部关闭；1.5 秒握手期限后原有 16 个慢握手 peer 全部回收，随后使用有效服务端身份的 V2 Client 成功完成 TLS 就绪。该用例验证有限规模的接入突发、peer 拒绝计数与超时恢复，不等同持续大规模握手负载、取消或所有权/内核内存完整总账。
- dev.31 增加 `test_tls_pending_handshakes_close_on_server_destroy`：4 个 peer 只发送不完整 TLS record 后，外部线程销毁 Server。测试要求 `tr_server_destroy()` 收敛为 `TR_OK`，所有客户端 socket 在 5 秒握手期限的一半以内关闭；这样不依赖握手超时完成 teardown。该场景验证 Server 主动销毁时的 peer 生命周期，不覆盖 provider 凭证取消、持续大规模握手负载或完整资源总账。
- dev.32 在所有 OpenSSL profile 共用的 `SSL_CTX` 构造路径显式设置对端证书链上限为 100 KiB。该值与 OpenSSL 3 默认上限一致，固定产品策略，避免依赖加密库隐式默认值；OpenSSL 文档说明此限制用于约束握手中动态增长的对端证书链缓冲（[SSL_CTX_set_max_cert_list](https://docs.openssl.org/3.6/man3/SSL_CTX_set_max_cert_list/)）。它不代表 OpenSSL 堆、证书解析临时分配或内核 socket 缓冲的总量硬上限。
- `test_tls_openssl` 检查 Client/Server profile 均向 OpenSSL 写入 100 KiB 策略，并用超过该上限的可信、主机名匹配服务端证书执行真实 TLS 握手；客户端必须以 `SSL_R_EXCESSIVE_MESSAGE_SIZE` 拒绝，且不得进入已认证态。测试证书和 CA 私钥只落在工作区 `build/test-tmp/`，测试结束后清理。

新增回归同时修复一个等待终态错误：TLS 失败关闭 Reactor 连接并唤醒 Channel 等待者后，若没有重连任务，`tr_channel_wait_ready_deadline()` 现在返回 `TR_ERR_CLOSED`，不再把已关闭连接继续等到原始 deadline 并误报 `TR_ERR_TIMEOUT`。启用重连时仍允许等待下一次就绪。

身份文件沿用现有 helper，写入 worktree 的 `build/test-tmp/`。用例不通过 shell 启动子命令；独立 `gnutls-cli` 使用 `posix_spawnp()` 固定参数。反向 Server 使用 GnuTLS API 和独立线程。新增构建依赖为系统 `libgnutls28-dev`；CI 同时安装 `gnutls-bin` 与该开发包。测试身份文件、缓存与构建产物均留在工作区 `build/`，未写入 `/tmp`。

## 尚未覆盖

本次不证明 OpenSSL 堆、证书解析峰值和内核 socket 缓冲的完整硬预算；64 连接回归不覆盖更大规模持续握手洪峰、握手取消/迟到回调、长期负载、性能回归、目标平台矩阵或公网发布安全门槛。应用级 RPC 正文通过 GnuTLS TLS 端点转发到本地 c-trpc Server；尚未覆盖独立外部 RPC 服务端实现、跨进程业务负载及目标网络性能。

因此 TLS-E 与 #234 仍未完成，PR #312 保持未合并；dev.32 只固定并验证入站证书链上限，不构成完整资源总账。OpenSSL 证书解析峰值与其余动态分配、内核 socket 缓冲、持续洪峰与 provider 取消、长期稳定性、性能、目标平台及独立 RPC 服务端互通仍未验收。本记录不代表 TLS-E、#234 或 V2 整体验收完成。
