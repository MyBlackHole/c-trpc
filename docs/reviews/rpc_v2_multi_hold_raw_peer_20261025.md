# 公开 Server 多消息持有期间 RAW 同伴进展回归

日期：2026-10-25。版本：`2.0.0-dev.81 -> 2.0.0-dev.82`。关联 #241、#235。

## 验收目标

扩展公开连接组 Server 的真实慢消费者场景：多条真实 Zstandard 解码正文同时由应用持有期间，另一条物理 DATA 成员上的 RAW 消息仍可交付。该用例补充单条持有和监听器组件预算满额的证据，重点验证多个公开应用持有者。

## 场景与断言

- 使用真实 TCP 建立普通公开 `tr_server`/`tr_client` 连接组和两条 DATA 连接。现有链接期路由探针继续确认压缩消息与 RAW 同伴消息落在不同物理连接。
- Server 最大解码正文为 1 MiB、编码正文上限为 4096 字节，压缩任务容量为 6。
- 客户端向同一个已就绪 transfer 依次发送六条有效 Zstandard 消息：五条解码为 1 MiB，最后一条解码为 64 KiB。服务端回调逐条返回 `TAKE_OWNERSHIP`，同时保存每个公开消息描述符和预期字节模式。
- 六条应用持有正文合计 5,308,416 字节（5.0625 MiB）。全部持有期间，第二 DATA 成员发送一字节 RAW 消息；测试确认其回调完成，并在 RAW 回调后再次逐条检查六个已持有缓冲完整。
- 释放六个公开消息，再释放两个 transfer 并排空连接组；正常销毁 Client/Server。

## 发现与验证

初始尝试把 Server 压缩任务容量设为 1，并在第一条 1 MiB 输出仍被持有时再提交第二条压缩消息；第二条未到达应用回调。将该组件测试的压缩任务容量设置为 6 后，六条正文均成功解码并同时保留。该调整只影响测试夹具配置，不改生产逻辑。

GCC Release 完整 `test_connection_group_facade` 连续 5/5 通过；ASan/UBSan（`detect_leaks=1`）、TSan 均通过；完整 Release 测试 91/91 通过，耗时 140.925 秒。

格式复核使用系统提供的 clang-format 23.1.3 对两个测试文件的修改行进行 `git clang-format --diff` 检查，结果均无待格式化改动。项目工具政策固定要求 clang-format 18.1.8；包站不可达，未能安装固定版本，因此该精确版本检查未执行。

## 结论边界

正文来自公开 Server 的实际压缩解码输出，直接通过公开连接组消息所有权 API 持有，没有测试预算预约或伪造分配。测试没有读取 Server 的私有预算账本，因此不声称全局预算精确达到上限，也没有验证持续 RAW 饱和流量的公平性。普通 Server 全局预算精确自然耗尽、持续饱和公平性及更广 RAW/Zstandard/多组组合仍待验收。本次仅修改测试、文档与版本号，无生产 API/ABI、wire 或运行时行为改动。
