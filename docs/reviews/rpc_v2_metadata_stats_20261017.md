# V2 响应元数据与调用语义统计

## 阶段结论与基线

本阶段接续[公共 V2 业务 SDK](public_rpc_v2_sdk_20261017.md)，基线为草稿
PR #275 的 `b4167805ca9476a5aef9413524ee1681335a02d6`，tree 为
`aeef58d6f7c63a38aa28a9d8ef42138003ba22ac`。在既有业务 SDK 上补齐两项能力：
Server 工作回调内设置响应 INITIAL/TRAILING 元数据，以及两端读取稳定的
RPC 生命周期统计。完整使用合同见[公共 V2 SDK](../rpc-v2-sdk.md)与
[可观测性](../observability.md)。

本阶段沿用回调内有界回复、同调用事件 FIFO、网络背压重试、合作取消和分层排空。

安装公共头仍为 9 个，生产 C 编译单元仍为 43 个，Xmake 注册测试仍为 84 项。

## 响应元数据合同

新增 `tr_rpc_v2_reply_set_metadata(reply, phase, entries, count)`。回复能力只能
在当前 work 回调中使用；公共入口先验证当前线程的活动能力，再访问内部批次。
成功返回前复制输入数组中的键和值，业务随后可以立即覆写或释放全部源存储。

| 边界 | 合同 |
| --- | --- |
| 输入 | 复用 `tr_rpc_metadata`；键为 NUL 终止字符串，值是精确长度的二进制字节 |
| 键 | 1～63 字节，只允许小写 ASCII `[a-z0-9_.-]`；同一阶段不可重复 |
| 大小 | 每阶段编码后最多 512 字节，每项另含 3 字节长度字段；最多 128 项 |
| 空列表 | 仍消耗该批该阶段的一次设置；空 INITIAL 也真实交付一次初始事件 |
| INITIAL | 尚未发送初始元数据时可设置，始终先于本批正文发送 |
| TRAILING | 只属于同批终局，须在 finish 前设置；HALF_CLOSE 默认完成和业务错误也可携带 |
| 资源 | 每批最多两个按编码大小分配的元数据副本，计入共享预算；空列表不分配 |

阶段状态在任务实际提交时从 owner 拷贝到工作批次，避免下一事件排队后，前一
批才完成 INITIAL 发送而使工作线程使用陈旧状态。网络背压保留原副本和发送位置，
不重新执行 work。传输接受元数据记录并复制前缀后，工作批次立即释放相应副本。

正文追加或元数据设置失败会锁存整批错误，丢弃该批全部正文和元数据。
既有非 OK 状态不被后续错误或业务返回值覆盖。元数据设置的非法参数、键或
编码长度对应 INVALID_ARGUMENT；阶段顺序或重复设置对应 FAILED_PRECONDITION。
正文追加超过消息或批次额度、任一接口资源不足，对应 RESOURCE_EXHAUSTED。
NULL 或回调外无效能力不触及批次。

显式 `reply_finish(non_OK)` 或 work 返回合法非 OK 状态可以保留有效元数据，
只丢弃本批正文。普通非终局批次设置 TRAILING 后返回 OK，则锁存阶段错误。
finish 后不能再追加或设置。前批已经被传输接受的记录无法撤销，Client 仍以
最终状态判断调用结果。取消、期限和停机先取得终局时，可丢弃尚未交付的工作
结果；setter 成功仅表示复制受理，不证明元数据会被发送或收到。

## 语义计数与读取

`tr_client_get_rpc_semantic_stats()` 与 `tr_server_get_rpc_semantic_stats()`
现在支持 V2，复用 `tr_rpc_semantic_stats` 的 started、finished、inflight 和
17 个最终状态桶。统计不暴露 Reactor、工作线程、传输槽、队列或资源池布局。

| 端点 | calls_started | calls_finished |
| --- | --- | --- |
| Client | 调用已经受理并发布能力；即使 OPEN 尚受背压阻挡，也承担一次终局责任 | 唯一 terminal 回调之前，回调内可见包含自己的终局快照 |
| Server | 完整合法 OPEN 匹配方法并通过期限准入，早于工作对象分配或执行器拒绝 | 已提交工作真正返回并完成交付之后，唯一业务 terminal 提交之前 |

未知方法、无效或未完成 OPEN、未通过期限准入的 OPEN 不计入 Server 开始数。
没有安装业务 terminal 函数时，Server 在相同提交点记账。Client 的回调可早于
外部 start 返回；Server 网络 RESET 已被接受也不意味着工作已返回。因此两端
总数与状态分布可以不同，Client 的 finished 不能证明 Server 的 inflight 已归零。
结束计数也不证明 terminal 已返回、TX 已释放或远端收到结果；完整静默继续使用
既有排空与生命周期屏障。

Client 在自己的 owner 上累计。Server 的每个分片持有一份累计对象，同 owner
的各 peer 在启动前绑定并借用它。分片寿命长于全部 peer 和残留工作，回收 peer
不转移、不清空、不重复归档计数。运行中只由 owner 记账；停止后，仅在父线程
join 且公共统计入口关闭之后由串行清理域接管。热路径没有新增全局原子、锁、
计时读取或每调用分配。

普通线程及 Client 自身 LIVE 回调可以读取 Client 快照；其他 owner、工作线程
与 SHUTDOWN 回调返回 STATE。Server 全分片聚合只允许外部控制线程，所有
c-trpc 回调和工作线程都返回 STATE，不随分片数变化。Server 拒绝路径先检查
TLS 执行域，再访问可变生命周期字段，避免销毁等待工作退出期间的数据竞争。
首次 destroy 开始后拒绝继续读取，包括仍在 LIVE 域交付的终局；失败保持 out
原文。成功构造但尚未连接或启动的对象返回零快照，外部生命周期操作仍须串行化。

每个成功快照保持 `started - finished == inflight`，所有状态桶之和等于
finished。计数使用检查加法；本地累计溢出永久标记，跨分片求和溢出也使本次
读取返回 BAD_LENGTH，均不写部分输出或回绕，不影响 RPC 本身的准入和终局。
跨分片读取不是全局同一时刻的快照，但成功输出保持这些语义关系。

## 回归范围

在既有测试目标中扩充有意义的边界，没有增加全量测试目标数量：

- 派发器验证两阶段各 512 字节、二进制和空列表、源字节覆写、重复键、阶段
  错误、分配和预算失败、首错锁存、错误 FINAL 保留合法元数据、背压后的初始
  阶段关闭，以及取消和停止后预算归还。
- Client 的 11 组回归覆盖受理后 OPEN 背压、start 返回前的提前终局、跨 owner
  拒绝、销毁期间读取和 `UINT64_MAX` 读出及合并边界。
- 公共 Server 回归覆盖 12 次调用，精确验证业务错误、整批丢弃、阶段关闭、
  OPEN 工作分配失败、阻塞取消和 SHUTDOWN；单目标不是 12 个 Xmake 测试。
- 公共 SDK consumer 验证四种 ONE/MANY 形态、复制和事件顺序、未知方法拒绝、
  cancel/deadline/drain、终局回调内读取以及跨 peer 的累计保留。
- 两分片配置的多 peer 回归证明总累计保留，不据此宣称实际连接均匀分布在两个
  分片。原 Server 回收用例另在真实 peer 退役后逐轮核对精确累计值。
- 端点隔离夹具验证统计对象的原指针透传、启动屏障、下层错误传播和累计值
  借用寿命；替身不实现真实统计记账。

安装消费端继续只包含 `<tr/trpc.h>` 与 libc/POSIX，以同一源文件同时验证
C11/C++11。原四个场景标记保留，新增 `stats-peer-retirement`，每次运行共五项。

### 保留的首轮结果

开发首轮公共 SDK 五场景全部通过，Server 定向用例在 NO_JOB 的尾部事件数
断言失败。精确诊断确认该场景无待清理 worker，端点在正常连接上发送空错误

测试将此场景期望修正为精确一次，阻塞取消仍为零，状态和统计断言保持不变。

## 后续边界

下一项公共业务能力是回调外异步生产者，需要独立确定持有/释放、背压等待、
取消竞态及销毁屏障。NONE 基数、自动重连、连接组、网络压缩和 TLS 仍未提供。
已有 RPC smoke 只验证其既有对象，不作为 V2 吞吐或生产负载承诺。

本记录陈述本地验收；最终草稿 PR 正文补记远端 head、合并检出 tree、全部
14 个作业的结果及完整日志/制品核验。前序草稿与本阶段草稿继续等待评审。
