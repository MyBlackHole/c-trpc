# V2 DATA 类型标志的流级错误隔离

日期：2026-10-23；基线 `d134f027209ae1ab1899bb4a607834f622b7fe29`，
版本 `2.0.0-dev.7`；本次版本 `2.0.0-dev.8`。对应 #242。

## 现象与分类

TRP 线帧允许 `LANE_BULK` 标志，但 DATA 帧只允许 `FIRST` 与 `LAST`。
旧接收路径在查找 Stream 前拒绝多余标志，导致一个已打开流的类型标志
错误关闭整条连接，同连接正常流也一并失败。此时帧头校验、载荷长度、
精确物理连接和 Stream 身份均可验证，错误可以隔离到目标流。

接收路径现在先核对线帧载荷长度、流身份与已公布接收信用。对有效的
OPEN 流，非法 DATA 类型标志使用原有流级 RESET 与有界丢弃路径；
终局原因映射为协议已经支持的 `TR_ERR_STATE`，不更改线格式。
未知流、错误连接、已终止流、不可信长度与越过接收信用仍按连接错误
处理。RESET 过程中只吸收有效类型标志和冻结信用内的数据。

## 验证

真实同连接双流测试向流 1 注入带 `LANE_BULK` 的 DATA，同时保留
流 3。旧代码等待流 1 RESET 超时；源码中的旧错误路径会请求关闭连接。
修复后只看到流 1
的 `TR_ERR_STATE` RESET，流 3 继续交付消息，双方确认终止后流槽回收。
未知流携带非法类型标志，以及已打开流但未协商 RESET 的情况，
仍要求连接级终止，不能误降级为无终局的本地通知。

本次只解决一种可信边界内的 DATA 类型标志错误。#242 的连接组
排空/epoch、更多错误分类及组合故障矩阵仍需继续完成。
