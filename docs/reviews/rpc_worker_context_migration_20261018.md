## 实际问题及本次范围

基线中 `tr_rpc_v2_producer_wait_writable()` 为拒绝工作线程阻塞，调用
`tr_rpc_in_worker_context()`。该查询定义在旧的 `src/rpc/rpc.c`；静态链接因而
把旧 Endpoint、执行组及 `rpc_wire.c` / `rpc_codec.c` 一同带入 V2 网络测试。
链接映射和实际符号表可复现这条依赖，不是仅依据文件命名推断。

本轮将所有框架工作线程的身份查询下沉到执行层：

- 新增 `src/execution/worker_context.h/.c`。内部线程局部布尔量提供词法进入、
  保存及逆序恢复；不递增计数，不分配内存、不加锁、不创建工作线程。
- 通用任务执行器、旧 RPC 私有执行器和旧 RPC 共享执行组的真实线程入口共同
  进入该域，正常退出时恢复。删除两个旧的线程身份查询及其私有声明。
- Client、Server、Runtime、MessageService 和 V2 生产者使用同一个拒绝门禁。
  V2 生产者不再为了工作域查询包含旧 `rpc_internal.h`。
- 通用执行器的清理所有者接管拒绝旧 RPC 工作线程；旧 RPC 执行组的启动、
  停止及销毁同样拒绝通用工作线程。拒绝不应先修改被操作对象。

工作域只描述“当前是否在框架工作线程中”。它不授予 Reactor 所有者身份，
不延长对象寿命，不替代外部生命周期串行化、取消完成或回调静默屏障。
进入/恢复令牌仅在同一线程内成对使用，不能作为跨线程能力。

## 可执行的 V2 链接边界

修改现有 `test_rpc_record_endpoint_tcp`，只复用列明的 23 个实际生产对象；
不继承整个 `trcore` 链接参数，不链接旧 `rpc.c`、`rpc_wire.c`、`rpc_codec.c`
或 Zstandard。测试仍使用真实 TCP、Channel、Reactor、路由与执行器，不是网络替身。
既有故障注入包装和真实测试场景继续保留。

Xmake 配置新增链接后符号门禁，禁止旧 Endpoint、执行组、旧线协议及旧调用入口
进入该验证二进制。每个指定生产对象要求恰好匹配一次，禁止重复编译生产源。
本地直接链接及等价的 `nm` 检查已经实际执行；Xmake 钩子本身尚待原生构建验证。

这个测试的构建仍先依赖 `trcore` 生产对象，因此证明的是独立**链接边界**，
不是已经实现不构建整个库的完全独立模块构建。普通 SDK 门面仍会引用旧 RPC。

## 回归及反向证据

新增 `test_worker_context` 只链接一个真实执行层对象：8 个真实线程、2000 轮
屏障同步，让有标记与无标记线程同时检查状态；另验证嵌套进入/恢复及主线程隔离。

扩充既有 `test_rpc_executor_group_drain`，不用伪造线程身份代替实际执行器：
旧 RPC 业务回调不能接管通用执行器；通用任务不能启动、停止或销毁旧 RPC 执行组。
外部控制线程随后可以正常操作和释放对象，证明拒绝没有破坏其状态。
原有执行组排空及故障回收场景保留。既有任务测试增加工作回调和完成回调的执行域断言。

独立反向实验均保留原始结果，错误变体没有进入补丁：

1. 用基线生产对象进行同一独立网络链接，稳定因缺少
   `tr_rpc_in_worker_context` 失败；这是旧二进制依赖证据，不是运行时缺陷声明。
2. 基线完整链接网络程序含 22 个禁止的旧 RPC 定义；新独立链接程序含 0 个。
   数量是明确符号筛选集合的结果，不代表穷尽全部历史符号。
3. 分别在本地错误变体中去掉真实旧 RPC / 通用执行器的工作域登记。
   两个变体都编译、链接成功，然后被真实混合执行器测试的身份断言拒绝。
   不把编译失败算作运行时断言覆盖，也不宣称发现两个历史生产缺陷。

## 本地实际验收

下面各模式分别编译全部 45 个生产翻译单元，随后链接并执行同样六个定向测试。
它们是直接编译器调用，不是 Xmake 全量验收、安装消费验收或远端 CI。

| 本地编译/运行模式 | 生产编译 | 定向程序运行 |
| --- | --- | --- |
| GCC 14.2，O0 | 45/45 | 6/6 |
| GCC 14.2，O2 | 45/45 | 6/6 |
| Clang 17，O2 | 45/45 | 6/6 |
| Clang 17，ASan + UBSan，O1 | 45/45 | 6/6 |
| GCC 14.2，TSan，O1，非 PIE | 45/45 | 6/6 |

六个程序是 `test_rpc_record_endpoint_tcp`、`test_worker_context`、
`test_task_executor`、`test_rpc_v2_sdk`、`test_transport`、
`test_rpc_executor_group_drain`。五模式共 30 次定向测试通过；不能写成
85 个全库测试或此前基线的 420 次验证。测试断言保留；检查器程序均以成功退出，
原始输出未出现检查器诊断。完整命令、退出码、链接映射、输出和符号检查在随附证据包。

全库链接的本地定向程序使用系统预构建的 Zstandard 1.5.7 静态归档；不声称
该第三方对象经过本次检查器插桩，也不声称验证了 Xmake 固定包配方或安装归档合并。
V2 独立网络程序没有链接这个归档。

本地辅助脚本放在仓库之外，仅用于本次验证，不在项目中新增第二套生产构建系统。
本机没有 Xmake 和固定 clang-format 18.1.8；格式工具下载因网络不可达未完成。
`git diff --check` 已检查空白错误，但不能替代固定格式器门禁。

一次同时启动两套编译模式的外层工具命令到达时限，不能视为未结束模式通过；
后续完整重跑 Clang 模式并取得六个明确退出码。两套反向错误变体的断言失败是
预期的验证结果，独立保存，不计入上述正常测试通过数量。

## 静态分析台账与未完成验收

移动线程身份定义使旧 `rpc.c` 诊断语句的行号改变。本候选只按未修改语句映射
更新三个坐标：GCC `2698 -> 2692`；Clang `3539 -> 3533`、`3542 -> 3536`。
诊断消息、检查器、列、数量和 `unverified` 状态均未修改；不是删除、确认误报或豁免。
这些坐标必须由精确候选的 GCC 11 / Clang 14 原生静态分析重新核验。

仍须完成原生 Xmake 全目标、完整功能测试、固定格式、双静态分析、SDK 安装消费、
CRC 回退和精确提交的远端 CI。未因此移除草稿状态、合并 PR 或关闭架构问题。

## 后续真正的 V1 删除边界

本次没有更改公开头文件、默认工厂、协议或连接组能力。
`tr_client_create()` / `tr_server_create()` 的 V1 默认路径、旧 Endpoint、
旧 RPC 执行组和旧线协议仍存在。下一迁移切片必须盘点这些入口的调用者，
把普通门面与一元调用适配到同一 V2 状态机，然后删除不再引用的旧协议/执行器。
不能只保留接口包装而继续运行两套语义，也不能把传输/连接组通用能力一并误删。
TLS、网络压缩、类型化编解码器、跨架构及性能发布验收不属于本次交付。
