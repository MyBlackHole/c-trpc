# V2 回调外异步生产者审查记录

## 目标与实现范围

前序响应元数据及语义统计阶段继续作为本阶段基线。本阶段允许业务在 work
返回后持续生成回复，使用独立拥有的 `tr_rpc_v2_producer`，并保持请求 FIFO、
有限资源、唯一终局及可重试销毁的原有约束。

公共入口仍由安装后的 `tr/rpc_v2.h` 提供，不暴露路由器、Stream、执行器、
记录头或内部预算地址。已有的 work 内有限批次及其整批错误锁存规则保留。
接入代码和完整使用合同见 [`../rpc-v2-sdk.md`](../rpc-v2-sdk.md)。

新增接口包括取得句柄、retain/release、发送初始元数据、发送单条正文、
原子提交带尾部元数据的 finish、有限等待可写和查询关闭。没有新增业务通知
回调、线程、文件描述符或第二条传输队列。宿主已有的有限周期进度泵继续推进
命令、期限、取消及背压恢复，不承诺即时调度或硬实时。

## 所有权与交接

`reply_acquire_producer()` 只在当前公共 work 的空批次中成功，每调用最多一次。
当前事件尚未追加正文、设置任何元数据、finish 或锁存错误时才可取得。失败不
改变批次或输出参数，应用可处理资源错误或继续同步回复。

创建时预先取得应用和 job 各一个强引用，完成初始化后才将应用引用交出。
job 的可变回复只由 work 写入；owner 仅在执行器完成发布屏障后的 done 读取，
随后将库内引用移交调用槽。应用可以在 work 返回前把句柄发布给另一个线程，
但每个并发使用者必须预先取得自己的引用。

取得成功后，输出权单向切换到 producer。当前及后续 work 的同步回复写入口
返回 STATE，并锁存当前工作批次的 FAILED_PRECONDITION。释放 producer 不会
恢复同步模式。后续请求工作继续 FIFO，HALF_CLOSE 不再隐式选择成功终局。
异步发送背压不阻塞后续请求工作；业务负责这些工作与生产线程之间的同步。

| 状态或条件 | 合法参数的提交 | 普通线程等待可写 | owner 的责任 |
| --- | --- | --- | --- |
| STAGED、槽空 | 可复制一条记录 | 等待，0ms 为 TIMEOUT | 等待创建 work 返回和 done 交接 |
| ACTIVE、槽空 | 可复制一条记录 | OK，不预约容量或字节预算 | 公平推进输入工作与输出 |
| 正在复制、已占槽或发送尚未接受 | AGAIN，不保留本次输入 | 等待槽恢复或关闭 | 保留同一记录和正文重试 |
| finish 已受理、尚未关闭 | STATE | STATE | 发送已受理的 FINAL 并收敛终局 |
| 已关闭 | CLOSED | CLOSED | 解除库内引用，应用可继续查询、释放 |

STAGED 的外部等待不能用于让创建 work 等待生产线程退出。交接前取消仍通过
原 work 的借用令牌合作观察；暂存可以在已发生取消后复制成功，再在 done
中丢弃。取消不抢占工作线程，terminal 仍须等待真实工作退出和完成交付。

## 单条记录、元数据和接受点

INITIAL、MESSAGE 和 FINAL 共用一个记录槽。大正文分配和复制前，先在短锁内
占据 BUILDING 状态；复制在锁外执行，其他提交包括 finish 都返回 AGAIN，
不能越过尚未发布的正文。只有完整复制且再次确认尚未关闭后才发布命令。

初始元数据和尾部元数据沿用同一编码验证器及每阶段 512 字节限制。控制存储
在句柄创建时计费，元数据不会在调用之间借用应用地址。首次 INITIAL 或
MESSAGE 受理后关闭初始阶段；错误参数、AGAIN 或正文分配失败不消耗阶段。
finish 与尾部作为一条命令原子受理，没有独立长期暂存的 trailing setter。

owner 取出命令时，邮箱仍保持占用。调用路由器或传输时不持 producer/domain
锁；首次 MESSAGE 需要补空 INITIAL 时，也不提前归还正文槽。只有真实
MESSAGE 被传输接受后才开放下一次提交。发送可以同步释放正文，complete
只丢弃旧指针，不再次读取已转交的 buffer。

正文预算不足或分配失败返回 NOMEM，发送槽忙返回 AGAIN。可写等待只证明
已激活且单槽空闲，不预约共享字节预算；竞争者仍可导致 AGAIN，资源压力仍
可导致 NOMEM。使用一个 CLOCK_MONOTONIC 绝对期限处理全部等待及伪唤醒。
库内 I/O 域、工作域和终局回调禁止等待，避免依赖当前执行域的自等待。

方法响应上限为零仍允许取得句柄和发送零字节 MESSAGE。ONE 基数违规时，
派发器转换为 INTERNAL FINAL；已经验证的 FINAL 尾部保留，未发正文释放。
owner 同时锁存失败门禁，阻止新工作越过错误回复，已经运行的工作仅完成
清理，不能用迟到结果覆盖这条错误 FINAL。取消、期限和停机仍沿原路由收敛。

## 终局、销毁和独立预算域

最后一份应用引用在 finish 尚未受理时归还，会请求 CANCELLED。finish 受理
后归还引用不会撤销该回复。异步 FINAL 与仍在执行的后续 work 可以竞争：
已经由 owner 接受或选择的路由终局保持不变，terminal 仍等待原 work/done。
工作先返回非 OK 时，关闭 producer、丢弃尚未接受的命令并沿原工作错误路径
结束调用；这不承诺保留另一个尚未接受的异步 FINAL 的尾部。

每个 Server 分片有一个独立引用的 producer 域，跨该分片的全部对端共享有限
句柄配额。已关闭但尚未释放的句柄继续占配额及控制字节，反复连接和对端退役
不能重置这些限制。producer 和每个正文分别持有域引用；传输接受后的正文
可以长于 producer 存活。

域锁保护本地计费及借用的上游预算指针。正常 reserve/release 同步更新两侧，
任何使用者都不缓存上游裸地址。Server 在派发器和传输退出后，在同锁内一次
归还剩余上游计费并清除该指针；本地计费不清零，剩余应用句柄和迟到复制仍
须逐一归还。Server 不等待应用引用归零。

关闭与锁外复制可以并发。关闭会唤醒等待者、丢弃尚未转交的记录并解除库内
引用；迟到复制仅访问自己持有的 producer/domain，重新检查关闭并释放副本。
因此句柄和复制不要求 RuntimeShard 的内嵌预算存活到应用最后 release。

terminal 和语义 finished 在全部 work/done 退出、producer 库内责任收敛后
交付一次。它们不证明应用自建线程已经退出，也不证明对端收到 FINAL。
应用的线程及其私有状态必须有自己的寿命协议。正常排空继续以 Endpoint
实际终局及传输退出条件判断；已关闭句柄的应用引用不阻止 wait_drained。

## 验证范围

新增回归放入既有三个 V2/Dispatch 目标，没有新测试目标或 CI 作业标识。
核心新增一个生产翻译单元，由 Xmake 构建图及原生编译数据库校验覆盖。

- 内部派发回归覆盖单槽复制与重试、真实传输背压的原正文身份、阶段失败
  恢复、取消与停止、work/FINAL 两种先后、ONE 违规后阻止新工作、最后引用
  放弃、跨派发器共享配额、零正文上限及锁外复制与预算解绑竞态。
- 公共 SDK 使用真实应用 pthread，验证 STAGED 背压和源字节覆写、ACTIVE
  交接屏障、整窗口及空正文、元数据、取消、期限、Server 销毁、保留句柄、
  语义统计和排空；安装消费端仍只依赖公共头及 C/POSIX。
- 公共 Server 专测验证同步输出权切换的错误锁存、最后引用请求取消、
  STAGED 工作错误丢弃结果、finish 已受理后的 STATE 及提前 release。
- Endpoint 隔离夹具补齐共享域绑定的替身，继续验证独立宿主边界。

冻结提交的五模式全量、固定双分析器、四编译器安装消费、修改行格式及远端
作业验收结果将在收口后补入本记录。当前段落只说明范围，不作为通过声明。

## 保留的开发检查记录

首轮库编译通过。开发回归的原日志与独立原字节捕获均按尝试分别保存，
不覆盖失败后重跑。

1. `dispatch-01` 的新 producer 预算场景误用了同步批次的预约 helper。
   原 helper 要求有一份被 gate 阻塞的 submitted work，而该 producer 已经
   ACTIVE、完成 done，正确占用是一个活跃调用及零个 submitted/held/reply。
   新增专用 helper 精确检查这一状态，原同步 helper 的严格断言保留。
2. `public-01` 的 SDK 通过，Server 专测把已交接后的最后引用取消套用了
   blocked work 的尾部预期。前者已无在途工作，会正常发送空 CANCELLED
   FINAL，因此尾部精确为一次；后者工作尚未退出，先通过 RESET 停止网络，
   尾部仍精确为零。修正为两条有明确前提的断言，没有放宽为零或一次。

审查中另外修正了工作先返回错误时不应要求保留未接受异步 FINAL 尾部的
测试预期，以及上文的零上限和 ONE 失败门禁；保留接受点的真实区别。

## 范围限制

本阶段不提供 V2 NONE 基数、重连、连接组、网络压缩、TLS、通用重试或健康
检查。已有压缩后端编译并不表示已接入 V2 网络调用。旧静态告警继续逐条
跟踪，不能将基线接受或缺乏新告警解释为已证明误报或零告警。
