# 同 profile TLS 连接周转资源验证

日期：2026-10-29；候选 `2.0.0-dev.177`，关联 #234、#241、#247。
承接 [OpenSSL 分配账本](rpc_v2_tls_resource_ledger_20261029.md)，只扩展测试与文档，
生产代码、公开 API/ABI/wire 保持原合同。主会话内联执行，没有子 agent。

## 生命周期边界与场景

进程全局清理归零不能证明长期存活 profile 的资源行为；profile 自身的密钥缓存
又可能延迟扩容，不能把所有存活字节不变当作公开合同。

测试先用一对真实 TCP mTLS 会话预热全局算法缓存，释放 session 和 profile，
记录未执行全局 cleanup 时的请求字节/块基线。随后重新创建相同凭证的 profile，
连续 34 轮，每轮同时保留 16 对会话，累计创建并释放 1,088 个 session。
前两轮完整握手与双向各 64 KiB 传输；之后八轮四阶段循环分别覆盖：

- 尚未开始握手即释放；
- Client 发送 ClientHello 后中止；
- Server 推进握手、对端尚未认证完成时中止；
- mTLS 双向认证并传输校验正文后释放。

中止阶段核对 socket BIO 已写入握手字节且 SSL 认证未完成。完整握手和四个回收
位置预热后，后续 28 轮逐轮固定存活块数、记录存活字节范围；每轮检查包装预算
current 归零、fd 仍归调用方并由测试关闭。最后释放这对 profile，在全局 cleanup
之前要求请求字节和块数均精确回到预热基线；之后原有全局清理归零检查仍保留。

这保留了密钥缓存的合法寿命，同时检查逐连接对象回收与 profile 释放边界；没有
加入固定字节容差。它不能证明 profile 内部的所有潜在 resize 都有产品硬上限。
所有 SSL 驱动调用在独立子进程同一线程发生，不代表多 owner 的线程局部缓存总账。
原目标名、注册数据与 120000ms 超时不变，也保留提前释放调用方 profile 的原场景。

## 被否定的精确字节平台假设

最初候选要求六轮预热后每轮请求字节完全相等，曾通过本机四种工具链/消毒器和
全量 95/95；后续换证书重复验证的第 4 次在 `wave=8` 增加 8 字节，块数未变。
因此这些早期通过不能当作最终候选验收，候选没有在此时提交。

临时分配来源链表逐块比较，确认唯一变化为 `crypto/bn/bn_lib.c:279` 的一个请求
从 256 字节替换为 264 字节，旧指针已释放。进一步保存该块调用栈，原分配来自
`RSA_setup_blinding → BN_BLINDING_create_param`；替换来自
`BN_BLINDING_update → BN_BLINDING_create_param`。其余来源、大小与块数相同。
这排除了 TLS 会话缓存新增与账本 realloc 漏记两项假设，定位到 RSA 盲化缓存更新。
OpenSSL 的[盲化实现](https://github.com/openssl/openssl/blob/openssl-3.6.5/crypto/bn/bn_blind.c)
会周期性重建参数，[大数扩容实现](https://github.com/openssl/openssl/blob/openssl-3.6.5/crypto/bn/bn_lib.c)
替换旧缓冲；具体分配行号和字节数只属于当前后端观测，不进入最终断言。

最终改按资源所有者的释放边界核对字节，并继续逐轮检查块数；没有禁用 RSA 盲化、
更改证书算法、扩大内存池或任意增加允许增长字节数。来源链表和调用栈探针已移除。

## 当前本机观察与变异

Linux x86_64 / GCC 16.2.1 / OpenSSL 3.6.5，工作区日志中的一轮结果：

| 位置 | 请求字节 | 请求块数 |
| --- | ---: | ---: |
| 全局算法预热后、profile 已释放 | 543928 | 8185 |
| 活动 profile 下逐轮释放 session 后 | 604031 | 8994 |
| 34 轮后释放 profile、全局 cleanup 前 | 543928 | 8185 |
| 全局 cleanup 后 | 0 | 0 |

初始完整传输峰值 2882759 字节，交错握手暂停/中止后峰值 3287612 字节。
包装预算峰值 2304 字节，socket 配置容量 4456448 字节。
这些不是 RSS/内核驻留、跨版本保证或产品硬上限；头部和分配器元数据不在请求字节中。

最终边界设计加入两个全局预热 session 后，临时遗漏第 195 次 `SSL_free`，
即六轮周转预热后第一只 session，新块数断言在 `wave=6` 捕获（8994→9014 块）。
生产源码随后逐字节恢复，强制重建后目标通过；最终测试不保留故障探针。

边界调整后的重复第 14、15 次均再次观察到 604031→604039 字节的合法缓存变化，
块数保持 8994；profile 释放后仍精确回到 543928 字节、8185 块并通过。
这直接验证新的字节检查位置覆盖了该已复现后端行为。

原始证据在忽略目录 `build/performance-20261029/`：
`dev176-repeat-4.log`、`tls-waves-source-2.log`、`tls-waves-stack-4.log`、
`tls-waves-profile-boundary.log` 和最终变异/恢复日志。私钥没有进入日志或提交。
