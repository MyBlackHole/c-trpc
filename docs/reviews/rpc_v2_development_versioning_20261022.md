# RPC V2 开发版本编号规则

日期：2026-10-22。

## 目的与当前版本

仓库此前没有项目版本字段或发布标签，但缺陷提交规范要求每个缺陷修复都能关联到实际版本。为保留“当前是未发布开发候选”的发布边界，并让修复版本可追溯，V2 开发阶段采用 Xmake 项目预发布版本：

```text
2.0.0-dev.N
```

当前建立的开发基线为 `2.0.0-dev.0`。它是预发布开发标识，不代表稳定版 `2.0.0`、不承诺稳定 API/ABI，也不创建 Git 发布标签。

## 递增规则

- 每个按 `bug-commit-format` 或 `feature-commit-format` 提交的缺陷修复或功能提交，都递增 `N`，并在提交标题和正文中记录旧、新版本。
- 纯文档、审计或构建记录提交不改变项目版本。
- 当前 D9/D10 预算归还修复将 `xmake.lua` 从 `2.0.0-dev.0` 更新为 `2.0.0-dev.1`。
- 稳定发布版本、兼容性承诺和 Git 标签由单独的发布审查决定；不得从 `-dev.N` 候选提交中推断已经发布。

## 构建与 ABI 边界

版本由根 `xmake.lua` 的 `set_version()` 声明，供 Xmake 项目/制品元数据使用。当前不配置 `soname`，也不通过此版本字段生成动态库 ABI 链接名。静态 SDK 的头文件、符号和消费者兼容性仍按各自的安装验收与发布审查判定。
