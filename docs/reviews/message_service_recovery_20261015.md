# MSG-D1：父所有者退出后的消息服务显式回收

## 范围

基于 #255 的 `13883aeed58d3d9f76b5ac4969e64b5bf34e7fda`，关联 #235、#241、
#243、#248、#249 和 #239。本阶段解决父 Reactor 已成功停止/join 后的任务、
事件发布和回调责任接管，不将“停止准入”当成“原线程已经静默”。

这是实际实现与测试，不是旧 Runtime/Client/Server 自动接入完成。父生命周期
仍由调用方独占协调；没有新增父子对象注册、父对象引用计数或自动致命退出通知。
父 Reactor 与预算域必须继续存活，不能先销毁父对象再用悬空指针回收。

## 证据与设计取舍

已有 `tr_reactor_call_or_stopped()` 在未 started 时持 ctl_lock 执行短操作；
started 但不接受命令时返回 CLOSED。已有 `tr_reactor_stop()` 只有在成功
pthread_join 后才清除 started，join 失败可以重试。新实现利用这条真实边界，
不通过睡眠、accepting 标记、pthread_kill 或重用旧 pthread_t 猜测线程生存期。

- [POSIX pthread_join](https://pubs.opengroup.org/onlinepubs/9799919799/functions/pthread_join.html)
  定义成功 join 后目标线程已终止；这仍不代表它提交给其他工作线程的任务已结束。
- [libuv 事件循环](https://docs.libuv.org/en/v1.x/loop.html) 将停止循环与关闭仍存活
  的请求/句柄区分。这里借鉴责任区分，不引入 libuv，不声称两者恢复接口等价。

选择显式回收入口而不隐式换线程调用原完成函数，是为了保持原回调的所有者契约。
正常结果回调可能访问所属 Reactor/Call 私有状态，不能在其线程死亡后静默迁移。
同样，算法已成功但未交付的结果不能因停机接管而冒充一次新的成功交付。

## 接管执行器

`task_executor_recovery.h` 是单独的库内生命周期协调契约，不暴露槽位布局，也不
将模块私有的代次头公开给 Runtime。调用者先证明旧完成所有者不再执行，再停止
执行器并调用 `tr_task_executor_takeover_quiesced()`。

接管在执行器锁下进行：拒绝开放准入、正在回调及第二接管线程；仅首次接管或
同一个回收线程的重试成功。首次接管不比较已经失效的旧 pthread_t。清除通知与
通知调用使用同一锁，因此返回后没有旧通知正在执行，也不会再调用该通知。
工作线程仍可运行，任务槽位和完成结果不被丢弃，后续由新回收者 dispatch/join。

部分最终销毁失败也可能发生在父所有者退出前：例如条件变量已销毁、互斥锁销毁
失败。接管仅修改仍存活的控制状态，不再次广播已销毁的条件变量；新回收者只
继续剩余 destroy 步骤。这条分支在独立测试和集成测试中分别覆盖。

此接口本身不能证明旧线程死亡。它是受前置条件约束的内部移交，不是任何线程都
可调用的抢占机制；旧所有者与接管者并发操作仍是错误调用。

## 消息服务回收

新增 `tr_message_service_reap_stopped()`：

1. 在访问可变服务状态前，利用 call_or_stopped 核验父循环已完全停止。运行态
   回到原 owner 后无副作用地返回 STATE；停止中或 join 失败返回 CLOSED。
2. 在上述短串行区中取消在途工作、撤销执行器通知并锁定一个回收线程；不在父
   ctl_lock 内执行用户函数，也不嵌套调用会再次取得 ctl_lock 的 Reactor API。
3. 串行区之外逐个注销辅助 fd 源和定时器。错误时保留各自发布状态、fd 和对象，
   下次只继续未完成步骤。调用方必须持续独占父生命周期，禁止重启/销毁父循环。
4. 每次最多处理配置 dispatch_limit 个已完成结果，再尝试 join。一个工作仍未
   退出时返回 AGAIN，其他已完成工作仍可回收；不等待它才开始释放全部结果。
5. 完成责任、工作线程和事件发布全部收敛后复用同一个最终释放实现：销毁执行器、
   关闭 fd、释放服务；正常关闭与离线回收不各维护一套最终析构。

接管不可逆，不恢复正常准入，on_owner 操作和正常事件 pump 不再交付结果。
每次回收的 abandon 函数只借用到本次调用返回，不在后台继续调用。

## 原完成与放弃回调不能混淆

原 `done` 仍只在原 Reactor 所有者执行。父循环退出后，每个尚未交付的任务改走
调用方显式提供的 `abandon(arg, handle)`：释放变换操作和私有输出后再调用；
不交付任何成功载荷，不调用原 done。回调可记录 OWNER_LOST/取消并释放 arg，
调用线程、重入限制及资源责任写入头文件。

已正常交付并被应用保留的输出不属于服务私有结果，回收不得撤销该引用。它可在
服务和父 Reactor 销毁后继续持有，前提是对应预算域仍存活。

回收回调在所有内部锁之外执行；测试在回调中重新进入父停止串行接口验证不自锁，
同时确认递归回收被拒绝。回调可以释放原任务参数，服务之后不再访问它。

## 测试

### 执行器独立目标

`test_task_executor_recovery` 仅链接真实 task_executor 对象及 pthread，不链接
整个 trcore、Message 或 Zstandard。真实创建者线程退出并由测试 join 后，验证：

- 未停止的执行器拒绝接管；停止后接管成功，同线程重试幂等，第二线程拒绝；
- 工作者仍被门闩阻塞时 join 返回 AGAIN，预算不提前回收；
- 撤销通知后产生的完成不再通知旧参数，完成和最后释放仍正确执行；
- 已完成任务终局不被接管改写，部分 join 失败进度可以继承；
- 条件变量已销毁、互斥锁销毁失败的对象由新线程继续最终销毁；
- 回调中再次请求接管被拒绝，完成只交付一次，最终预算归零。

### 真实 Reactor 集成目标

`test_message_service_recovery` 链接真实 trcore/Reactor/Zstandard，用测试专用
链接包装控制事件顺序或注入错误，不给生产库加故障标志。新增用例包括：

- 父循环正常停止及 epoll_wait(EIO) 致命退出；父 pthread_join 首次失败时禁止
  回收，即使旧线程已看似退出；成功 stop/join 后才接管。
- 一条真实压缩工作被阻塞、其他任务排队时，离线接管仍保留数据和 fd；解除阻塞
  后取消收敛，逐次最多回收一个结果，工作线程 join 失败后继续重试。
- 原所有者已丢失，未交付的成功输出必须销毁并调用 abandon；同服务此前已经
  正常交付的输出继续保留，不重复回调、不提前释放其预算。
- fd 注销、定时器注销及最终同步对象销毁失败保留对象；正常关闭进入部分最终
  销毁后父 owner 再退出，也能接管剩余责任。
- 创建但未启动的服务可回收；回收完成后重启同一个 Reactor，没有旧发布再访问
  释放的服务；所有原始参数恰好终局一次，最后预算归零。

事件和定时回调延迟仅用于固定“结果已完成但未交付”的测试时序。故障目标是当前
服务或父线程，不改其他 fd。测试不调用 pthread_cancel 强杀线程，不把这种未定义
业务回滚等同于事件循环正常执行致命退出路径。

## 未完成的自动接入与下一边界

本轮没有修改旧 Runtime/Client/Server 自动销毁链、旧 RPC 执行器、线协议、
方向性协商、网络信用或 TLS，也没有开启生产网络压缩。下一步仍须将显式回收
纳入真正的父运行时协调流程，不能要求业务无限期手动维持这些内部顺序。

已核对 Runtime 的内存预算目前嵌入分片存储；新消息输出允许越过服务寿命，因此
门面接入必须同时设计“分片/预算域不得先于保留输出释放”的责任。不能只加一个
服务指针然后在 Runtime destroy 时直接 free 分片。这项与 #241/#243 联动验证。

当前要求父生命周期独占、成功 stop/join、父对象和预算域继续存活，重试须来自
同一回收线程。尚无自动父对象 pin、防止他人重启的持久租约、父对象销毁后的救援，
也不保证不合作工作者的强制终止。边界是可检查的有限回收能力，不是任意并发
错误或进程崩溃后的恢复承诺。PR 保持草稿，不关闭整体实现任务。
