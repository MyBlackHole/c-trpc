# #240：统一 RPC 语义内核与调用信封分析

日期：2026-10-15。状态：研究建议；事件名均为概念，不是新增 API 或已冻结 wire。关联 #235、#241—#245、#248；治理 G01/G02/G03/G04/G05/G07。

## 1. 原因与参照

[流式契约](https://github.com/MyBlackHole/c-trpc/blob/130835414f3e00cf97d49ca8af21d7a83c25146d/docs/architecture/08-rpc-streaming-conformance.md) 的 MANY 请求需要首条 REQUEST 才能识别方法；[元数据契约](https://github.com/MyBlackHole/c-trpc/blob/130835414f3e00cf97d49ca8af21d7a83c25146d/docs/architecture/09-rpc-context-metadata.md) 的一元调用没有独立尾部元数据。根因是调用控制与业务消息耦合，不是单独少了一个空消息 API。

[gRPC 协议](sources.md#s01) 将调用头、消息序列、半关闭与最终状态分别表达；[HTTP/2](sources.md#s04) 提供方向性流状态。借鉴语义，不继承 HTTP 头表示、网络序或每个语言的线程模型。

## 2. 目标状态与事件

建议保留一个 Call 语义核心，正交记录：打开状态、请求方向、响应方向、最终结果是否选定、任务/回调/存储是否回收。不要把每种 RPC 的所有组合复制成独立状态机。

| 事件 | 前置条件 | 原子语义结果 |
|---|---|---|
| CALL_OPEN | 调用尚未建立，方法和元数据合法，有准入额度 | 发布方法/基数/截止/策略快照；打开处理义务建立 |
| REQUEST_MESSAGE | 请求方向开放，数量和大小允许 | 接受一条业务消息；零长度仍计一条 |
| REQUEST_END | 请求方向未关闭，ONE 时请求数满足约束 | 只关闭请求方向；不自动宣称调用成功 |
| RESPONSE_HEADERS | 响应初始信息未发且调用未终局 | 冻结初始元数据；不要求先有业务体 |
| RESPONSE_MESSAGE | 响应方向开放且基数允许 | 接受消息；结果仍由最终状态决定 |
| FINAL_STATUS | 合法状态，未选定其他终局 | 冻结最终状态/尾部元数据，关闭新发送准入 |
| CANCEL/DEADLINE/RESET | 可终止状态 | owner 上选择终局，撤销未开始工作；已执行任务走回收路径 |

事件表只是骨架，实施时必须补齐每个非法输入的错误作用域。终局竞争在同一 owner 中线性化；用户可见最后事件之后不得出现新消息。若之前接受的消息回调仍排队，明确采用排空已接受回调或取消尚未开始回调的单一政策，不能靠偶然队列顺序决定。

ONE 是成功路径上恰好一条的约束；远端在完整请求前拒绝可直接错误终结。MANY 可为零条；零条流和一条零长度消息不能混淆。双向流不要求请求/响应交替，也不允许一个阻塞处理器等待依赖同一串行回调队列的下一条消息。

## 3. 接受、认证与截止时间

把传输接收、RPC 准入、handler 开始、业务副作用、最终响应分别记录；这些不是同一个提交点。OPEN 可用于早期方法验证/认证，但恶意或高并发对端仍可能提前发送字节，因此必须有有界 pre-admission 缓冲或明确 reset，不能声称“先认证”就无需限制待认证数据。

每个新 Call 预约终局控制/完成能力，错误返回不再依赖无限分配。OPEN 大小、并发和期限受限，避免零消息请求洪峰占满资源。

调用本地使用一个绝对单调 deadline。[gRPC deadline 传播](sources.md#s21) 使用扣除已耗时间的相对预算。c-trpc 也应在真正发送 OPEN/重试前计算剩余值，不把队列里等待前的 timeout 原样发送而延长远端预算；不同机器的单调绝对值不可直接比较。网络时延和时钟调度存在误差，客户端本地总期限仍为权威，不能承诺双方纳秒同时终止。

## 4. 方案取舍

A：独立语义信封，单个网络批次可组合 OPEN/数据/END；推荐。B：在第一条业务 REQUEST 中继续嵌入所有控制字段，给零消息和尾部元数据增加特例；拒绝，因为会继续产生形态分叉。C：完全复刻 HTTP/2 头部；并非必要，后端选择在 #246。

公开一元 API 可保留易用形式，但内部走统一 Call 核心；特化只允许优化编码/批量提交，不得绕过基数、鉴权、预算和终止证明。正式发布前可删除旧分支；新协议版本不匹配明确失败，不能猜测旧格式。

## 5. 实施与验证

| 切片 | 交付 | 判定证据 |
|---|---|---|
| RPC-A | 纯状态转换函数和受控效果接口 | 四种基数；零消息/空消息；每个状态的非法事件 |
| RPC-B | OPEN/初始/最终元数据的 wire 编解码 | 黄金向量、任意字节拆分、未知类型、长度溢出、重复终局 |
| RPC-C | 一元和流式统一适配 | 同等请求产生相同核心事件，成功必须见合法终局 |
| RPC-D | 取消/期限/拒绝和执行器接入 | OPEN 后未发体、鉴权挂起、已执行业务但响应丢失、完成队列满 |
| RPC-E | 删除旧路径并完善文档 | 旧 wire 安全拒绝，SDK/示例真实运行，无旧测试悄悄掩盖新语义 |

核心属性：没有隐式成功；最终结果最多一次；接受的回调/资源义务必能结束或明确等待外部归还；header/body 的分离不新增强制线程跳转。负责人待指定；本轮不把状态表当成已执行模型检查。
