## 2. 必须分开的账本

对预算域 d 定义：`available_d + reserved_d + held_d = limit_d`。预约转为实际持有时不能重复扣减；实际分配失败撤销对应预约；池缓存未释放仍算 held。计账单位必须标在类型/字段里，避免把消息条数、明文字节、编码字节混用。

| 域 | 计费对象 | 不允许的简化 |
|---|---|---|
| 网络 | 后端定义的 flow-controlled octets；连接和流独立 | 用解压输出 U 返还编码体 C 的信用 |
| 存储 | 输入、staging、输出容量、保留消息、重放缓存 | 把逻辑 len 当实际 capacity；把同一存储的多个引用重复收费 |
| 执行 | 任务槽位、最终完成节点、压缩工作区与工作并发 | 只有消息队列长度，无完成路径容量 |
| 全局/分片/服务 | 确认纳入的用户态资源与子域预留 | 启动 N 分片后把总预算偷偷扩大 N 倍 |

第三方内部分配、分配器元数据、线程栈和内核 socket 内存需单列范围；未纳入者不得通过一个 memory_budget 选项被宣称全面受控。CPU 预算采用公平工作配额/并发限制，不把 deadline 当成可抢占 CPU 定时器。

## 3. 推荐的首个可证明数据路径

建议本地消息提交不以全部网络窗口已就绪为前提。先获得消息存储与操作/完成额度，接受后可处于 WAIT_WIRE 状态；网络发送按帧/块使用流与连接信用。该队列有上限，满时拒绝接受而不是追加旁路链表。

对已知编码长度 C 的消息，接收端在开始数据处理前核查消息描述和配额，可预留足够的重组/解码存储或明确拒绝。收到一个片段并转入已经预留的有界存储后，可推进网络消费信用；完整消息及应用保留期间，存储额度仍持有。这样 C>网络窗口时仍有分段推进路径，而不是等待整消息完成才返还网络窗口。

这是候选机制，不要求新增往返握手：消息首部、流初始许可或已有协商可表达允许接收的范围，确切映射与 #240/#246 一起定。若不提供接收预约/信用推进，就必须在准入时明确拒绝无法支持的组合，不能永久 TR_AGAIN。单纯把默认窗口调到最大消息只能改变样本，不能证明所有配置和不对称对端。

增量解码候选可减少双缓冲，代价是错误时可能已产生部分输出。面向完整消息的 API 必须在校验成功后才交付；增量应用 API 必须独立说明回滚不可撤销，不混入首版完整消息语义。

## 4. 多预算原子性和公平调度

逻辑预约事务覆盖存储、任务和终局能力：失败撤销已取的 token，不在持有某个全局锁时等待其他额度。可由同一 owner 串行，或采用明确全序的非阻塞获取加回滚；不得假设几个原子计数各自正确就组成原子事务。

网络调度推荐按流的就绪队列与有界字节配额；比较轮转和赤字轮转在异构消息大小下的公平性。已经部分写出的同一帧不可被后续帧插入字节；只在合法边界重排。控制帧有保留额度和有界优先突发，不能无限压倒 DATA。某流等消费不得把整个连接的所有就绪流锁死。

RESET 后未交付的已接收字节仍要维护连接信用；流信用是否需要回补由后端终止规则决定。不能在 reset/释放/连接关闭三个路径各返一次。正常存储释放与最终信用责任由唯一 token 消费。

## 5. 实验、属性与完成切片

| 切片 | 实验 | 通过条件 |
|---|---|---|
| FLOW-A | 复核允许配置；L<W、L=W、L>W，无其他流 | 可接受组合有前进，不支持组合立即明确失败；不接受无限暂时背压 |
| FLOW-B | 独立预算账本、失败回滚和最小任务池 | 每步守恒，无超额或重复归还，整数饱和/转换受检 |
| FLOW-C | 一字节拆分、双向发送、C>W、U远大于C | 不靠加大窗口完成；解码不绕过存储限制 |
| FLOW-D | 慢消费者、大/小流混合、控制洪峰 | 压力解除且调度公平时所有已接受工作可推进 |
| FLOW-E | 持有消息、取消、重连、late completion | 原代次资源释放，不影响新流计数；终局仍有出口 |

活性声明有前提：网络最终可用、调度公平、应用最终归还外部持有对象。应用永不归还缓冲时不能承诺无限继续服务；要返回背压、期限或显式仍持有状态，而不是提前 free。阈值和资源粒度需按对等测试选择。本轮未运行上述实验。
