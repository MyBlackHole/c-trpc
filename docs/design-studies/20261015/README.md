## 1. 研究方法与证据等级

每个分项采用同一问题链：当前源码/契约是什么 → 外部项目实际提供什么机制 → 原场景与 c-trpc 的差异 → 采用及不照搬的理由 → 状态/接口/资源责任 → 有限实施切片 → 正向、负向和活性验收 → 待实验决策。

| 标签 | 含义 | 使用限制 |
|---|---|---|
| 基线事实 | 固定提交的源码/契约或已经读取的当前议题状态 | 不凭历史 TODO 推断缺陷依旧存在；未逐一重新执行旧测试 |
| 外部机制 | 官方文档、协议或源码明确描述的行为 | 语言/版本/上下文分别标注；不把软限额称为硬保证 |
| 本项目建议 | 根据需求和机制提出的候选设计 | 不等于接口已冻结、已经通过审阅或实现 |
| 待实验 | 需要最小原型、复现或对等测量作出的决定 | 不宣称已复现 bug、已经更快或已经符合安全级别 |

[来源目录](sources.md) 登记 S01—S42，共 42 个研究入口，不代表 42 个独立项目。选型引用的版本是研究样本，不表示已经引入依赖、已确认最新补丁或已做漏洞扫描。动态网页/默认分支按本次访问日期记录，关键实现采用记录的 tag/blob 身份；实施阶段需要重新固定候选依赖并运行测试。

没有复制第三方实现进入生产代码。采用某个设计原则不意味着迁移到 Bazel、libuv、Seastar、Netty 或完整 Envoy，也不意味着必须维护多个后端。

## 3. 本轮纠正和新增的关键认识

**资源限制的语义不可混用。**Envoy 水位、grpc-go 的发送软配额、网络窗口、应用持有存储和第三方内部分配是不同域。#241/#234 分别要求证明自管预算与外部内存范围，不以单个配置宣称严格限制整个 RSS。

**逻辑消息不要求一种唯一缓存实现。**逐消息独立压缩与增量处理兼容；首个有界完整变换方案只是候选实施切片。需要增量模式时先定义未知编码长度、部分输出和终止语义，不为了沿用旧 wire 假装问题不存在。

**接受操作、执行完成和存储回收不能合并。**容量预约不是已接受工作；拒绝与接受后的失败有不同所有权。回调不在提交栈中执行，也不保证另一线程绝不先于提交函数返回运行；必须在发布前准备状态。

**其他项目不是无条件的正确性背书。**TLS 库分配器钩子不天然提供逐连接硬隔离；codec 的堆预算不天然限制递归栈；时间截止也不能抢占一次同步 C 算法调用。缺失的保证要补机制或收窄承诺。

**参照资料之间也需要判断。**gRPC 协议的历史重试说明不能替代后续 gRFC A6；重试责任和提交条件按明确的 A6 范围研究。项目、语言、具体版本的内部线程/队列设计不混为一谈。

## 4. 实施依赖：先有最小共同契约，不形成循环等待

不把 #240、#241、#243、#248 写成互相“全部完成后才能开始”的阻塞环。先共同评审最小契约切片 D0：

- 字节视图/持有引用和预算责任令牌；
- operation 的拒绝/接受/取消/最终完成及 P/C/R 屏障；
- Call 语义事件与 Message 业务体的分界；
- 字节端点/流传输的能力与完成事件；
- 最小组件清单和受限依赖测试入口。

D0 可以通过类型草案、少量纯模型和替身测试审查，不要求先实现完整 TLS、调度器或新协议。

| 阶段 | 可以并行的工作 | 依赖的具体产物 | 退出条件 |
|---|---|---|---|
| D0 契约切片 | MOD-A、ASYNC-A、RPC-A、FLOW-A 的模型/草案 | 已核对基线与真实需求 | 所有接受点/owner/预算单位明确，没有相互复制终态 |
| D1 可执行原语 | MSG-A/B、TLS-A/B、TEST-A/B、MOD-B | D0 所需窄接口，不是整项 issue 完成 | 无真实网络的核心测试和单连接 TLS 负向测试分别有证据 |
| D2 垂直接入 | RPC-B/C、MSG-C/D、FLOW-B/C、ERR-B/C、ASYNC-C | 原语的接受/取消契约 | 一条真实 RPC 与普通消息路径正确回收；各入口逐一验证 |
| D3 目标与后端 | TARGET-A/C、CODEC-A/B、BACKEND-B/C | 统一语义/能力表 | 选择和重放边界可说明；不靠旧协议兼容决定方案 |
| D4 综合验收 | 故障/慢消费者/多 DATA/TLS/压缩、平台、性能 | 对应实际实现提交 | 明确支持范围、残余风险与有限任务关闭条件 |

压缩不等待整个选路/重试/治理清单完成；TLS 也不等待压缩算法完成。每个功能切片同时执行 G01 模块边界、G02 生命周期和 G04 预算检查，不先堆完功能再补架构。

## 5. 待实验决策与证据要求

本轮没有随意冻结的选择包括：TLS socket/memory BIO、第三方内部分配的预算覆盖、消息完整/增量变换、流消费信用触发、标识空间/晚到帧规则、codec 默认后端和最终传输后端。各分项都给出了实验对象、负向场景和拒绝条件。

实验记录至少包含：候选方案、需求和不可放弃的不变量、精确源码/工具版本、负载或事件轨迹、实际命令、正/负例结果、资源/性能成本、未覆盖范围、采用/拒绝理由。负责人和复核人由项目在实施切片中指定，当前未指定不能假称已有人持续执行。

测试通过只对其提交、配置和范围有效。文档检查、模型检查、编译、运行时测试、漏洞适用性分析、性能测量分别报告；本轮没有执行产品编译、运行时故障实验、安全扫描或性能测试。新文档的路径/链接/覆盖检查若执行，应在 PR 中单独记录，不能代替这些产品证据。
