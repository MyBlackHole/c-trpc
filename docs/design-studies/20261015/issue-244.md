# #244：服务目标、策略、健康与调用尝试分析

日期：2026-10-15。状态：建议，尚未启用自动重试。关联 #234/#240—#243/#247/#248；治理 G02/G03/G04/G05/G10。

## 1. 现状与一手参照

[client.h](https://github.com/MyBlackHole/c-trpc/blob/130835414f3e00cf97d49ca8af21d7a83c25146d/include/tr/client.h) 的连接入口限数字 IPv4，且明确重连不透明重放进行中 Call。该安全默认不应在引入服务发现时被无意取消。

[gRPC 选路](sources.md#s24) 的 Resolver/连接管理/Picker 和 [服务配置](sources.md#s37) 提供目标级策略；[libcurl multi](sources.md#s22) 区分传输任务与事件驱动；[Envoy circuit breaking](sources.md#s23) 对连接、待处理请求与重试设置不同约束。吸收分域责任，不把某个线程/连接池默认值当 c-trpc 目标。

## 2. 对象边界与安全缓存键

建议 ClientChannel 拥有 target、地址快照、连接集合、策略版本和 Picker；LogicalCall 拥有应用唯一结果与总 deadline；Attempt 拥有选中 peer、传输 stream、发送/响应进度与引用；Connection 拥有 TLS 和字节流状态。

连接复用的等价键不能只有 IP/端口，应涵盖预期服务身份、TLS/ALPN 配置和身份安全域。解析到同 IP 不意味着可以复用不同受众的令牌。调用凭证按受众生成，不把 bearer token 本身变成无界连接池键或指标标签。

地址/策略更新以不可变快照发布。进行中调用保留其策略快照；新地址集合移除的连接进入排空，仍被 Attempt 使用的对象不能立即释放。配置来源不可信时不能允许其修改信任根、扩大凭证受众或解除安全约束。

## 3. 就绪、健康与等待

Picker 结果区分 READY、暂时无连接、等待健康、永久配置/身份错误和显式拒绝。只有可恢复状态可以进入有界 wait-for-ready；等待的字节、条数、定时器和引用都纳入 #241，总期限不重新开始。

TCP 活跃、TLS 通过、传输握手完成、服务健康和方法准入分别建模。健康检查自身有频率、并发和退避预算，不能在服务过载时制造另一波洪峰；业务健康不等于安全授权。首次版本先验证 static resolver + 单连接选择 + 可控健康替身，再增加 DNS/IPv6 和轮转，不先做复杂动态插件框架。

解析失败时是立即失败、保留有期限的上次有效快照，还是等待重试，要显式配置和记录陈旧期限；过期的安全策略不能被普通地址容错掩盖。

## 4. 重试策略与提交条件

[gRFC A6](sources.md#s02) 把尝试数、退避、重试状态、推迟信号和缓冲限制组合，且总 deadline 覆盖各次尝试；幂等与可重试状态的选择由服务拥有者负责。c-trpc 的方法重放许可是自身设计，不能声称网络库自动判断业务幂等性。

建议首版只做顺序尝试。以下条件任一出现即不再透明切换：响应初始信息按契约被接受并提交、任何响应向用户可见、重放数据无法完整保留、策略不再允许或总期限到期。具体较早提交点可更保守，不能为了重试率延后到业务已可见后。

分类：尚未离开客户端；对端明确未处理；处理情况未知。前两类也要有协议/运行时证据，不能仅根据 sendmsg 返回值推断。第三类仅在方法许可和预算允许时重放；客户端超时、连接重连、REMOTE_CLOSED 都不是未执行证明。

尝试数包括初次请求；全目标重试额度与单 Call 上限分别限制。退避使用可注入随机源和抖动，取消可撤销定时器。远端 pushback 的合法范围、负值/无法解析处理、超过剩余期限时的行为必须冻结，不能信任对端延迟使本地无限等待。RESOURCE_EXHAUSTED 也不自动许可重试。

## 5. 有限实施切片

TARGET-A：目标/策略快照/安全键；测试地址删除、相同 IP 不同身份、解析结果乱序。

TARGET-B：Picker 与有界等待；测试无节点、永久认证错误、健康抖动、取消及总期限。

TARGET-C：单 Attempt 内核和计数；逻辑调用与 Attempt 结果不混合，旧 epoch 完成无效。

TARGET-D：重放缓冲与顺序重试；在提交点前后断连、执行后丢响应、缓存满、恶意 pushback、退避取消。

TARGET-E：DNS/IPv6/多连接选路及诊断；扩展不得改变前四项不变量。请求对冲需另行需求和副作用评估，不为对标强制加入。

## 6. 判定与未决项

验收要求每条轨迹只有一个应用结果，全部 Attempt 资源守恒，排队时间包含在端到端延迟内。无法验证远端未执行时保留不确定结果，不承诺恰好一次。目标更新一致性、连接池上限和退避参数必须实测；不因为它们是 P1 就绕过 #240—#243 的基础契约。本轮未运行实现测试。
