# #242：错误作用域、重置与排空边界分析

日期：2026-10-15。状态：候选协议设计，未实现。关联 #240/#241/#243/#244/#246；治理 G02/G03/G04/G05/G07。

## 1. 问题与参考

[Channel 接收路径](https://github.com/MyBlackHole/c-trpc/blob/130835414f3e00cf97d49ca8af21d7a83c25146d/src/transport/channel/channel.c#L1616-L1880) 中可定位到流的某些错误和重组池失败进入连接级 protocol_error。这里确认的是错误策略，不是内存漏洞，也不是所有路径都必须改为忽略。

[HTTP/2 RFC 9113](sources.md#s04) 区分流/连接错误及 GOAWAY 边界；[nghttp2](sources.md#s06) 区分连接/流消费反馈。借鉴错误隔离和信用责任，不直接把 HTTP/2 的 stream id 顺序套到多 DATA 连接组。

## 2. 建议错误分类

| 原因 | 处理作用域 | 剩余义务 |
|---|---|---|
| 业务拒绝、方法不存在、调用级鉴权失败 | FINAL_STATUS | 冻结调用结果，停止新消息，结束用户回调 |
| 边界可信的单流消息语义/解码失败 | RESET/该调用错误 | 释放该流存储，处理已经在途的字节及连接信用 |
| 本地池/任务预算压力 | 明确资源拒绝或有界等待 | 不冒充对端损坏；控制终局须有预留容量 |
| 无法信任的帧边界、连接协商错误、TLS 完整性失败 | 连接关闭 | 该连接所有流失败并按 owner 屏障收敛 |
| 未知事件/不可能的私有状态损坏 | 根据可证明恢复域关闭或隔离 | 不能盲目遍历已经可能损坏的链表假装安全释放 |

RESET 是异常终止双向流，不等于正常半关闭；收到一部分响应不等于最终成功。远端错误信息需大小/速率上限，不能把它直接打印为无限标签或误当本地可执行操作。

## 3. 晚到帧与标识空间

推荐同一会话内流 ID 单调分配且不复用，到上限进入排空/重建身份域；本地 slot/generation 与 wire ID 分开。重连创建新的会话 epoch，旧代次完成不可命中新对象。这是候选新协议，不要求兼容旧回绕行为。

不能为每个已结束流永久保留 tombstone。应明确活动表、有界最近结束状态，以及基于合法已分配区间/连接状态判断的处理规则。高水位本身不证明每个较小 ID 都曾合法打开，存在空洞、交错和不同发起方时尤其不能全部忽略。实现前需要列出允许晚到的类型、可计量丢弃量、超过限额的动作及超时回收规则。

解析边界仍可信时可使用受限 scratch 缓冲丢弃某流剩余字节，不分配整个恶意 payload。与此同时，reset 流已接收字节的连接信用只能归还一次；存储释放和流移除的先后要进入模型。无法按协议安全跳过时必须关闭连接。

## 4. GOAWAY 与连接组

定义“已接受”线性化点：建议在方法/协议合法、Call 及终局额度完成准入后发布。它只说明框架接管请求，不说明 handler 已开始、业务已经提交或副作用只发生一次。

单连接可传最后可能已处理的流界限及拒绝原因；界限之后的请求只有在协议明确证明未处理时，才作为 #244 的安全重试依据。界限之前一律不能推断成功或未执行。

多 DATA 连接组需要组 epoch 和每成员/传输的接收边界；CONTROL 消息先到与 DATA 字节先到没有天然总序。候选 A 是每成员独立边界加组级屏障，候选 B 是显式 transfer 接受记录；选择须验证异步附着、成员替换、CONTROL 断开和已退役任务。不能通过一个全局 next_stream_id 伪造跨 socket 原子快照。

## 5. 控制面前进与攻击成本

在接受流时保留终局控制描述符；发送队列饱和时仍可发 RESET/STATUS，或者按明确策略终止受影响连接。不用无界控制队列解决死锁。控制帧还需要每轮/每连接速率或工作预算，否则攻击者可用极小帧绕过字节限额。

单流隔离的目标不是无条件保住连接：反复非法流、控制洪峰或必须保持的连接不变量失效时，升级关闭连接是合理的受控政策，应有计数和理由。

## 6. 切片与验收

ERR-A：错误分类表与纯状态模型；测试同一个故障在不同解析可信度下的作用域。

ERR-B：RESET 和标识不复用；测试 DATA/STATUS/RESET/END 各种先后、重复 RESET、ID 空洞、上限及旧 epoch。

ERR-C：信用和控制保留；一流坏输入不影响其他正常流，连接级破坏必须关闭；OOM 不被误报为业务成功。

ERR-D：排空与接收边界；OPEN 与 GOAWAY 并发、处理后响应丢失、多 DATA 状态不一致都不得给出错误重试许可。

ERR-E：有界历史和丢弃成本；长期大量短流、恶意长度和晚到 DATA 下资源/CPU 不随历史无界增长。

全部以事件轨迹、原始失败和预算守恒验证；这些实验本轮未执行。
