# #245：方法描述、序列化与 C/Rust 接口分析

日期：2026-10-15。状态：候选设计与选型实验，未实现生成器。关联 #235/#240/#241/#243/#248；治理 G01/G03/G04/G05/G07/G08。

## 1. 现状及三种参照

[当前 codec 头](https://github.com/MyBlackHole/c-trpc/blob/130835414f3e00cf97d49ca8af21d7a83c25146d/include/tr/rpc_codec.h) 公开 RAW 基线；[方法描述](https://github.com/MyBlackHole/c-trpc/blob/130835414f3e00cf97d49ca8af21d7a83c25146d/include/tr/rpc.h) 使用手填 ID/基数/codec/长度。已有本地注册校验不能被说成缺失；缺口是双端和生成物的一致来源。

[protobuf-c](sources.md#s18) 提供生成描述及 allocator/unpack/free 配对；[Nanopb](sources.md#s19) 可用字段上限约束静态存储；[Buf](sources.md#s20) 区分源接口和 wire 等不同变化检查。借鉴对象生命周期、资源约束与契约检查，不把某库支持 Protobuf 等同于它已经满足全部 CPU/递归深度硬限额。

## 2. 推荐的描述和数据边界

建立唯一 MethodDescriptor：稳定方法名/ID、请求响应 schema、ONE/MANY、允许 codec、原始消息限制、授权/重放策略引用。ID 不依赖注册顺序；若由名字哈希产生，必须检测冲突并有注册失败规则，不能当无碰撞标识。

序列化属于类型化业务对象到字节的边界；Message 压缩只接收已明确所有权的字节；传输不认识 Protobuf 对象。核心保留 RAW/字节能力，但不要求应用重复手填已经能由描述生成的信息。

codec 接口区分 `encode(borrowed object → owned bytes)`、`decode(borrowed bytes → owned object/retained view)`、destroy/retain。输出对象引用原始消息存储时必须显式保留；不能在回调返回后继续用借用 bytes。编码两遍计算长度与实际 pack 之间对象必须不可变，容量检查和整数溢出必须处理。

## 3. 候选方案与拒绝条件

A：Protobuf 描述 + protobuf-c 后端。适合动态对象与生成 C 接口；需自定义预算 allocator、匹配释放及恶意深层/重复字段实验。

B：Protobuf 描述 + Nanopb 后端。适合可预先给出字段上限的消息；可变字段回调不自动获得同等静态内存保证，schema 上限也不替代栈深度分析。

C：自建 IDL。只有现有描述不能表达必要契约且维护成本有证据时才采用；不能为“更轻”重复制造 parser、类型系统和跨语言漏洞面。

推荐先让 A/B 在同一黄金 schema 上比较正确性、对象大小、分配和深度控制，再选择默认后端；允许只维护一个，不为插件化强制长期支持所有 codec。未知 codec 必须明确拒绝，不能把未知数据回落为 RAW 后交给业务。

## 4. 安全与演进不能混同

解码有独立的深度、字段/元素数、字节和分配上限。外层消息长度上限和 Zstd 输出上限不能防止解码器内部对象膨胀。allocator 可以限制堆，但不能自然限制递归栈或同步 CPU 时间；选定后端必须确认这些控制存在，否则收窄允许 schema 或调整实现，不能虚称硬上限。

schema 指纹可用于诊断和严格模式，不应默认把整个描述字节完全相同当成所有通信的必要条件：Protobuf 的合法新增字段可能仍能按已约定规则解析。正式发布前可选择拒绝旧版本，但必须是明确的协议策略，不是偶然由指纹或生成器版本不同触发。Buf 类检查用于揭示变化，是否允许破坏由项目决策，不能违反用户允许重设计的原则。

## 5. C/Rust 桩与异步所有权

生成桩提供类型化方法入口，最终调用统一 #240/#243 内核，不各造一套超时/重试。Rust 封装必须把 borrowed view、owned message、Call retain 和异步 completion 映射为正确生命周期；禁止仅把裸指针包装成 safe struct。

ffi 回调的线程域、是否可能早于提交函数返回、panic/异常跨 FFI 的处理、库卸载前存活对象都要明确。取消 future 不等于 C 侧操作立刻释放；安全封装需要保持回调状态到 C 侧完成/退役。

## 6. 切片与验收

CODEC-A：单一描述、稳定 ID 和冲突测试，生成结果可重现。

CODEC-B：A/B 后端实验；同一个 schema 的往返、黄金字节、错误类型、截断、未知字段和边界数据。

CODEC-C：分配/深度/工作量约束；第 N 次失败、持续失败、恶意嵌套、过多元素，验证释放配对。

CODEC-D：C 调用桩/派发与 Rust 所有权封装；回调后持有、取消后迟到、线程切换、跨语言一致性。

CODEC-E：构建漂移门禁；修改 schema 未更新生成物必须失败，生成器和依赖锁定在真实测试提交。当前仅研究，不宣称任何一个后端已通过选型。
