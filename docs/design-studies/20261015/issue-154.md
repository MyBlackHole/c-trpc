## 4. 四类容易过度承诺的地方

第一，引用计数不自动保证指针有效。取得引用前必须已有有效持有或受保护查找；release/acquire 的具体 C11 关系单独证明，不能机械复制 Linux 内存模型。

第二，失败关闭不等于任何内存损坏都可恢复。链表或私有对象被破坏时，沿链表释放可能继续访问非法地址。应区分正常资源失败和无法证明状态有效的内部故障，不以“库不 abort”为由伪造可安全继续运行。

第三，Linux close 错误并不普遍允许重新对同一个数字 fd 调用 close；[close(2)](sources.md#s41) 说明 fd 复用风险。把逻辑 teardown 的重试能力与系统调用 close 的重试分开，不能因统一 helper 误关已经重用的描述符。

第四，消毒器与静态分析都有限：地址/线程检查器不等于活性证明，精确告警基线也不是误报许可。当前两条 GCC unverified 仍需独立验证；诊断减少只能说明这组输入下工具不再报告。
