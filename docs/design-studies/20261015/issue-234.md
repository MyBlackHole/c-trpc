# #234：TLS、身份与连接状态的逐项设计分析

日期：2026-10-15。状态：研究与建议，待接口评审和实现验证；不表示 TLS 已实现。代码基线与证据等级见 [总索引](README.md)。关联 #239、#241、#243、#248；治理 G02/G04/G05/G08/G09。

## 1. 当前问题与学习入口

[当前 README](https://github.com/MyBlackHole/c-trpc/blob/130835414f3e00cf97d49ca8af21d7a83c25146d/README.md) 明确无内建 TLS；[Connector 契约](https://github.com/MyBlackHole/c-trpc/blob/130835414f3e00cf97d49ca8af21d7a83c25146d/src/io/connector_internal.h) 已有连接尝试、取消与回调源拆除语义。TLS 必须接入这些所有权边界，不能另造一套会话线程。

| 一手参照 | 机制 | 借鉴限制 |
|---|---|---|
| [OpenSSL 非阻塞指南](sources.md#s11)、[SSL_write](sources.md#s12) | 读写操作可能要求相反方向的网络事件；重试有输入稳定性要求 | 示例中的等待方法不直接放入 Reactor；不能把 WANT 当普通 EAGAIN 后随意切换写缓冲 |
| [SSL_pending](sources.md#s13) | 库内已处理数据与未处理记录不同 | 有未处理记录不保证可输出明文，不能自旋 |
| [gRPC 认证](sources.md#s14) | 连接凭证和调用凭证分离 | TLS 证书有效不等于获得任意方法/组的权限 |
| [libuv handle](sources.md#s08) | 请求关闭与最终存储回收不是同一时刻 | 借鉴屏障，不要求引入 libuv 或复制其取消 API |

## 2. 推荐架构与方案比较

推荐连接模块导出字节端点，明文/TLS 是其后端；RPC 与 Message 不见 SSL、BIO 或 fd。连接所有者独占 SSL 状态；握手工作由该所有者分轮推进，外部凭证获取使用受限任务执行域。

候选 A：OpenSSL socket BIO 接入，较容易与现有 fd 事件路径验证；候选 B：memory BIO，便于控制输入输出和测试，但增加密文缓冲与消费责任。先原型比较两个方案的部分写入、关闭、预算和测试替身需求，不能仅因 B 更抽象就默认选择。首版候选以 TLS 1.3 为基线，算法/依赖版本与策略在实现 PR 中明确；引用 OpenSSL 3.5 文档不表示已选定安全补丁版本。

不采用：每连接工作线程、TLS 失败隐式回退明文、公开 SSL 指针、默认跳过证书验证、默认 0-RTT。显式明文开发模式可独立存在，不能伪装成安全模式。

## 3. 状态、接口与所有权契约

建议状态：TCP_CONNECTING → TLS_NEGOTIATING → AUTHENTICATED → TRANSPORT_HANDSHAKE → READY → DRAINING/CLOSING → DETACHED → RELEASED。每个箭头有 owner、失败原因和已持有资源，任何状态都不能在回调源仍可触达时释放连接对象。

字节端点操作至少表达：接受/拒绝、已消费明文长度、待关注事件、可继续推进标志、EOF/失败，以及最终完成。SSL 写入重试期间持有稳定缓冲与原始参数；部分成功后只推进实际消费的区间。SSL 产生的密文尚未写出时，不能把“已消费明文”当成完整 RPC 已送达。

读写事件兴趣取握手、pending read、pending write 的需求并集；处理预算耗尽但库内仍有可处理数据时进入有界就绪队列。连续调用无输入/输出进度时等待外部事件，不因 SSL_has_pending 恒真而忙等。致命 SSL 错误、正常 close_notify、TCP 截断及 RPC 缺失最终状态分别报告。

连接/握手使用总单调期限，不因 WANT 重置；截止时间或取消停止新准入，已排入的回调和缓冲按 #243 收敛。正常关闭尝试有界 close_notify；致命 SSL 错误遵循后端要求，不能机械再次执行 SSL_shutdown。

信任契约分三层：预期服务身份（SAN 主机名/IP 等）、本连接验证结果、调用/连接组授权策略。DATA 加组要绑定经验证的主体与组代次；同 CA 签发不等于同主体。凭证轮换发布不可变配置快照，旧连接保留其引用；迟到的凭证结果不能复活已取消的 Attempt。

## 4. 资源边界：不能虚报硬上限

c-trpc 明文、密文、队列、握手数量和自管工作区都必须记账。但 OpenSSL 的内部配置/会话/证书分配不天然提供每连接预算接口；[内存分配接口](sources.md#s15) 不是可以随意对某个 SSL 动态安装的隔离分配器。

实施前必须列出可精确追踪的库管理字节、外部分配、分配器开销和内核缓冲；不能靠限制连接数就声称进程 RSS 有严格上限。若产品要求包含 TLS 内部分配的硬限额，需验证选定后端的分配控制/统计适配或调整支持声明。握手 CPU 也不能仅靠检查墙钟时间实现硬抢占上限；并发额度、证书输入限制和公平调度是独立约束。

## 5. 可关闭的实施切片与验收

| 切片 | 交付 | 必须通过的测试 |
|---|---|---|
| TLS-A | 字节端点与 mock TLS 状态模型 | WANT_READ/WRITE 交叉、无进度、取消、关闭、未接管资源不丢失 |
| TLS-B | 单连接 TLS 1.3 + 服务身份验证 | 正确信任、未知 CA、过期、错误 SAN/用途、明文输入、协议降级拒绝 |
| TLS-C | 原始 TRP 握手及双向业务流接入 | 任意 TCP 拆包、部分写、库内 pending、队列满、EOF 与 STATUS 先后 |
| TLS-D | mTLS/组授权/配置轮换 | CONTROL/DATA 主体不符、旧快照存活、轮换失败、迟到认证 |
| TLS-E | 预算/长期负载/发行契约 | OOM、取消洪峰、慢握手、干净与截断关闭、GCC/Clang/消毒器与外部客户端 |

验收由实际命令、精确提交和资源清单支持；没有网络互通及攻击负向证据不能关闭 #234。接口设计可与 #235 并行，不等待复杂重试/选路。

## 6. 待实验的有限决策

socket BIO 与 memory BIO 的选择、TLS 内部分配可计量范围、每轮握手工作预算、策略轮换方式。每项均需原型、失败矩阵和成本对比后决策，不以“以后优化”掩盖安全保证空缺。实现负责人和复核人待项目指定。
