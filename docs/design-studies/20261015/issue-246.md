# #246：传输后端契约与 TRP/HTTP2 选择分析

日期：2026-10-15。状态：评估方案，不预判性能。关联 #234/#235/#240—#244/#248；治理 G01/G03/G04/G06/G08。

## 1. 为什么不能直接给出“保留 TRP”结论

[当前 Reactor](https://github.com/MyBlackHole/c-trpc/blob/130835414f3e00cf97d49ca8af21d7a83c25146d/src/execution/reactor.c#L1-L110) 包含 TRP 解析/编码和帧 TX 状态；[Call 创建](https://github.com/MyBlackHole/c-trpc/blob/130835414f3e00cf97d49ca8af21d7a83c25146d/src/rpc/rpc.c#L5394-L5632) 又直接绑定传输流。已有协议和目录不是不能改变的前提，也没有本轮对等性能实验支撑“自定义一定更快”。

[nghttp2](sources.md#s06) 展示可复用 C 帧层及消费接口；[libcurl multi](sources.md#s22) 展示多传输的事件驱动集成；[Envoy HTTP filters](sources.md#s40) 将较高层请求事件与具体 HTTP 版本分开。学习这些可替换契约，不要求嵌入完整代理、复制 curl 所有协议或迁移到特定事件库。

## 2. 两个不同层次的接口

字节端点：connect/握手、读写进度、EOF、事件兴趣、取消及最终回收。它可采用现有 epoll，但不解析 RPC 或传输帧。

流传输：open_stream、提交受限消息/字节片段、方向性结束、reset、接收窗口反馈、连接 drain、错误作用域与完成事件。它依赖端点和执行能力，不访问 RPC 私有状态。

接口必须声明后端能力：是否提供流级 reset、可证明的接收边界、元数据约束、消息大小及资源模式。无法表达的必要语义在创建/调用前明确拒绝，而不是静默降级。共享层不应为复用而退化成只有 void* 和 int 的不透明大开关。

## 3. 对比候选与决策门

| 候选 | 主要收益假设 | 必须支付和验证的成本 |
|---|---|---|
| TRP 下一版 | 可按专门数据流、组传输和静态资源优化 | 自维护流控/RESET/GOAWAY/版本/攻击防护，不能仅改帧头 |
| HTTP/2 + nghttp2 原型 | 标准帧状态、流多路复用、流/连接信用 | HPACK/头部/控制帧资源、第三方分配、回调生命周期及与 TLS 的组合 |
| 两个后端永久并存 | 满足确实不同的部署需求 | 测试矩阵、语义交集和维护成本；没有需求证据不作为目标 |

先实现 mock byte endpoint 与 mock stream transport，再选一个真实适配做最小闭环，以检测抽象是否足够，而不是为了抽象同时写两套完整产品。

**HTTP/2 后端不自动等于 gRPC 互通。**还需要方法路径、gRPC 消息格式、元数据、状态和具体序列化的一致映射。互通若成为目标应有独立的跨实现测试；若仅使用 HTTP/2 承载 c-trpc 自有语义，要明确标注并使用合适协议协商，不能冒称 gRPC。

## 4. 性能实验必须对等

固定 CPU/编译配置、业务处理、消息分布、原始与编码尺寸、TLS、压缩、连接数、最大并发、内存约束和成功判定。分别报告冷连接握手、稳定复用、连接组/多连接、慢流混合、丢包/延迟和异常恢复。

既测开环负载也测闭环，记录 offered/admitted/completed/rejected、端到端与服务时间、排队、P50/P99/更高分位、CPU、RSS、自管存储峰值、复制/分配/syscall。不能让一个后端大量拒绝请求后按幸存请求延迟宣称更快。

HTTP/2 的流多路复用不消除 TCP 级队头阻塞；自定义协议在单 TCP 上也有这一点。连接组多 socket 的收益要和相同连接拓扑比较，而不是把另一方限制为单连接。性能阈值先按目标负载确定并记录，不在没有基线时虚构百分比门槛。

## 5. 资源、错误及取消适配

背压要区分本地队列接受与后端写出。nghttp2/其他库内部缓冲也纳入统计范围，不能因为藏在第三方就绕过 #241。暂停一个流不应无意暂停所有连接级控制进度。

部分发送、RESET 与消息变换完成交错时，唯一 adapter 负责把后端事件映射为 #240 语义；不允许 RPC 和后端分别通知两次终局。版本不匹配明确拒绝；旧开发协议可删除，不保留永远运行的双路径。

## 6. 切片及退出条件

BACKEND-A：两层契约、能力表和 mock 测试；核心测试不链接真实网络。

BACKEND-B：当前 TRP 适配到契约并保留全部生命周期回归；不把移动文件当完成。

BACKEND-C：HTTP/2 最小实验（若目标比较确有需要），统一错误/流控/取消测试。

BACKEND-D：运行对等负载和故障实验，形成采用/拒绝 ADR，注明覆盖与未覆盖。

BACKEND-E：删除不选路径或正式承担多后端矩阵，更新 SDK/部署/协议说明。

本轮仅给出决策条件，未构建或运行两个后端，也未承诺 HTTP/2、TRP 的绝对速度。
