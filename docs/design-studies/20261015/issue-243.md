# #243：异步操作、持有能力与取消收敛分析

日期：2026-10-15。状态：设计建议，不宣称已经替换同步 API。关联 #154/#234/#235/#240/#241/#248；治理 G01/G02/G04/G07。

## 1. 现状和借鉴机制

[当前 rpc.h](https://github.com/MyBlackHole/c-trpc/blob/130835414f3e00cf97d49ca8af21d7a83c25146d/include/tr/rpc.h) 的 Call handle 是借用能力，[client.h](https://github.com/MyBlackHole/c-trpc/blob/130835414f3e00cf97d49ca8af21d7a83c25146d/include/tr/client.h) 明确限制回调内等待和销毁。这是已有契约，不等于已发现死锁；下一步需要能安全表达跨回调存活的业务/压缩/鉴权操作。

| 项目 | 可借鉴点 | 必须保留的区别 |
|---|---|---|
| [libuv](sources.md#s08) | 关闭请求与可释放时刻分离 | 不是所有 request 都能以同一种 cancel 取消 |
| [Seastar gate](sources.md#s10) | 关闭准入并等待已进入的工作退出 | gate 不是强杀长任务，也不自动收回应用持有引用 |
| [Tokio Sender/Receiver](sources.md#s09)、[许可与关闭](sources.md#s36) | 预约容量、提交和关闭后待持有许可分开 | 直接把任务入队不等于会被接收方执行，不能用 send 成功当 RPC 完成 |
| [Linux kref](sources.md#s28) | 在交给其他执行者前取得生命周期引用 | 先读裸指针再任意加引用不保证对象仍存活 |

## 2. 推荐操作模型

借用视图、可持有引用、协议能力三者分开。引用可保持对象存储，但不能让终止 Call 重新获得协议权限。稳定控制块或经保护的 handle lookup 确保 retain 与销毁互斥；generation 检查本身不能修复已经失效的裸指针。

建议公开提交是非阻塞的：拒绝时保留调用方资源且不产生完成；接受时引擎接管规定资源、取得执行与最终完成额度。operation_id、owner epoch、Call/Attempt 代次共同标识结果。接受后的成功、失败或取消都产生一次完成义务，不能在 OOM 时静默丢掉。

推荐不在 submit 的调用栈内执行用户完成回调；但是其他执行线程可能在调用方从 submit 返回之前就观察到完成，因此不能笼统承诺“所有回调必在函数返回后”。调用方必须在发布操作前准备 callback_arg；需要严格串行时使用明确的执行域契约。现有 Connector 允许 inline 完成，迁移必须同步修改调用方和测试，不能只改注释。

## 3. 预约、接受与停止

预约令牌持有队列/预算/生命周期引用，尚未表示业务操作已接受。commit 时重新验证 admission epoch；关闭后旧预约不能向重新打开的新 epoch 发布工作。未提交的令牌归还预留，释放持有引用；不得在用户仍持有 token 时直接释放其控制块。

令牌可设计为内部短作用域能力，不必先公开复杂 API。停止流程为关闭准入 → 撤销未接受预约或等待令牌归还 → 取消/完成已接受工作 → 排空最终回调 → 释放资源。等待外部持有引用可以超时并明确返回仍被持有，而不是伪造销毁成功。

每个 Call 可把终局完成节点内嵌在预分配状态中，普通消息满载不影响最终通知。不能使 STOP 依赖一个已满且无人再消费的普通队列。

## 4. 并发和跨模块边界

同一 Call 的协议事件由单 owner 修改；每个方向的在途读写数明确约束。执行器只负责任务，不直接修改 Call/Stream。同步便利接口位于异步内核外层，在 owner 或潜在循环依赖上下文拒绝等待；跨 owner A→B→A 必须用异步结果而不是阻塞链。

应用回调顺序与协议接收顺序分别定义。阻塞 on_message 等下一条同 Call 串行回调会造成自等待；需要挂起/续处理表达，而不是加更多线程掩盖。

取消在 owner 上选择结果并阻止新业务准入；正在执行的 C 处理器只能协作停止，不能强制回收其正在使用的输入。父子调用关系持有有界关联；子 deadline 不晚于父；父取消传播和子完成解绑均幂等，避免循环强引用。

## 5. 三个屏障及失败责任

P：协议最终结果已选定。C：最后用户回调已结束。R：所有任务、引用、预算和缓冲已归还。P 不推出 C，C 不推出 R；检查每个对象允许在哪个屏障释放哪些资源。

构造失败的回滚也可能失败，必须保留精确的可重试控制对象或使整个构造事务在发布前不可失败地回滚。两种契约都可以，但不能通过错误码掩盖仍活跃的线程/回调。存在结构损坏时不得假设遍历释放必然安全。

## 6. 切片和验收

ASYNC-A：定义 operation/control block、借用/持有与预约事务；测试拒绝不接管、epoch 变化、令牌滞留。

ASYNC-B：提交/完成队列和取消模型；单 worker、最小容量、STOP 与提交竞争、回调可能早于 submit 返回。

ASYNC-D：同步封装和父子上下文；测试 A→B→A、回调内等待、子期限继承、循环引用防护。

ASYNC-E：P/C/R 屏障和故障回收；断连/超时后持有缓冲、构造回滚失败、持续 OOM、重复取消。
