# #235：独立消息层、压缩与有界变换的逐项设计分析

日期：2026-10-15。状态：建议，非实现。关联 #238、#240、#241、#243、#248；治理 G01—G07/G09。共同基线见 [总索引](README.md)。

## 1. 当前差异与学习材料

当前源码无压缩实现；#238 仍是消息层设计草稿。[RPC 信封](https://github.com/MyBlackHole/c-trpc/blob/130835414f3e00cf97d49ca8af21d7a83c25146d/src/rpc/rpc_wire.h) 包含控制与元数据，[连接组消息](https://github.com/MyBlackHole/c-trpc/blob/130835414f3e00cf97d49ca8af21d7a83c25146d/include/tr/transport.h) 还有 FIRST/LAST 接收语义；不能只在一个 Channel 回调加算法后宣称所有入口都已接通。

| 参照 | 可吸收机制 | 不能据此宣称 |
|---|---|---|
| [gRPC 压缩](sources.md#s03) | 双向算法可不同、逐消息不压缩 | Channel 必须强制只有一个双向算法 |
| [Zstandard v1.5.7 API](sources.md#s16) | 压缩界限、增量 API、流式解码窗口限制 | 仅设置窗口限制就限制了实际输出、CPU 或整个进程内存 |
| [Netty 引用计数](sources.md#s17) | 消息视图与底层存储寿命分开 | C 代码中复制描述符自然获得持有引用 |
| [Tokio 容量许可](sources.md#s09) | 接受前预留，未提交的许可可归还 | 关闭后所有预留自动消失 |

## 2. 推荐契约，而不是预先冻结算法目录

核心数据概念为只读字节视图、拥有存储、预算责任令牌、消息描述符、变换操作。Message 不拥有 RPC Call 终态，也不读 Channel 私有字段；消息/传输适配器传入已验证的方向性编码配置，消费完成事件。`none` 保持原有存储，允许嵌入式描述符；不要求额外分配、复制、线程或通用动态插件链。

序列化 codec、压缩算法与网络分帧是不同责任。只压缩业务体，不压缩 CALL_OPEN、身份元数据和最终状态。业务体包含秘密或与攻击者内容混合时仍需禁压缩。每消息使用独立逻辑上下文；实现可复用已重置的工作区，不能复用前一消息的历史字典。首版不接收远端自定义字典。

方向性策略：连接能力声明“允许的算法集合与限制”；每个调用/流方向选择发送编码；消息标志可选择该编码或 none。未知、未协商、超限或不一致组合明确拒绝。具体标识、长度字段和作用域由协议 ADR 固定，不在本文抢占旧 wire 位。

## 3. 完整变换与增量变换的选择

A：完整业务体 → 有界工作任务 → 得到已知编码长度 C → 分帧发送。优势是消息描述与失败回滚易验证，代价是原始体 U、编码体 C 和工作区可能同时存活。

B：增量压缩、边输出边发送。减少 staging，但需要未知长度/终止标记、部分发送后的失败、解码校验和取消语义；不能把 gRPC 的已知长度消息前缀原样套到未知 C。

推荐首个生产接入用 A 作为可证明的有界方案，接口允许后续 B；不是为了兼容旧实现，而是先获得明确的消息接受与预算模型。#241 必须允许已知 C 大于网络窗口时分段推进，不得用 A 作为整消息必须装进窗口的理由。若目标大消息不能在允许内存内做 A，应先完成 B 的独立语义而不是静默突破预算。

## 4. 双提交点与额度责任

建议异步 `submit_transform`（概念名）：拒绝时不接管输入、不产生完成回调；接受时原子持有输入、操作槽位、预算和最终完成义务，之后的编码或传输失败通过完成结果交付。纯同步辅助变换可借用输入产生新输出，但不能在下游 TR_AGAIN 后仍承诺已经释放的原缓冲归调用方。

状态为 RESERVED → ACCEPTED → TRANSFORMING → READY → TX_ACCEPTED → RETIRED；取消标记与最终结果单独线性化，工作完成可能晚于结果选定。接受后至少存在一种完成或取消结果；完成节点必须在接受前有容量，不能在最后一步 OOM 丢掉通知。

额度账本记录 U、C、已分配输出容量、工作区、持有引用和所属预算。对相同存储多视图不重复记内存；两份存储并存必须双计费。网络信用按实际 wire 定义处理，释放 U 不能误返 C 的流信用。动态池保留容量在真正缩容/销毁前仍占存储额度。

## 5. Zstandard 后端的具体检查

压缩前检查输入上限与 size_t 转换；检查 ZSTD_compressBound 自身的错误并限制输出预约，不只检查最终返回长度。选择增量路径时逐轮限制输入/输出块，完成后验证只消费允许的消息范围。

流式解码显式设置 ZSTD_d_windowLogMax，同时独立限制累计实际输出、输入尺寸和工作区。该参数在单次解码中的意义不同，不能机械调用后当成所有模式通用硬限额。声明的原始长度来自不可信对端：先验证上限，解码后检查实际长度，处理未知长度、截断、多帧/尾随数据、skippable frame 和字典标识的明确接受政策；首版宜拒绝未定义组合。

deadline 只能取消准入或在安全检查点协作停止，不能抢占正在执行的单次 Zstd C 调用。高压输入必须用并发/工作量约束及受限块处理降低影响；无进度的增量循环必须等待更多输入或报错，不自旋。失败后的上下文按选定 API 恢复/重建，复用前验证状态。
