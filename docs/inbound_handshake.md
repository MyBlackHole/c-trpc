# 入站握手期限与资源回收

## 配置与兼容性

`tr_server_config.handshake_timeout_ms` 限制一条已接受 TCP 连接完成入站握手的总时间：

- 普通 RPC 监听器：Channel 完成 HELLO 能力协商并产生 `CONTROL_UP`；
- 连接组监听器：完整、合法的 TRR1 前导通过路由准入并交接到 CONTROL/DATA。

默认值为 `10000` 毫秒。显式 `0` 同样归一化为默认值，不表示无限等待或关闭防护。
`UINT32_MAX` 仍是有限毫秒数，约 49.7 天。期限从接受连接后的准入处理开始，
覆盖后续 Channel/RPC 构造；不会因为收到部分头部、部分载荷或 TRR1 字节而延长。
需要更短或更长网络握手窗口的应用应显式设置该字段。

字段追加在 `tr_server_config` 尾部，保留已有字段顺序。使用初始化函数、指定字段初始化
或尾部零初始化的旧源码，在重新编译后获得默认有限期限。此变更增加结构体大小，
**不承诺与旧头文件编译的二进制 ABI 兼容**；升级库时必须同时重新编译所有使用方。
当前构建产出静态库，自行封装成动态库时也适用。不能把旧尺寸配置对象传给新库的
创建或初始化函数：新初始化函数同样会按新结构体尺寸写入。

握手期限独立于 `keepalive_interval_ms/keepalive_timeout_ms`。保活只检查已经就绪的
Channel；即使保活被禁用，入站握手仍有有限期限。它不构成 RPC 截止时间、认证流程
抢占、或连接组成功交接后的空闲连接回收策略。

## 所有者、容量与失败路径

普通服务端每个 Reactor 分片最多增加一个定时器；连接组监听器最多增加一个定时器。
它们复用 Reactor 原有固定 `4 * max_connections + 16` 定时器预算，不增加线程、
额外工作队列或随接受次数增长的对象。期限保存在现有有界 peer/connection 槽位中，
新增准入和到期处理只扫描所属有界表。每轮只考察当前槽位中的句柄及期限；旧连接的
到期唤醒不会保存并追踪已经复用的对象指针。

- 期限使用 `CLOCK_MONOTONIC`；读取失败则拒绝该次准入。
- 定时器注册或 arm 失败时拒绝新连接。旧连接已经建立的定时器唤醒保持有效。
- 到期时由原 Reactor 所有者同步 abort 精确连接，不向可能已满的命令队列重新提交关闭。
- 普通 peer 仍通过既有 DOWN 通知、延后清理事件和 Endpoint 引用计数退役。
  不在 Channel 回调栈上直接释放 Channel/RPC。若旧 Endpoint 退役额度已满，
  先关闭到期的物理连接，再遵守既有退役背压，待旧 RPC 工作释放后归还 peer 槽位；
  握手期限不会抢占正在执行的业务回调。
- TRR1 尚未交接的连接通过原前导释放回调归还容量。
- 到期与 RX 在同轮可用时，完成握手前再检查期限，晚到的完整握手也不能越过期限。
- 销毁前先关闭监听准入，再跨过定时器注销屏障，最后释放回调参数。
  注销失败时保留对象与句柄，调用方可重试销毁。

这些保证依赖 Reactor 所有者持续得到调度，以及用户所有者回调遵守短小、非阻塞契约。
超时不会抢占阻塞中的授权回调或操作系统线程。进程暂停、调度延迟或操作系统异常
可能推迟实际关闭；这不是硬实时定时器。

## 就绪诊断

`peers_ready_current` 和 `peers_ready_total` 只在真实 `CONTROL_UP` 后计入。
已构造 Channel/RPC 但尚未收到有效 HELLO 的连接只计入 `peers_current`。
握手超时不增加 `keepalive_timeouts`，因为它不是就绪后的存活探测失败。

## 回归验证

`test_inbound_handshake_deadline` 使用真实回环 TCP，并仅在测试链接阶段包装时钟、
定时器和 abort 边界。精确期限测试仍在原 Reactor 所有者上执行回调，不增加生产钩子。
覆盖：

- 不发送任何握手字节、逐字节发送不完整 HELLO/TRR1；
- 截止前 1 纳秒仍保留连接、截止时回收、字节到达不续期；
- `max_peers/max_connections=1` 满槽拒绝、超时释放后合法 Client 成功连接；
- 旧定时器通知与槽位复用、连接组 stop/listen 新周期；
- 零配置恢复默认有限期限、真实 80ms 定时器与 10ms 保活配置相互独立；
- RX 先于 timer 分发但握手已到期、完成判断的单调时钟失败；
- TRR1 授权回调跨过期限、最终交接检查失败后的 CONTROL 会话回收；
- DATA 已附着后最终检查失败，保留精确关闭事件、退休成员关系并重用代次槽位；
- 初始时钟、定时器注册、arm、abort 和运行中/停止后注销故障；
- 已有连接等待时第二次 arm 失败，旧连接仍由原真实 timer 回收；
- 两分片的总容量与容量拒绝、超时后资源回收；
- 真正就绪后不再受旧握手期限影响。

`test_deadline` 同时覆盖纳秒转换的零值、无限期限、负时钟拒绝、最大毫秒数和
64 位饱和边界。原有传输/RPC、线程预算、构造回滚与 teardown 回归继续适用。
