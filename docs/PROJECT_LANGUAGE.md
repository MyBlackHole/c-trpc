# 项目语言约定

## 中文是面向维护者与使用者的默认语言

新增或修改的 README、公开 API 注释、设计文档、开发与测试指南、代码注释、示例说明、命令行帮助、纯人读诊断、提交说明、PR 标题与说明均使用简体中文。既有英文按独立的语言清理批次迁移，不在功能修复中顺带全库重排。

技术概念用中文解释；首次出现容易混淆的概念时可附固定英文术语。不要用英语句子或大段英汉拼接替代中文解释。例如写“超时期限”“所有权转移”“工作线程”“发布与消费”，并保留实际代码中的 `deadline`、`owner`、`worker` 等标识符。

## 必须保留的兼容面与原文

- API、ABI、函数与类型名、宏、枚举、变量、字段、导出符号、SONAME、协议类型和协议字节保持不变。
- 文件名、路径、命令、参数、配置键、环境变量、构建目标、JSON/CSV 字段、结构化事件代码、基准指标键及单位保持不变。
- 既有错误状态标记及可被自动化解析的日志标签保持不变；是否为机器接口不明确时，先查调用者、测试及下游约定，不直接翻译。
- CI 的任务 ID、既有必需检查展示名称、工作流关联身份、构建产物名称和下载引用视作自动化接口。普通 `step.name` 可以中文化；身份改动另行核验规则与调用者。
- C、C++、Linux、POSIX、Xmake、CMake、Syslog 等专名、标准名、代码中的固定术语保持原样。
- 第三方 LICENSE、版权声明、SPDX 标记及法定通知保持原文；可以另加中文说明，但不改写或声称译文替代原文。
- 历史原始日志、性能数据、审计证据、版本快照与外部引用保持原文和可核验性。另加中文导读或译注，并标明对应版本、时间与适用范围；不能把旧结论翻译成当前项目保证。

上述例外不豁免普通说明句。示例中的协议负载、测试字符串和字节比较数据不因读起来像英文就改写。

## 用户可见文本

新写的纯人读错误解释、帮助及提示使用中文，错误代码与上下文键原样保留。既有文本迁移前记录消费者：交互展示、日志检索、测试精确比较、脚本解析、外部 API 返回值。

仅当确认属于展示文本时，才修改其文案。涉及 `printf` 的转换类型、占位符顺序、转义、换行、缓冲区长度及截断条件都必须核对。UTF-8 中文增加字节数，不能假定原容量足够。系统 `strerror()`、编译器和第三方工具输出不强制翻译；由项目补充中文上下文。

## 评审与验证

1. 一批只处理一种层次：约定/入口文档、公开 API 注释、设计说明、内部注释、展示文案、历史导读。
2. 文档与注释批次不得修改标识符、常量、控制流、命令、协议或测试语义。不要同时运行全库自动格式化。
3. 逐项检查链接、章节锚点、代码示例与引用。改变中文标题时同步本库引用；外部已公开锚点应保留兼容锚点或提供明确迁移。
4. 注释批次逐项比较非注释词法单元，再跑对应编译/测试；不能以简单正则删除注释作为唯一证明，因为字符串也可能包含注释符号。
5. 展示文案批次逐条查找字符串消费者并更新受影响测试，不削弱断言、不改机器数据以使测试通过。
6. 英文扫描只作候选提示，必须有例外清单和人工判断，不能按 ASCII 命中强制“零英文”。
7. PR 使用中文描述范围、保留项、验证命令与结果；未运行的验证明确写出。
