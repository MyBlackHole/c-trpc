# PERF-V2-02：初始信用的容量恢复通知

日期：2026-10-23。基线：`36dadcc298a3606c87a36f1b430e0a94107e52a2`（`2.0.0-dev.2`）。关联 #247、#241。

执行：按用户要求由当前主会话连续完成，不使用子 agent。沿用已隔离的工作副本。测试输出、临时目录及缓存全部位于工作区 `build/`。

## 目标与设计

PERF-V2-01 已保留初始 WINDOW_UPDATE 暂满时的待确认流，但只在 25ms 维护定时器重试。控制发送池归还容量后，应由 Reactor 在正常调度点通知待确认流；保留原定时器兜底及其失败清理契约。

采用每条物理连接一个内嵌的一次性观察项，所有者维护 FIFO 等待链。只有控制池有空位、命令队列有容量时才通知；回调前摘除，失败者可重新登记到队尾。通知共用每轮 TX 分派预算，不在释放发送项或登记函数的调用栈中运行，不扫描全部连接。跨线程归还最后一个被占用的控制池空位时，通过已有 eventfd 唤醒所有者，避免检查后入睡的丢失唤醒。

通知绑定精确连接代次及当时处理器；关闭、处理器替换和显式取消移除观察项。Channel 成功确认、排空拒绝及拆除同步取消观察并归还 RX 暂停。该切片只推进待确认 OPEN；消费信用、RESET 及更广的容量准入另行评估。

相较缩短定时周期，此方案在容量实际恢复时调度；相较在池释放中直接回调，它避免 Channel 锁内重入。保持默认容量、公开 API、协议字节、每连接至多一个待确认流、受理高水位及 GOAWAY 顺序不变。
