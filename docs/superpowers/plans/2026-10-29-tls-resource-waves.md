# TLS 同 profile 连接周转资源验证计划

关联 #234、#241、#247；承接 dev.174 的独立分配账本。
主会话内联执行，不使用子 agent。

## 目的与设计

清理进程后请求块归零不能证明长寿命 profile 下资源不会按连接次数增长。
复用同一对 mTLS profile，分批保留 16 对真实 TCP 会话，交错覆盖未开始握手、
已发送 ClientHello、服务端已推进握手即中止，以及完成双向各 64 KiB 后释放。
预热完整握手后逐轮检查自有预算归零、fd 所有权和 OpenSSL live 请求块数，记录字节；
记录工作集峰值，严格区分平台缓存、测试头部和内核配置容量。

先观察真实后端的稳态范围，再固定有来源的断言；不能随结果放宽发布容量或硬上限。
如有增长，先定位实际所有者，不通过全局 cleanup 掩盖轮次之间的残留。
生产 TLS 生命周期合同不变；测试默认轮次有界，保留原目标与 120000ms 超时。
长稳和跨平台仍须单独验收。
