# PERF-V2-03：流槽耗尽时有界拒绝新流

关联 #239、#242、#247。基线 `968df41d93f120b29a87757e098fb641dfa88273`（2.0.0-dev.3）。沿用用户持续开发授权，在主会话实施与审查。

## 已确认问题与选择

PERF-V2-02 小档实验在 `active_streams == max_streams == 64` 时进入连接级 `TR_ERR_NOMEM`；控制池当时还有 8 个空位。当前 `STREAM_OPEN` 分配流失败即关闭连接，无关调用随之失败。

不能等到旧流释放才恢复接收：关闭旧流所需的帧可能位于新 OPEN 后面。GOAWAY 可以安全排空，但会永久停止该连接准入，不能承接后续新调用。选择独立的未受理拒绝帧，明确不分配接收端流、不给初始信用、不进入上层业务。

## 协议和责任

- Channel 握手协议升级到 3；线帧信封仍为 1，RPC Record 仍为 2。握手只接受本版本，旧版本在准入前拒绝，避免将新拒绝规则发送给不支持的对端。
- 新增 `STREAM_REFUSED = 15`：flags=0、stream_id 非零、message_id 为 `-TR_ERR_NOMEM`、无 payload。它仅拒绝尚未获得初始 WINDOW_UPDATE 的 OPEN。
- 开流端只对精确连接上的本地 OPENING 接受拒绝，立即使句柄失效，发布一次 `TR_STREAM_EVENT_REFUSED`。不回 CLOSE/RESET，不保留墓碑。未知、重复、错误连接、已受理流的拒绝仍是连接协议错误。
- OPENING 已禁止 DATA/CLOSE/RESET；本地取消保留终局结果，待初始信用或拒绝完成传输回收。REFUSED 映射为 RPC `RESOURCE_EXHAUSTED`，先前已提交的取消/截止结果不被覆盖。
- 拒绝证明该 transport stream 未受理；不将它泛化为对其他 Attempt 或业务副作用的证明。

## 有界发送与公平性

复用 Connection 现有单流终止预留，支持 RESET 和 REFUSED 两种互斥帧。幂等比较包含帧类型，保留固定命令前沿、DATA FIFO 与 GOAWAY 顺序，普通控制池和命令队列满不影响其准入。

每条物理连接最多保存一个未提交的拒绝 ID。预留忙时先取得既有维护定时器责任，再暂停该连接 RX；恢复只等待预留发送项释放，绝不等待流槽/RESET 回应。重试取得预留后解除 RX 暂停。新拒绝先让既有 RESET 推进；拒绝和 RESET 都在等待时，按该物理连接上次取得预留的类型交替，让持续 OPEN 和部分写都不能饿死 RESET。重试沿用 25ms 维护周期，本阶段不宣称其吞吐已满足 40k。

本地排空可以用冻结的 GOAWAY cutoff 接管尚未提交的拒绝：暂停期间不可能接受更大的同连接流。已提交拒绝维持与后续 GOAWAY 的 FIFO。断连清除精确连接待办；解绑/销毁恢复借用连接的 RX，不遗留回调。

新增 Channel 固定两个 32 位拒绝 ID 和两个 8 位轮换标记（实际大小另受对齐影响）；不增加逐流表或动态分配，Connection 复用现有预留。

## 验证

真实 socketpair 验证槽满只拒绝新流、旧流继续传输、槽归还后继续准入；串行拒绝数超过槽总量仍有界。覆盖控制池/命令满、预留忙、部分写、拆分连接、排空/取消交错、定时器失败、停止/解绑、非法及重复帧、旧版本拒绝。普通 V2 端到端验证 RESOURCE_EXHAUSTED、单次完成与全部回收。
