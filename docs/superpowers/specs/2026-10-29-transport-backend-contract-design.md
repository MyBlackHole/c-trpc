# 传输后端语义契约与 TRP / HTTP/2 对照设计

日期：2026-10-29；状态：设计提案，未实现通用适配器或完成后端比较。
关联 #246、#240–#245、#247。用户选择自定义传输与业务消息格式；本文保持该
产品方向，同时补齐后端判断依据，不以历史 TRP1 字段作为不可修改的约束。
主会话内联执行；不新增生产依赖、运行时线程、队列或公开 API。

## 1. 边界与现状

后端承载有序双向字节流、流生命周期、准入与网络信用；Message 层负责业务消息
边界、压缩/解压和拥有型存储；RPC 内核负责 OPEN/INITIAL/MESSAGE/FINAL、基数、
方法/类型合同与 Call 终局。TLS 属于字节端点，不能因后端更换就省略认证、身份
快照、关闭顺序和凭证代次。CTM1 的共同描述协商仍按其独立待审阅设计处理。

当前 [rpc_record_stream](../../../src/rpc/rpc_record_stream.h) 直接依赖
[Channel/Stream](../../../src/transport/channel/channel.h)，还没有本文定义的后端无关
绑定。当前 TRP 使用 Frame、Channel HELLO v3 和 RPC Record V2 等不同版本域，
不能一概称为一个“TRP1 版本”。本提案不把文档接口描述当作已完成的源码解耦。

后端边界沿 [ADR-007](../../architecture/decisions/ADR-007-layering-performance.md)：
同一 owner 可直接调用，不要求每层一条队列、线程或复制。实现可以只保留最终
选择的一个后端；实验适配器不自动变成长期产品维护承诺。

## 2. Call、Attempt、流与连接

- 逻辑 Call 固定原期限、方法语义、已获准保留的请求快照、可重放依据及总尝试预算。
  流式历史只能在显式重放额度内保留，不自动保存全部输入。一个
  Attempt 绑定一条双向传输流和一个连接代次；后续 Attempt 必须取得新能力。
- 一次 Attempt 可以一对一映射到 HTTP/2 Stream；这不要求逻辑 Call 永远绑定
  同一物理流。gRPC 的重试也会建立新流，不把这点误列为 HTTP/2 不适用。
  [重试参考](https://grpc.io/docs/guides/retry/)
- 上层能力不能是 fd、HTTP/2 stream ID 或可复用数组下标。后端持有有界映射，
  同时验证实例/连接代次/流代次；旧完成只能释放旧持有，不能触达新 Attempt。
- method/service ID 与传输 stream ID 独立。HTTP/2 的编号规则不应缩小业务
  u32 身份空间；TRP 的双 lane/多连接也不让 Call 偷跨代次复用能力。
- CTM1 选择描述属于本 Attempt 的前置合同。重试不能靠选旧描述丢掉新字段；
  可表达性、原语义、幂等/提交点及预算仍由 #244/#245 检查。

## 3. 必需操作及接受边界

下表规定行为，不冻结某组 C 函数名或公开结构布局。

| 操作 | 成功/失败与所有权 |
|---|---|
| 创建后端/连接 | 验证有限 profile、算法/版本/身份要求，冻结策略；失败不发布半构造能力，保留可重试销毁的例外须明确 |
| 打开 Attempt 流 | 先取得流槽/操作/输出额度；同步拒绝不欠完成，成功受理后必须有一次终局与资源退休出口 |
| 提交字节切片 | 整次提交只返回全部受理或不受理；成功移交拥有型持有，失败保留原切片及协议状态；不代表写出或远端执行 |
| 半关闭发送 | 排在此前已受理字节之后；不终止接收、不构造 RPC OK；重复或终局后的提交明确拒绝 |
| 接收有序片段 | 回调借用至返回；跨异步保留必须有已计费的存储引用或复制，流字节切点不作为业务消息边界 |
| 接管接收存储/回补信用 | 有界下游已经承接字节后才确认接管；内存额度仍到真正释放才归还，不能把两种信用合并 |
| 可写/容量就绪通知 | 指向具体流和资源原因，恢复时有进度出口；不能永久返回 AGAIN 却没有可能唤醒它的事件 |
| RESET/取消 | 停止此流后续提交，保持已选 Call 结果；通知取消不证明 worker 已停止、远端未执行或对象已回收 |
| 排空/GOAWAY | 停止新准入，保留带连接代次的处理边界；已准入流按既有结果/期限收敛，不隐式重放 |
| 退休/销毁 | 终局已选、最后回调已返回、操作/缓冲已释放分别可观察；未收敛时保留所有权并返回可重试状态 |

字节接口允许将大 Record 分段提交，但不能产生第二条无界队列。每次只承接有限
切片；待发源、输出暂存、TLS 稳定重试缓冲和完成记录都进入额度。当前 TRP 整消息
发送限制不是这种分段能力已经实现的证明；不可表达的消息/窗口组合须明确拒绝。

能力快照必须声明流发起角色、并发/大小上限、半关闭/复位及拓扑支持。必需能力
缺失在创建或调用前拒绝；HTTP/2 请求方向不能无条件表达双方随时新建任意流，
不能偷偷将它转换为 push。需要反向调用时，须明确使用另一连接/角色或拒绝。

所有协议变更仍在单 owner 提交；应用回调不在 owner 阻塞等待。同一 Call 的
数据/终局顺序、回调返回屏障和取消后迟到结果沿 #243，不由后端另造一套规则。

## 4. 配额与错误

每个后端 profile 都须给出有限的连接/活动流/待开流数、输入/输出队列条数与
容量、控制预留、单次解析字节/事件工作量、编码重组、解压工作区及外借存储。
已接收压缩字节、解码输出和应用保留独立计费；连接/分片/宿主及跨宿主持有的
归属必须可核对。零值语义逐项固定，不能通用解释为无限。

请求回补网络信用前，下一层须真实预约存储，不能先交付再赌分配成功。后端既
不能因一个业务持有者停止处理整条连接的控制输入，也不能在内存耗尽后把输入
倒入无界缓存。配额满是资源拒绝，不是坏格式；永久过大不能伪装为临时 AGAIN。
后端实际扣费与上层业务字节分开记录；协议字节、丢弃和流关闭后的信用收敛也须
按后端规则处理，不能直接以业务 payload 长度代替网络消费账本。

错误携带 cause、scope 和阶段：本地参数/版本/能力错误、流级协议错误、连接级
解析状态失配、配额/分配错误与传输失联分开。上层已选择的成功/取消/期限不能
被迟到后端结果改写。流协议错误不一律扩大到连接，但后端共享解析状态已损坏
时也不能只取消一个 Call 后假装连接健康。沿 #242 核对原始错误作用域。

GOAWAY 的处理边界只作为某 Attempt 的 not_processed/may_have_processed/unknown
证据。是否再试仍须满足业务幂等、提交点、原期限和总预算；不因收到某个错误
数字就自动复制请求。单流半关闭、连接 EOF 和 RPC FINAL 也不是同一个事件。

## 5. HTTP/2 候选的最小等价映射

以下为候选设计，未连接到生产 RPC。HTTP/2 的流/连接双级 DATA 信用、流级 RESET
及带处理边界的 GOAWAY 可作为映射基础；头部相关状态另有资源/错误要求，不能
只通告头部大小设置就认为存在硬内存上限。
[RFC 9113 §5–6、§10.5](https://www.rfc-editor.org/rfc/rfc9113.html)

| 项目 | 候选映射与必须检查的差异 |
|---|---|
| Attempt 与 OPEN | 每 Attempt 一条请求流，固定最小 HTTP 路由头；业务 service/method/元数据仍在 RPC Record 中 |
| 双向数据与半关闭 | DATA 承载同一 Record 字节序列，保持上下行独立；传输 END_STREAM 不产生 RPC 成功 |
| INITIAL/FINAL/类型协商 | 保留上层记录及其顺序；HTTP 响应头不冒充业务 INITIAL，SELECT 不占用业务响应头 |
| 二进制元数据 | 原 512 字节 RPC 元数据留在 Record；若改映射为 HTTP 字段，须重新定义编码/大小/重复项规则，不能静默改变 |
| 网络信用 | 显式控制流和连接消费通知；慢流保留自己的存储，不无限占满共享解析/任务资源 |
| 错误和排空 | 区分后端流/连接错误，记录处理边界与代次；RESET/GOAWAY 不替代 RPC status/Attempt 策略 |
| TLS 与连接组 | 正式 HTTPS 候选须定义 h2 ALPN、同等身份/关闭合同；多 socket 拓扑分别对照，不假定 HTTP/2 只能单连接 |

这里比较“相同自定义 RPC 语义的载体”，不是宣称与 gRPC 互通。原生 gRPC 另有
请求/响应头、逐消息长度前缀与尾部状态；若加入它的完整栈比较，应单列功能和
转换成本，不能将少实现的方法、认证或重试当作速度优势。
[gRPC HTTP/2 协议](https://github.com/grpc/grpc/blob/master/doc/PROTOCOL-HTTP2.md)

成熟 C 库 nghttp2 不负责 socket I/O，可以由现有 owner 驱动；单 session 不能
同时被多线程操作，回调也不能递归驱动 send/recv。这提供可集成路径，不代表
现有 ByteEndpoint、ALPN 和 RPC 绑定已经具备它。
[库架构与回调约束](https://nghttp2.org/documentation/programmers-guide.html)

其序列化输出有借用期限。实验适配器必须在下一次会使输出失效的发送调用之前，
将字节写完或复制到有界自有存储；TLS WANT 重试参数必须稳定。不能让 serializer
覆盖仍在等待 SSL_write 的内存，也不能仅凭 want_write=false 销毁外部待发数据。
[输出寿命](https://nghttp2.org/documentation/nghttp2_session_mem_send2.html)

可禁用自动窗口更新，通过 consume 明确归还接收信用；存储接管与真正释放仍由
本项目分账。[手动更新选项](https://nghttp2.org/documentation/nghttp2_option_set_no_auto_window_update.html)、
[消费接口](https://nghttp2.org/documentation/nghttp2_session_consume.html)
自定义 allocator 入口可用于预留/回滚实验，但只证明接缝存在；仍须覆盖 session、
回调、HPACK、输出、外部 TLS 与迟到存储的所有者。
[allocator 接口](https://nghttp2.org/documentation/nghttp2_session_client_new3.html)

## 6. 公平的比较实验

先固定语义与资源，再测性能。两种候选必须运行同一组事件/故障 oracle，记录
submit rejected、accepted、terminal selected、callback returned、storage retired；
只比 HTTP GET 与完整 RPC、只比帧头大小、只比 parser CPU 都不能完成 #246。

| 组别 | 相同条件与通过依据 |
|---|---|
| 语义 | 四种 ONE/MANY、零条/零字节、初始/尾部元数据、类型不匹配、重复终局、半关闭、流复位、排空边界 |
| 活性 | L<W / L=W / L>W、最小池、单 worker、持有慢消费者、双向同时发送、控制与数据恢复 |
| 资源 | 先预约后分配；每步编码/解码/工作区/排队/在途/外借账本；分配失败、取消和迟到完成最终守恒 |
| 拓扑 | 同连接多流、等量多连接、TRP 双 lane/多 DATA；分别测隔离收益和额外 socket/TLS/RSS 成本 |
| 安全 | 同 TLS 版本/密码套件、服务端认证或 mTLS、身份与凭证代次、压缩/未知长度/坏格式上限 |
| 性能 | 相同消息/并发/到达模型/业务工作/总额度/CPU；吞吐、成功率、尾延迟、复制/分配、syscall、CPU/RSS 与故障恢复 |

压缩 NONE 与 Zstd 分组；未知长度/伪造原长、已接受后的取消、坏编码与配额不足
都保留。初步比较关闭重试时两边都关闭；启用 Attempt 策略后再在同预算/幂等
条件下比较，不把透明重试产生的额外工作漏掉。

固定二进制、源码、依赖和机器，预先给出到达率/时长/预热/重复/采样与质量规则。
每次保留失败率、调度迟到/丢弃和负结果，不丢弃坏样本，不增大对方限额来掩盖
活性缺陷。开发机诊断与固定基准机验收分开；没有共同语义的项目写未验证，而
不是改小候选功能集来取得漂亮数字。

## 7. 当前证据与缺口

本次已阅读官方规范/库说明及当前 Channel、Record 绑定源码；本机 pkg-config
报告 libnghttp2 1.70.0，安装头含上列候选 API。在线说明为 1.71.0-DEV，因此
是否可调用以本地固定版本头/链接/运行核对为准，不能用网页版本代替实测。
存在头文件或 allocator API 不等于编译、网络互通或资源验证通过。
版本、头文件摘要及九个 API 声明的只读核对见[清单](../../reviews/data/transport_backend_inventory_20261029.json)；
其中编译、链接、RPC 适配和网络比较均显式标为未运行/未实现。

- 当前 TRP 的 CI、SDK、流控/压缩/TLS 回归和负性能结果可作为既有一侧证据；
  新后端还没有同 oracle 的对应结果。旧基准不是完整重设计 TRP 的验收。
- RPC 仍直接绑定 tr_stream_handle；通用后端适配、HTTP/2 ALPN/头部及共享状态
  预算、协议事件回放、真实 TCP 和等价性能矩阵都未实现/未运行。
- 当前 producer 的跨宿主持有计费、#244 Attempt 和 #245 类型合同尚未全部收口，
  不能用一份后端契约替它们宣布完成。
- 本文不是生产实现计划或依赖引入批准，不冻结未测过的接口布局/默认限额。
  后端选择 ADR 只有在正确性、维护成本和等价测量齐备后才能正式接受；用户的
  自定义方向不自动证明当前实现已经优于其他方案。#246 保持开放。
