# V2 服务端共享内存预算设计

日期：2026-10-23；基线 `b64a6e76649eea907ddab69da847f4d97442b186`，
版本 `2.0.0-dev.6`；对应 #241 的连接/分片/全局预算部分。

## 现状与目标

普通 V2 Server 已有 `memory_budget_bytes` 总额，但构造时把它等分为
每个 shard 的独立硬限额。各分片使用者均计入自己的预算，因而总使用量
不会超过总额；然而一个繁忙 shard 可以在其他 shard 尚有空余时被其份额
过早拒绝。总额也没有可直接核对的原子账本。

本次建立一个 Server 拥有的共享总预算，同时保留 shard 本地统计。
任意 shard 的新增申请都先竞争总预算，再计入本地账本；所有 shard 的
本地当前字节之和等于总预算当前字节，不计入独立于此 Server 的应用存储。
在总额仍有空余时，不应仅因旧等分份额拒绝某个 shard。

## 设计

`tr_memory_budget` 新增可选父预算指针。无父预算时维持原行为。
有父预算时先原子预留父预算，随后预留本地预算；本地失败须归还父预算。
释放先归还本地再归还父预算，两个计数器在操作中始终满足父当前值
大于或等于所有子当前值之和。父指针在子预算存活期间不变，父预算
寿命必须长于全部子预算及持有的 Message 视图。共享父预算只允许
根预算，不允许形成多层链或环。

普通 V2 Server 将父预算嵌在 Server 对象内，限额是现有推导总额；
每个 RuntimeShard 的本地限额设为同一总额，并指向父预算。
这样保留本地账本，但局部限额不会先于真实全局限额耗尽。
直接 Runtime、Client、Transport-only Server 不设置父预算。
Server 完成 Runtime 销毁后，总预算应归零；未收敛的应用 Message
视图仍通过现有 Runtime 销毁重试屏障保留子预算和 Server 外壳。

已转移到独立 producer 持有域的应用存储在关闭后不属于这个
Server 的预算，跨域账本仍待 #241 后续处理。
本次不新增公开配置、租户身份或跨 Server 进程预算；未来租户
限制可在明确租户身份与生命周期后接入独立父域。

## 验收

1. 两个子预算共享有限父预算：任一子可使用超过旧等分份额的空余，
   总额耗尽后另一个子明确 `TR_AGAIN`；释放后可继续，最终双层归零。
2. 子本地限额拒绝时，已取得的父额度全部回滚；零字节、溢出和
   错误释放不改变不相关预算。
3. 两个 RuntimeShard 的固定存储和后续申请进入同一个父账本；
   Runtime 销毁后父账本归零，失败回滚不留下额度。
4. 普通 V2 Server 的分片预算使用同一父对象和总限额；
   Client 与 Transport-only 行为保持原合同。
5. GCC 全量、受影响 ASan/UBSan、CI 精确静态分析和实际主线验证通过。

性能成本：有父预算的申请和释放各增加一次原子记账；不新增分配、
线程、锁或消息复制。40k 容量与尾延迟必须实测后才能声称达标。
