# 自定义业务消息格式与 C/Rust 编解码生成设计

日期：2026-10-29。状态：具体设计待审阅，尚未实施。
依据：用户已选择“传输和业务消息格式都自定义”；关联 #245、#241、#242、#247。
主会话内联执行，不使用子 agent。

## 交付边界与方案

业务消息不引入 Protobuf。现有自定义 TRP/RPC Record 继续承载消息，RAW 编解码
保留。schema 的 JSON 是构建期输入，网络正文采用下述自定义二进制格式，不发送 JSON。

本子项目交付单源 schema 校验、确定性描述与指纹、C11/Rust 编解码生成、跨语言
黄金向量和错误向量。它是后续 RPC 类型桩的基础，不自行宣称 #245 已完成。
RPC OPEN 方法指纹检查、四种基数的类型化调用/服务派发、Rust 安全 Call 包装和
重放策略接入分别在后续子项目设计；本子项目不把正文校验冒充 OPEN 前的方法准入。

比较三个方案：

| 方案 | 收益 | 代价与结论 |
|---|---|---|
| 受限 schema + 自定义二进制 + 生成代码 | 单源定义、有界解码、C/Rust 同一 wire | 维护编译器与格式；按用户选择采用 |
| 仅导出通用方法描述，正文仍手写 | 对现有 RAW 接入较少 | 不能充分防止正文与方法漂移，不作为完整类型方案 |
| Protobuf 描述与语言后端 | 可以利用既有 schema 生态 | 用户本次明确选择全自定义，不作为默认依赖 |

第一版采用按字段 ID 排序的位置编码，而非逐字段 TLV。完整类型指纹必须匹配，
避免在尚无演进规则时静默接受另一种布局。代价是相关字段、名称或限制变化需要
双端共同更新，不能宣称支持自动滚动兼容；不提供未知字段跳过或推测迁移。

## schema 与确定性

文件后缀 `.ctm.json`，顶层固定包含 `format: "ctm-schema-1"`、`package`、
`types` 和 `services`。JSON 对象重复键、未知键、浮点数字、非法 UTF-8、过大输入
和超过 64 层的 JSON 直接拒绝，不按“最后一个键覆盖”解释。输入文件最多 1 MiB。

- package 为点分 ASCII 标识符；类型、服务、方法、字段名称均使用 ASCII 标识符。
  拒绝 C11/Rust 关键字及生成名称冲突，不通过隐式改名隐藏冲突。
- 类型、服务、方法、字段和枚举项均显式给出非零 u32 ID；禁止按注册或文件顺序编号。
  ID 在所属命名域内唯一，名称同样唯一。对象列表规范化时按 ID 排序。
- 每文件最多 256 个类型、64 个服务；每类型最多 64 个字段，每服务最多 256 个方法。
  类型图必须无环；引用必须存在；最大结构/可选/数组嵌套深度为 16。
- 字段类型支持 bool、u8/u16/u32/u64、i8/i16/i32/i64、f32/f64、有界 bytes/string、
  命名 struct/enum、有界 array 和 optional。所有变长字段必须显式给出上限。
  不支持递归类型、map、联合体、任意对象、隐式无界容器和用户解码回调。
- bytes/string 的上限按编码后的字节计，array 的上限按元素数计。数组上限最大 65535。
  编译期用检查算术计算最坏编码大小，含帧头不得超过 1 MiB；溢出或超限拒绝。
  enum 以显式非零 u32 项编号编码，拒绝未声明的值。
- 方法定义包含 service/method ID 与名称、请求/响应类型、ONE/MANY 基数、消息上限、
  可选压缩能力和重放声明。缺省重放声明为 `never`，不从名称或错误状态推断幂等性。
  本阶段只生成这些数据，不启用重试。

最小完整输入示例：

```json
{
  "format": "ctm-schema-1",
  "package": "backup.v1",
  "types": [
    {"id": 1, "name": "Chunk", "kind": "struct", "fields": [
      {"id": 1, "name": "offset", "type": "u64"},
      {"id": 2, "name": "data", "type": {"kind": "bytes", "max_bytes": 65536}}
    ]}
  ],
  "services": [
    {"id": 1, "name": "Backup", "methods": [
      {"id": 1, "name": "Put", "request": {"type_id": 1, "cardinality": "ONE"},
       "response": {"type_id": 1, "cardinality": "ONE"}, "lane": "BULK",
       "compression": {"request": ["none", "zstd"], "response": ["none", "zstd"]},
       "replay": "never"}
    ]}
  ]
}
```

`kind=enum` 的类型用 `values: [{"id": 1, "name": "Value"}]` 代替 fields。
字段 type 的标量形式为上述标量名；对象形式只允许 bytes/string 的 max_bytes、
`{"kind":"ref","type_id":1}`、
`{"kind":"array","max_count":8,"element":"u32"}` 和
`{"kind":"optional","value":"u64"}`。各形式只允许其列出的键。
类型/字段/服务/方法可有 `doc` 字符串，排除于规范化契约；其他未知键拒绝。
方法 lane 必填 CONTROL/BULK，compression 必填两方向集合且必须包含 none，
只允许 none/zstd；replay 可省略且规范化为 never，其他值本阶段只接受 explicit，
其含义是业务显式声明可以重放，而非本阶段启用自动重试。
消息上限从类型的最坏编码大小（含 40 字节帧头）推导，不另设易漂移的手填值。
示例 Chunk 的上限为 65588 字节，底层方法/传输配置仍须允许该大小。

规范化描述由校验后的语义对象建立，不直接散列原文件。固定采用 ASCII JSON，
键排序、无额外空白、数组按 ID 排序，输出末尾换行不参与散列。文档说明不参与指纹。
类型指纹为 SHA-256，输入包含 `ctm-type-1` 域、package、目标类型以及按 ID 排序的
可达类型定义；无关类型的新增不会改变该类型指纹。方法指纹以 `ctm-method-1` 域
包含方法契约和请求/响应类型指纹。类型限制属于指纹，运行时 deadline 不属于指纹。
指纹用于发现定义不匹配，不是认证或授权凭据。

## 二进制 CTM1

所有整数逐字段按小端编码，禁止复制 C/Rust 结构内存或对未对齐输入做类型转换。
独立消息的固定帧头为 40 字节：`CTM1` 四字节、u32 正文字节数、32 字节类型指纹。
完整输入长度必须恰好为 40 加正文长度；截断、尾随数据或指纹不匹配均拒绝。

正文按字段 ID 顺序排列，不携带字段名、字段 ID、内存地址、填充或本机大小：

| 类型 | wire 规则 |
|---|---|
| bool | 一字节，只允许 0/1 |
| 无符号/有符号整数 | 固定宽度；有符号数为补码位模式，转换避免有符号溢出 |
| f32/f64 | IEEE 754 位模式，以 u32/u64 小端传输；保留 NaN 位，不声称数值规范化 |
| bytes/string | u32 字节数后接内容；string 必须为严格 UTF-8，拒绝非法/过长编码和代理码点 |
| enum | u32 已声明项编号 |
| struct | 对应类型的有序字段正文，不加嵌套帧头 |
| array | u32 元素数，后接连续元素；先检查数量上限，再逐项检查 |
| optional | 一字节 0/1；0 无后续值，1 后接一个完整值 |

空类型、零长度 bytes/string、空数组和 optional 缺省值有明确编码；不把零长度
消息等同于 MANY 的零条消息。长度从剩余容量中扣减，不先相加再检查溢出。
非法值不能截断、替换为默认值或按另一种类型重试。

第一版 codec ID 使用新命名常量 `TR_RPC_CODEC_CTM1=2`，不改变 `TR_RPC_CODEC_RAW=1`。
在 RPC 正文接入完成前，生成产物不默认改变现有方法 codec 或线上流量。

## 编解码所有权与执行域

生成 C 输入结构只借用调用方数据直到 encode 返回；输出缓冲由调用方提供。
预检完整输入值、上限与所需大小后再编码，成功才写入 `written`。
源对象、其借用切片及输出区域禁止重叠，重叠在写入前拒绝。没有隐式堆分配。

decode 先验证完整帧与全部字段，再发布借用视图；失败不修改输出视图。
视图只含输入切片及固定解析信息，不为数组分配元素对象。数组由有界迭代器
逐项读取，嵌套对象仍借用原输入。所有游标操作检查边界；即使从已验证视图访问，
也不以裸指针转换或 unchecked 下标省略安全检查。

C 注释明确要求原输入不可变且存活到最后一个视图/迭代器使用结束。Rust 用
`View<'a>`、借用切片和迭代器表达相同约束，不用 unsafe 把 C 指针包装成安全拥有者；
不使用 Vec/String 隐式扩张输出。可选值使用 Option，固定宽度浮点用 to_bits/from_bits。
解码内存只包含调用方视图、游标和最大 16 层受限调用栈，不与元素数成比例分配。
Rust 的对应错误与 C 状态固定映射：magic 为 BAD_MAGIC，版本标识为 BAD_VERSION，
指纹/枚举为 BAD_TYPE，截断/尾随/容量/数量为 BAD_LENGTH，非法参数/重叠/bool/
UTF-8 为 INVALID；保留现有数值标记。CTM1 版本标识不匹配且有 CTM 前缀时归
BAD_VERSION，其他 magic 错误归 BAD_MAGIC。完整输入解码不返回 TR_AGAIN。

生成 RPC adapter 时仍须遵守 Message/work 回调的原借用寿命；持有 CallRef 不代表
持有正文。需要异步保存正文的业务必须使用明确的持有/有界复制机制，不能让借用
视图跨回调逃逸。本阶段不新增 Reactor 工作、线程、队列或在 owner 上解码业务对象。

## 产物、构建与发布

构建期工具仅依赖 Python 标准库，输出同名 `.ctm.h`、`.ctm.c`、`.ctm.rs` 和
`.manifest.json`。C11 代码使用既有状态返回约定；Rust 生成独立可编译模块，错误为
明确枚举。生成注释为简体中文，标识符、JSON 键和 wire 字节保持机器兼容形式。
工具的人读诊断接入现有 `tool_i18n`，不固定为中文。

普通构建不联网下载工具或 schema。Xmake 是构建/测试入口；Rust 生成物验证通过
显式 Xmake 目标调用已配置 rustc，缺失工具明确报错，不把跳过称作通过。已有 CI
检查名、测试目标参数及超时保持不变。临时产物、编译输出、缓存与日志只在 build/。

生成前完成全量校验；`--check` 比较全部预期产物与字节内容，拒绝缺失、额外或漂移。
输入路径/注册顺序/当前工作目录/时间戳不进入生成结果。许可、生成器版本及 schema
指纹进入 manifest；生成器版本不是类型指纹的替代。安装边界与原 11 头 SDK 的变化
必须单独验证和记录，不把新增文件自动安装到公共 SDK。
全部生成产物的总字节数最多 64 MiB，超限在发布任何产物前拒绝。

## 验收与失败作用域

1. 正向黄金向量覆盖所有标量边界、浮点位模式、中文/非 BMP UTF-8、空值、最大值、
   嵌套数组/结构/可选值；C 编码→Rust 解码及反向字节完全一致。
2. 同 ID 不同描述、字段/类型 ID 重复、引用缺失/环、注册顺序变化、关键字/生成名称
   冲突、未知 schema 键和重复 JSON 键分别覆盖；顺序变化不能改变产物。
3. 错误向量覆盖每个截断点、尾随字节、错误指纹、长度/数量越界、溢出、非法 bool/
   enum/UTF-8、过深 schema、无界字段、输出容量不足和编码源目标重叠。
4. 失败输出不变；生成码无隐藏分配；C11/C++11 头边界、Rust 生命周期编译正反例、
   GCC/Clang、ASan/UBSan、既有工具国际化与生成漂移门禁均须实际运行。
5. codec 本身只返回错误，不操作连接、RESET 或 RPC 终局。后续 RPC 接入必须将坏
   正文与方法不匹配隔离到目标 Call，验证同连接健康调用仍可完成，并保留 #242 的
   本地内部损坏作用域，不由本阶段提前宣称通过。

发布 #245 仍要求后续类型化 Client/Server 桩、OPEN 前方法描述匹配、取消后迟到结果、
Rust 原生 Call 所有权与预算接入验收；本设计不删除或降低这些要求。
